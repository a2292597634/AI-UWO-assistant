# CloudBase CDN 素材交付实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已由依赖索引确定的航海士头像和技能图标发布到 CloudBase 公开 CDN，通过确定性清单生成版本化 HTTPS URL，并让目录、详情、船队页直接消费 URL，同时保留文字与图片 fallback。

**Architecture:** 构建阶段以素材依赖索引和 PNG 文件生成不可覆盖的 release manifest，使用注入式 CloudBase CLI 适配层完成上传、权限和公开 URL 验证；没有环境 ID、CLI 或凭据时只允许生成计划和执行本地校验。数据生成器从受校验的 manifest 读取 URL，运行时不包含 CloudBase SDK、网络请求或 Node.js API；三页移除业务素材分包 loader，使用图片级状态、有限重试和本地 UI fallback。

**Tech Stack:** TypeScript、Vitest、Node.js 构建工具、CloudBase 官方 CLI、微信小程序原生 `<image>`。

## Global Constraints

- `archive/` 只读；`data/master/` 是规范数据源；`miniprogram/generated/` 只能由 `npm run data:generate` 生成。
- CloudBase 云存储采用公开读、管理员写；不使用云数据库、云函数、临时 URL、WebP、自定义 CDN 或运行时远程数据接口。
- 不新增小程序运行时依赖，不把环境 ID、SecretId、SecretKey 或 CLI 凭据写入仓库；不猜测 CloudBase 环境 ID。
- 运行时代码禁止 `wx.request`、`wx.cloud`、`wx.downloadFile`、Node.js API 和非 allowlist 远程 URL。
- 只允许生成数据中的图片字段使用配置的单一 HTTPS CDN origin；手写运行时代码中的远程 URL 继续失败。
- 发布路径必须包含 release ID；禁止覆盖已发布对象，普通验证和 `npm run verify` 不上传、不删除云端对象。
- 数据解析、素材清单、哈希、URL、索引和确定性构建逻辑必须先写失败测试，再实现。
- 页面和用户可见文字使用繁体中文；不顺手修复无关问题或格式化无关文件。

**Interfaces:**
- `parseCloudBaseConfig(env): CloudBasePublishConfig` 校验环境 ID、单一 HTTPS origin、内容版本和 bucket/path 配置；不接受查询参数、尾部路径、非 HTTPS 或自定义 CDN。
- `buildReleaseManifest(input): PublishedAssetManifest` 从依赖索引和已压缩 PNG 读取 `sha256`、`bytes`、`image/png`、`cloudPath`、`releaseId` 和稳定排序。
- `validatePublishedManifest(manifest, config): void` 校验缺失、重复、哈希/大小/MIME、release/path/origin、`fileID` 和 `publicUrl`。
- `CloudBaseCli` 通过注入的 `run(args)` 执行上传、对象详情、ACL 和 HEAD/GET 验证；上传命令不带 overwrite/upsert，CLI 缺失或 config 缺失时给出可操作错误。

- [ ] 运行 `npm.cmd test -- tests/asset-pipeline/cloudbase-manifest.test.ts tests/asset-pipeline/cloudbase-cli.test.ts`，确认因模块不存在或接口缺失而失败。
- [ ] 实现纯函数清单与配置校验；清单只包含依赖索引中的业务 PNG，不重新扫描模板。
- [ ] 实现 CloudBase 官方 CLI 命令适配；只使用 `tcb storage upload`/等价旧命令、对象详情和权限检查，绝不使用临时 URL 作为 `publicUrl`。
