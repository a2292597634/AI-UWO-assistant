# Plan: 新增佛雷德烈航海士资料

## 目标

依据用户提供的截图，新增一笔「佛雷德烈」航海士资料；同时把截图型航海士录入时的技能位置解锁规则、新技能图文直录规则和头像透明抠图规则固化到线下录入规范。

## 已确认资料

- 稀有度：S；航海类型：交易；职业：食品商；性别：男性；国籍：中立國。
- 语言：英語 Lv.5、俄語 Lv.3。
- 主动技能：行動封鎖、衝破威力強化、必死攻擊，均为技能等级 Lv.1；按既有主动槽位使用解锁等级 1、50、1。
- 普通被动技能按截图从左到右、从上到下放入 `sk0.slot 0–7`，解锁等级为 `10、10、50、50、30、30、70、70`。
- 固有被动「有趣的酒鬼」固定为 `sk1.slot 0`、技能等级1、解锁等级1；说明文字直接采用截图文字。
- 当前最大 `displayOrder` 为630，新航海士拟使用631。

## 执行步骤

1. 先在 `tests/data-pipeline/full-data-integrity.test.ts` 增加佛雷德烈的失败回归测试，覆盖基本字段、语言、技能顺序、技能类型、槽位、技能等级和解锁等级。
2. 在 `data/master/skills.json` 新增「有趣的酒鬼」技能主资料，使用用户截图提供的名称、说明和技能图示；不复用相似技能。
3. 在 `data/master/officers.json` 新增佛雷德烈，复用已核验的技能与字典 ID，内部 ID、来源引用和排序号按仓库规则生成。
4. 从用户截图生成两项素材：人物头像抠图为带真实 alpha 的透明 PNG；「有趣的酒鬼」直接裁切截图中的技能图示。写入 `data/assets/staging/` 后检查尺寸、格式和依赖。
5. 运行 `npm run data:check`，然后生成运行时数据并运行相关数据管线测试。
6. 资源若需要进入当前 CloudBase 发布清单，先保留现有未提交的 `data/assets/cloudbase-manifest.json` 修改，不覆盖它；在发布或更新 manifest 前单独向用户确认。
7. 最后运行 `npm run verify`；提交前展示变更文件、验证结果和拟用 commit message，等待用户确认，不自动提交。

## 约束与验收

- 不修改 `archive/`，不手动修改 `miniprogram/generated/`。
- 不改变既有航海士或既有技能的语义和素材。
- 头像必须不含原截图背景，透明区域不能遮挡稀有度背景色。
- 新技能名称、说明和图示必须来自用户截图；若资源发布未获确认，不宣称 CloudBase 已完成。
