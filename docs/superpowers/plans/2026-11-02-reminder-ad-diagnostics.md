# 激勵廣告精確診斷實作計畫

目標：依使用者已確認的診斷方向，保留微信廣告錯誤碼，讓正式版失敗能以截圖或複製文字回報。

設計：runtime 將建立、預載、展示、重載及再次展示的錯誤轉成白名單診斷；controller 保留一般失敗清理，透過通知回呼交給頁面顯示原生可複製彈窗。預載失敗只寫安全日誌，不主動彈窗；不改廣告完成判定、服務端開通、重試上限或網路邊界。

範圍：只修改提醒廣告鏈路。當前此分支只有提醒 runtime 使用 createRewardedVideoAd；使用者另述的首頁激勵廣告可能來自其他版本，不能以此分支推定其實作。

診斷欄位：固定診斷版本、廣告位、數字錯誤碼、失敗階段／來源、envVersion、版本、微信版本、基礎庫和系統類別。禁止原始 errMsg、AppID、OpenID、授權內容、票據及完整系統物件進入日誌或剪貼簿。未知值明示未知。

## 本輪證據與限制

四個提醒相關測試檔共77項通過。審查指出的同輪事件／Promise碼丟失、重載收到錯誤後再次展示及殘留計時問題，均先以紅燈復現，再修復；複查未發現剩餘P1／P2。

完整 verify 執行記錄保存在 `artifacts/miniprogram-review/reminder-ad-diagnostic-final/verify.log`。頁面 iterate 的視窗通道曾回報 rawPath 元資料錯誤；SDK通道兩次自動恢復後仍回報找不到項目GUI窗口，已保留 blocked HTML 報告，未再突破恢復上限。未取得本輪頁面截圖，不把本機模擬的1007視為微信正式版的真實回覆；final頁面驗收及真機正式版仍待完成。
