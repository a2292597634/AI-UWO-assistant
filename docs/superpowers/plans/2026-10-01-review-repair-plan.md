## 全局約束

- 分支命名 `codex/phase-N-描述`；不得在 `master` 開發。執行前建立或重用合適隔離工作樹，納入需要保留的目前內容。
- `archive/` 唯讀；人工資料只改 `data/master/`；所有 generated／分片／reference／清單由工具生成，禁止手改。
- master 異動後執行 `npm run data:check`；最終執行 `npm run verify` 和 `git diff --check`。
- 新增／刪除／升級依賴須另經使用者確認。本計畫使用現有依賴。
- 資料解析、轉換、校驗、篩選、生成與確定性邏輯遵循紅→綠→重構；每次紅燈必須指向預期缺陷，不能是無關 fixture／環境錯誤。
- 涉及 UI／WXML／WXSS／頁面共享 runtime 時，完整閱讀 Design Foundation 及 `2026-09-16-miniprogram-review-html-report-design.md`；技能任務另讀 `2026-09-13-skill-level-and-badge-convention-design.md`。
- 使用者介面／資料為繁體中文；註釋和文檔為中文，樣式類名英文 BEM。
- 本地測試使用記憶體 CloudBase／官方 HTTP mock；UI 雲功能使用明確的本地 fixture。實施和驗收均不提交真兌換、不修改真雲資料、不部署。
- 生成／同步／匯入整體驗證在隔離副本完成；驗證失敗不能留下半套 master／生成檔。原工作區不因檢查被格式化。
- 每個可交付批次展示變更清單、檢查／UI 結果及擬用中文 commit message，再等待使用者確認；計畫中的提交步驟不授權自動 commit。

## 批次驗收／交付步驟

- [ ] 開始時確認變更範圍、讀相關規格、建立測試 fixture；UI 任務先執行 `npm.cmd run devtools:doctor`。
- [ ] 逐任務執行明確的紅燈案例，完成最小修復，再跑該模組相關測試。外部審查 mock 轉成正式回歸，不能只重跑一次外部腳本。
- [ ] UI 每一完整修改批次執行 `npm.cmd run devtools:changed -- --mode iterate`，保留可信基線及修改後截圖；final 用同一規範完成報告。
- [ ] 生成及驗證在隔離副本：`npm.cmd run verify`、`git diff --check`。需要檢查 dirty generated 時先保存副本的內容快照作比較基線，不能把使用者已有差異當作非確定性。
- [ ] 對 P1、配置跨 await、伺服器狀態機及資料回復做第二位審查者複核；確認先前已有防護仍有效。
- [ ] 展示具體文件與結果，提出單一批次 commit message，等待使用者確認。部署不屬於這份實施計畫的自動步驟。

## 計畫選擇與預估規模

推薦「先單独交付 A1，再逐模組批次」：容易複核、回復，且最快消除唯一 P1。全部 26 項做成一個大型變更會使配置、主資料和生成差異難以定位；只修 P1 則仍保留多個資料損失／門禁缺口。因此總範圍保持 26 項，交付拆成上述批次。

共 **19 個**可獨立審核任務：A 4、B 4、C 3、D 1、E 5、F 2。執行時按任務及完成門禁追蹤，不以批次数當任務數；耗時受 DevTools／設備及資料證據影響，不承諾未驗證的工期。
