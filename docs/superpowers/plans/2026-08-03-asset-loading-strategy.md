# Asset Loading Strategy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 清理未引用 PNG，按目錄順序建立約 7 個素材分組與依賴映射，並讓目錄、詳情、船隊頁以同一套 root 素材載入器按需取得圖片。

**Architecture:** 新增純函式素材依賴索引生成器，將圖片路徑、技能圖示、航海士列表/詳情/船隊依賴和素材 root 描述一起輸出到自動生成檔；素材整理腳本只複製首次引用的圖片到目錄順序分組。運行時由共享依賴 store 解析頁面所需 roots，`asset-package-loader` 以單一串行導航佇列處理去重、共用 Promise、錯誤保留和重試，頁面先渲染文字再掛載已就緒圖片。

**Tech Stack:** TypeScript、Vitest、Node.js data pipeline、微信小程序原生 `wx.navigateTo`/`wx.navigateBack`。

## Global Constraints

- `archive/` 只讀；手動數據只改 `data/master/`；`miniprogram/generated/` 只能由 `npm run data:generate` 產生。
- 不使用 `wx.request`、`wx.cloud`、遠程 URL 或 Node.js API；不新增、刪除或升級依賴。
- 資產分組固定按 `data/master/officers.json` 目錄順序、每組 100 名航海士；相同圖片只複製一次，以首次引用分組為歸屬。
- 目錄列只引用頭像、前 3 個主動技能和前 3 個被動技能；詳情/船隊依賴延後解析。
- 所有實作遵循 TDD，先看到失敗測試再寫生產程式；本階段不處理 WebP、主包資料拆分或 CDN。
