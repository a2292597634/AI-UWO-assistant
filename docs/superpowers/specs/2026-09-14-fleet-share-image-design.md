# 配隊分享圖設計規格

## 目標

在戰鬥配隊與冒險配隊頁新增「分享隊伍」能力。用戶可將目前配置生成一張繁體中文長圖，圖片展示艦隊航海士構成、指定技能累計資訊及指向小程序首頁的小程序碼，並可從預覽層分享圖片或保存到相冊。

本功能採微信小程序 Canvas 2D 本地生成，不新增雲端圖片生成服務，不新增依賴，也不改變既有配置保存、求解或資料三層架構。

## 用戶流程

1. 用戶在戰鬥或冒險配隊頁點擊「分享隊伍」。
2. 若配置沒有未保存修改，直接進入圖片生成狀態。
3. 若配置存在未保存修改，顯示三個選項：
   - `直接生成`：以目前畫面狀態生成，不保存配置。
   - `保存後生成`：沿用既有保存流程；保存成功後以服務端回應的配置狀態生成。
   - `取消`：返回配隊頁，不改變配置。
4. 生成期間顯示明確的載入狀態並阻止重複觸發。
5. 生成成功後顯示圖片預覽，提供「分享圖片」「保存到相冊」「關閉」。
6. 圖片內的小程序碼統一指向小程序首頁，不攜帶配置資料，也不提供掃碼匯入隊伍能力。

若保存失敗，停留在配隊頁並沿用既有保存錯誤語義，不繼續生成。若用戶選擇直接生成，分享流程不得改變本地 dirty 狀態或配置版本。

### 分享入口按鈕

- 戰鬥與冒險配隊頁都使用同一個底部固定操作欄，放在內容滾動區之外、頁面安全區上方；操作欄不隨內容滾動，確保七條船或技能清單滾動到任意位置仍能發現入口。
- 操作欄左側顯示「分享當前隊伍」及輔助說明「生成可保存、可分享的長圖」，右側使用唯一主操作按鈕「↗ 分享隊伍」。冒險頁只替換左側上下文，不改變按鈕文案與位置。
- 操作欄與滾動內容之間保留底部內距，內容區同步增加等高的 padding；按鈕不得覆蓋最後一行航海士、技能或分頁控制，也不得製造頁面級橫向滾動。
- 按鈕沿用 `.ui-button` 的觸控規範，實際熱區至少 `88rpx` 高、水平內距至少 `32rpx`、操作文字不小於 `26rpx`；使用墨綠操作欄搭配黃銅強調按鈕，保持與「古典航海資料館」視覺一致。
- 默認狀態顯示「↗ 分享隊伍」；生成中顯示「正在生成…」並設為 disabled；Canvas 或素材錯誤時恢復可點擊並顯示可理解的重試提示。未保存狀態不改變按鈕位置，點擊後進入既定的三選一守衛流程。
- 不在頂部標題區額外重複放置第二個分享入口，避免與配置管理欄競爭；底部固定操作欄是兩個配隊頁唯一的分享入口。

## 架構與邊界

### 分享圖 View Model

新增獨立的分享圖 Presenter，將戰鬥或冒險 `FleetState`、航海士資料、技能資料及配置名稱轉換為純資料 View Model。View Model 只包含排好序且可直接繪製的文字、數值、素材路徑與分區，不包含 Canvas API、頁面實例或保存服務。

共享模型至少包含：

- 圖片標題、配置名稱、類型及資料摘要；
- 航海士名稱、頭像、品質背景、品質徽章與冒險／貿易／戰鬥類型圖標；
- 技能圖標、技能名稱、累計等級及主動／被動分區；
- 小程序首頁碼與本地佔位素材路徑；
- 根據內容計算圖片高度所需的分區行數。

### Canvas Renderer

新增共用 Canvas Renderer，負責：

- 載入並快取本次生成所需的頭像、品質、類型、技能及小程序碼圖片；
- 計算固定寬度、內容驅動高度的分享圖布局；
- 繪製頁首、內容分區、航海士、技能及頁尾；
- 將 Canvas 導出為本地臨時圖片路徑；
- 個別素材失敗時改用本地佔位素材並記錄降級數量。

Renderer 不讀取業務狀態，不計算技能等級，不判斷配置是否已保存。戰鬥與冒險共用頁首、頁尾、航海士和技能條目繪製單元，只在內容布局上使用各自的 View Model。

### 頁面協調

戰鬥與冒險配隊頁只負責：

- 觸發未保存提示；
- 必要時調用既有配置保存流程；
- 建立分享 View Model 並啟動 Renderer；
- 管理生成中、預覽、保存相冊、分享及錯誤狀態。

分享模組不得修改 `archive/`、`data/master/` 或 `miniprogram/generated/`，不得在 Runtime 新增 `wx.request`、`wx.cloud`、遠程 URL 字面量或 Node.js API。

## 共用視覺規則

- 分享圖使用「古典航海資料館」Design Foundation：海圖紙色背景、墨綠頁首／頁尾、黃銅強調與低飽和分隔。
- 輸出採固定邏輯寬度與內容驅動高度，Canvas 實際像素按設備與平台限制選擇安全倍率；不得裁切第七條船或技能尾行。
- 航海士頭像保留配隊頁相同的品質背景、品質徽章及冒險／貿易／戰鬥類型圖標。
- 品質徽章須按素材的實際非透明區域校準視覺尺寸，不得直接以 PNG 畫布尺寸推定可見尺寸。
- 類型圖標是輔助標記，尺寸小於品質徽章且不得遮擋人物臉部。
- 航海士名稱與技能名稱使用足以在微信圖片預覽中辨識的半粗體；長名稱單行省略，不擴張單筆高度。
- 技能累計等級使用獨立高對比膠囊，不疊在技能圖標上。
- 圖片底部放置預先生成並隨包發布的小程序首頁碼；Demo 中的示意碼不得進入正式素材。
- 分享圖所有正式文字使用繁體中文。

## 戰鬥分享圖

### 航海士布局

- 按艦隊中的船隻順序展示，最多七條船。
- 每條船一個分區，固定以一行展示 11 個位置。
- 空位保留明確的空位視覺，以維持位置語義；不得將後方航海士向前壓縮。
- 每位航海士顯示頭像、品質背景、品質徽章、類型圖標與名稱。

### 主動技能

- 只統計該船 11 個位置中已配置航海士的 `kind: active` 技能。
- 同一技能的 canonical 技能等級相加，得到本船綜合等級。
- 顯示本船綜合等級最高的 `TOP 5`，固定一行五項。
- 排序先按綜合等級降序；同等級時按技能名稱升序，再按技能 ID 升序，確保結果穩定。
- 每項顯示技能圖標、技能名稱及本船綜合等級。

### 被動技能

- 只統計該船航海士的 `kind: passive` 技能。
- 只保留技能分類屬於戰鬥相關分類的技能；分類依 canonical 技能分類資料判斷，不根據名稱猜測。
- 同一技能的 canonical 技能等級相加，僅顯示本船累計 `Lv.2` 及以上的技能。
- 按累計等級降序排列；同等級時按技能名稱、技能 ID 升序。
- 每行五項，行數由實際符合條件的技能數量決定，不設人為 TOP N 截斷。

主動與被動區不顯示最左側文字標籤，改以不同但克制的背景框區分：主動使用黃銅淺框，被動使用墨綠淺框。色彩只協助分區，不承擔主動／被動資料判斷。

## 冒險分享圖

### 航海士布局

- 不按船隻分區，合併展示艦隊全部已配置航海士。
- 航海士依品質 `S → A → B → C` 分組，每組顯示品質名稱與人數。
- 組內排序沿用艦隊船隻順序與位置順序，確保穩定且可追溯。
- 空位不進入品質分組，也不計入人數。
- 每位航海士顯示頭像、品質背景、品質徽章、類型圖標與名稱。

### 全艦冒險技能累計

- 計算來源是上方展示的全部航海士，不是預設目標值。
- 展示範圍只包含冒險配隊頁「預設目標」中已選擇的技能；不加入範圍外技能，即使其累計等級更高。
- 對範圍內每個技能，累加所有展示航海士對該技能的 canonical 技能等級。
- 按累計等級降序排列；同等級時按技能名稱、技能 ID 升序。
- 累計為零的範圍內技能仍保留並顯示 `Lv.0`。
- 區塊標題為「全艦冒險技能累計」，輔助說明須明確表達「統計上方全部航海士」及「僅列出預設範圍」，不得命名為「預設目標技能」。

若預設目標範圍為空，仍允許生成航海士分享圖；技能區顯示「尚未設定預設範圍」。

## 技能語義

- 技能累計只使用同一筆航海士技能關係的 canonical `level`，不得使用 `unlockLevel`。
- 主動／被動只依關係的 `kind` 判斷，不得根據技能名稱、圖標、槽位或解鎖等級推斷。
- 航海士關係中 `level` 缺失或無效時，該筆關係不貢獻累計值；資料異常仍由既有校驗流程處理。
- 分享圖中的「Lv.N」是指定範圍內的綜合累計等級，不是單一航海士技能角標，也不是解鎖等級。

## 素材與小程序碼

- 正式小程序首頁碼作為本地受控 UI 素材維護，生成分享圖時不發起臨時網路請求。
- 小程序碼周圍保留足夠留白，Canvas 縮放後仍需真機掃碼驗證。
- 遠程頭像與技能圖標沿用既有生成資料中的素材路徑；分享生成器集中處理圖片載入、超時與失敗降級，不在頁面散落素材處理邏輯。
- 本地佔位圖須能區分「人物素材缺失」與「技能素材缺失」，且不能使用 Emoji 代替正式圖標。

## 錯誤處理

- 重複點擊：生成中禁用入口並顯示可見狀態。
- 個別素材失敗：使用本地佔位素材繼續生成；預覽層提示「部分素材未載入」，但不阻止分享。
- Canvas 初始化或導出失敗：關閉生成中狀態，保留目前配置，顯示可理解的錯誤與「重試」。
- 保存相冊被拒絕：提示用戶在小程序設定中開啟相冊權限，不重複強制拉起授權。
- 分享能力不可用：保留保存到相冊入口，並提示用戶可保存後從微信分享。
- 小程序碼素材缺失：視為不可降級錯誤，禁止生成不含入口碼的正式分享圖。

## 測試與驗收

### TDD 單元測試

Presenter 測試至少覆蓋：

- 戰鬥技能只統計本船航海士；
- 主動技能按綜合等級取 TOP 5；
- 被動技能只保留 canonical 戰鬥分類且累計不低於 Lv.2；
- 主動、被動同分排序穩定；
- 冒險航海士按 S、A、B、C 分組，組內順序穩定；
- 冒險技能只取預設範圍、累加上方全部航海士並降序排列；
- 冒險範圍内技能累計為零時顯示 `Lv.0`；
- `level` 與 `unlockLevel` 不互換，`kind` 不由其他字段推斷；
- 空位、缺失素材及無效技能關係的處理。

Renderer／布局測試至少覆蓋：

- 五欄技能行數與內容高度計算；
- 七船、每船 11 人及四行以上被動技能不被裁切；
- 冒險各品質分組的行數與技能區起始位置；
- 頁尾與小程序碼不覆蓋內容；
- 相同 View Model 產生確定性的繪製指令順序。

頁面測試至少覆蓋未保存提示的三條分支、保存成功後生成、保存失敗不生成、重複觸發攔截、預覽關閉、分享圖片與保存相冊錯誤。

### 微信 DevTools 與真機驗收

- 戰鬥配置以七船、每船 11 人及被動技能四行以上的案例生成，確認內容完整。
- 冒險配置以 S、A、B、C 多行分組、預設範圍含 `Lv.0` 的案例生成。
- 在微信圖片預覽與聊天圖片中確認航海士名、技能名、品質徽章、類型圖標及累計等級可辨識。
- 在至少一台 iOS 與一台 Android 真機掃描圖片內小程序碼，確認進入小程序首頁。
- 驗證個別遠程素材失敗仍可生成，且佔位與提示正確。
- 驗證保存相冊拒絕、分享能力不可用及 Canvas 導出失敗流程。

### 工程門禁

- 執行相關定向 Vitest 測試與 `npm run verify`。
- 執行 `git diff --check`。
- 確認沒有修改 `archive/`、`data/master/`、`miniprogram/generated/` 或 `miniprogram/subpkg-fleet/generated/`。
- 確認沒有新增／升級依賴，沒有在小程序 Runtime 新增 `wx.request`、`wx.cloud`、遠程 URL 字面量或 Node.js API。

## 非目標

- 不分享可匯入的配置資料、配置 ID 或用戶身份。
- 不新增分享預覽落地頁；掃碼只進入小程序首頁。
- 不新增雲端圖片生成、圖片永久存儲或公開分享鏈接。
- 不修改既有配隊求解器、配置上限、配置衝突或保存語義。
- 不修改航海士、技能或素材 canonical 資料。

## 完成條件

- 戰鬥與冒險配隊均可從目前狀態生成符合本規格的分享長圖。
- 未保存狀態可選擇直接生成、保存後生成或取消，且各分支不破壞既有配置狀態。
- 戰鬥分享圖完整展示七船構成、主動 TOP 5 與符合條件的戰鬥被動技能。
- 冒險分享圖按 S、A、B、C 展示全部航海士，並正確顯示預設範圍內的全艦實際技能累計。
- 分享圖包含可掃描並進入首頁的小程序碼。
- 素材降級、Canvas 錯誤、分享與相冊權限錯誤均有可恢復處理。
- 相關自動化測試、微信 DevTools／真機驗收與完整工程門禁通過。
