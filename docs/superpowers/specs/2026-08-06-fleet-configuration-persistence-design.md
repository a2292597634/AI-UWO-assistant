# 配隊配置保存與使用者雲端管理設計

## 1. 設計狀態

- 日期：2026-08-06
- 適用範圍：配隊頁的個人配置保存與管理
- 設計狀態：已完成需求確認，等待進入實作計畫
- 推薦後端：CloudBase 雲函數服務層 + CloudBase 雲資料庫

## 2. 已確認需求

每位微信小程序使用者都可以管理自己的配隊配置，配置資料按使用者隔離。

- 每位使用者最多保存 20 套配置。
- 配置可新建、載入、覆蓋保存、另存為、重命名和刪除。
- 新建配置時必須輸入名稱；同一使用者下的配置名稱不可重複。
- 刪除配置前必須二次確認。
- 進入配隊頁並完成登入後，自動載入上次使用或最後修改的配置。
- 沒有已保存配置時，顯示空白配隊頁並提供建立配置入口。
- 修改已載入配置後，只有明確保存才會寫入雲端。
- 有未保存修改時，離開頁面、切換配置、另存為、重命名或刪除前，必須提示保存、放棄或取消。
- 未登入也可以正常配隊和修改；點擊保存時才要求登入。
- 未登入期間編好的配置，在登入成功後保留，直接進入命名並保存為新配置流程。
- 配置可在換手機或重新安裝小程序後，透過同一微信身份恢復。
- 暫不做配置分享、公開查看、多人共同編輯和即時同步。

## 3. 個人資料與身份

本功能只需要能識別「目前是哪一位小程序使用者」，不需要收集微信個人資料。

- 登入按鈕觸發微信小程序身份登入。
- 不呼叫取得暱稱、頭像、手機號或其他個人資料的授權流程。
- 雲函數從服務端上下文取得使用者身份，前端不得自行提交或修改 `ownerUid`、`openid` 等所有權欄位。
- 後端以 CloudBase 使用者身份或微信 `OPENID` 關聯配置；前端只操作「我的配置」接口。

CloudBase 官方資料：

- [CloudBase 身份認證概述](https://docs.cloudbase.net/authentication/auth/introduce)
- [CloudBase 小程序身份說明](https://docs.cloudbase.net/ai/cloudbase-ai-toolkit/prompts/auth-wechat)

## 4. 架構與資料流

採用以下三層結構：

```text
配隊頁
  ↓ 受控配置服務呼叫
CloudBase 雲函數
  ↓ 服務端身份校驗、資料驗證、版本檢查
CloudBase 雲資料庫
```

### 4.1 未登入流程

1. 使用者進入配隊頁。
2. 頁面顯示空白配隊狀態，不載入任何雲端配置。
3. 使用者可以正常使用全部配隊操作。
4. 頁面保存入口顯示「登入後保存」。
5. 點擊保存後進入登入流程；登入失敗時保留頁面狀態並允許重試。

### 4.2 登入後流程

1. 登入成功後，保留登入前正在編輯的未保存配置。
2. 若登入前存在未保存配置，直接進入命名並保存為新配置流程。
3. 若登入前沒有未保存配置，取得該使用者的配置列表。
4. 自動載入 `lastUsedAt` 最新的配置。
5. 若沒有上次使用配置，顯示空白配隊頁和建立配置入口。

### 4.3 運行時網路邊界

目前專案禁止小程序運行時任意使用 `wx.cloud`、`wx.request`、遠端 URL 和 Node.js API。實作本功能時必須將規範調整為：

- 只允許專用配置服務使用受控的 CloudBase 呼叫。
- 頁面不得直接操作 CloudBase 資料庫。
- 頁面不得拼接任意遠端 URL 或執行任意網路請求。
- 必須有專門的配置服務適配層，讓頁面只依賴本地介面。
- 網路品質門禁只放行已登記的配置服務呼叫，其他遠端存取仍然失敗。

## 5. 配置資料模型

每套配置是一筆使用者私有資料，建議欄位如下：

| 欄位 | 說明 |
| --- | --- |
| `configId` | 配置唯一識別碼 |
| `ownerUid` | 後端依登入身份寫入的擁有者識別碼 |
| `name` | 配置名稱；同一使用者下不可重複 |
| `fleetState` | 實際配隊資料 |
| `schemaVersion` | 配置資料結構版本 |
| `version` | 樂觀鎖版本號，用於偵測跨設備衝突 |
| `createdAt` | 服務端建立時間 |
| `updatedAt` | 服務端最後更新時間 |
| `lastUsedAt` | 服務端最後載入或保存時間 |

`fleetState` 只保存目前配隊的業務狀態：

- 7 艘船的順序與配置
- 每艘船的手動／自動模式
- 航海士 ID
- 鎖定航海士與移除航海士
- 排除航海士
- 目標技能與目標等級
- 需要重新檢查的狀態

不保存搜尋文字、技能篩選條件、目前選中船、滾動位置、圖片載入狀態等暫時畫面狀態。

名稱比較先移除前後空白，再檢查同一使用者下是否重複。配置上限由後端建立和另存為接口共同強制；重命名不增加配置數量。

## 6. 配置管理介面

配置管理區採精簡設計：

- 一行顯示目前配置名稱與「已保存／尚未保存」狀態。
- 點擊配置名稱開啟配置列表。
- 「保存、另存為、重命名、刪除、新建」收進單一管理選單。
- 只有存在未保存修改時，才突出顯示保存操作。
- 配置列表顯示名稱、最後修改時間和目前使用狀態。

操作定義：

- **保存**：新配置先輸入名稱建立；已載入配置依版本號覆蓋保存。
- **另存為**：輸入新名稱建立新配置，原配置保持不變。
- **載入**：切換到指定配置，並更新最後使用配置。
- **重命名**：修改配置名稱，保留配置內容和版本。
- **刪除**：二次確認後刪除；不自動建立替代配置。
- **新建**：建立空白本地草稿，保存時輸入名稱並建立雲端配置。

若目前有未保存修改，載入、另存為、重命名、刪除、建立新配置和離開頁面前都要提供：

- 保存並繼續
- 放棄修改
- 取消操作

## 7. 雲函數操作介面

雲函數服務只暴露目前需求需要的操作：

- `listMyConfigs`
- `loadConfig`
- `createConfig`
- `updateConfig`
- `saveAsConfig`
- `renameConfig`
- `deleteConfig`
- `setLastUsedConfig`

所有接口都從服務端上下文取得目前使用者，並在服務端執行：

- 所有權檢查
- 配置資料 Schema 驗證
- 配置名稱唯一性檢查
- 20 套上限檢查
- `schemaVersion` 相容性檢查
- `version` 樂觀鎖檢查

`updateConfig` 必須帶上頁面載入時取得的 `version`。若資料庫版本已不同，回傳版本衝突，不直接覆蓋。

## 8. 錯誤處理

- 登入失敗：保留目前頁面狀態，顯示重試入口。
- 配置列表載入失敗：顯示載入失敗，不能誤顯示成空列表。
- 配置不存在：返回配置列表或空白狀態，不自動載入其他配置。
- 保存失敗：保留頁面修改，狀態維持「尚未保存」。
- 版本衝突：保留本地修改，提供「重新載入雲端版本」或「強制覆蓋」。
- 重新載入雲端版本：明確提示本地未保存修改將被放棄。
- 強制覆蓋：再次確認後，以最新版本號作為寫入基礎，但寫入內容仍是目前頁面的本地配置，不做自動欄位合併。
- 配置引用失效 ID：不靜默刪除，標記為「需要重新檢查」，由使用者修正後保存。
- CloudBase 暫時不可用：仍可編輯目前頁面，但不能把失敗保存標記為成功。

## 9. 測試與驗收標準

### 9.1 後端與資料測試

- 使用者只能讀取自己的配置。
- 使用者不能以請求欄位偽造其他使用者的 `ownerUid`。
- 新建和另存為最多允許 20 套配置。
- 同一使用者的配置名稱不可重複。
- 不同使用者可以使用相同配置名稱。
- 重命名會檢查名稱唯一性。
- 刪除需要通過所有權檢查。
- 舊版本保存會回傳衝突，不會覆蓋新版本。
- 配置資料格式錯誤會被拒絕。
- 配置序列化和反序列化只包含已確認的 `fleetState` 欄位。

### 9.2 頁面流程測試

- 未登入可以正常配隊。
- 未登入保存會提示登入。
- 未登入編輯的配置在登入後保留並可直接另存為。
- 登入後自動載入最後使用配置。
- 新建、載入、覆蓋保存、另存為、重命名和刪除流程正確。
- 未保存修改離開或切換時能正確提示。
- 保存失敗時不清除本地修改。
- 版本衝突時可以重新載入或強制覆蓋。
- 跨設備登入可以取得同一使用者的配置列表。

### 9.3 專案架構檢查

- 配置服務以獨立適配層供頁面使用。
- 頁面不直接使用 CloudBase 資料庫 API。
- 只放行配置服務需要的受控 CloudBase 呼叫。
- 不新增未經確認的依賴。
- 完成後通過專案要求的相關資料、型別、測試和運行時網路檢查。

## 10. 明確不包含

- 配置分享或公開查看
- 配置匯入分享碼
- 多人共同編輯
- 即時同步
- 暱稱、頭像、手機號等微信個人資料
- 本地離線草稿與雲端自動同步
- 配置歷史版本列表
