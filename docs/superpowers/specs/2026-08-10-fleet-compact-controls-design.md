# 配隊目標與戰鬥技能篩選緊湊化設計規格

日期：2026-08-10

## 目標

修復戰鬥配隊與冒險配隊頁面的窄屏密度問題：縮小技能目標選擇、刪除、等級輸入控件的實際視覺與觸控熱區，降低目標行高度；縮小戰鬥頁內嵌技能篩選按鈕，讓首屏能看到更多選項；移除冒險配隊技能追蹤目標內重複的「技能追蹤 · 不參與計算」文字。

## 根因

目標行的 `.level-input`、`.target-row__remove` 與共用 `skill-picker-sheet` 的技能選擇按鈕使用接近 `88rpx` 的高度，且目標行自身同時配置較大的上下間距。戰鬥頁內嵌篩選 Tab 也沿用較大的按鈕內距，導致可見選項數量不足。

## 設計

- 戰鬥與冒險頁的目標行統一採用緊湊間距與較小控件高度；等級輸入框和刪除按鈕約為 `56rpx` 高，保留現有文字、事件與資料綁定。
- 共用 `skill-picker-sheet` 僅對 `inline` 模式縮小篩選 Tab 與技能選擇按鈕；彈窗模式維持現有尺寸，避免影響冒險頁新增目標的 Bottom Sheet。
- 內嵌篩選 Tab 使用較小水平內距和間距，保留既有橫向滾動與選中狀態。
- 冒險配隊移除追蹤目標列中的狀態文字；保留「技能追蹤」區塊層級的提示，避免失去區塊語義。
- 不修改 Controller、Presenter、Domain、Solver、配置保存流程、事件名稱或資料結構；不新增依賴，不修改 `archive/`、`data/master/` 或 `miniprogram/generated/`。

## 驗收與測試

- 頁面結構測試確認戰鬥與冒險目標控件仍存在，且冒險追蹤目標不再包含重複狀態文字。
- WXSS 結構測試確認目標控件與戰鬥內嵌篩選使用緊湊尺寸規則，並維持 Token 化樣式。
- 執行相關 Vitest 測試、`npm run verify` 與 `git diff --check`。
- 人工檢查 320px、375px、393px、430px 寬度下，目標行不再被右側控件不必要地撐高，戰鬥篩選列能顯示更多按鈕，且控件仍可操作。

## 變更邊界

只修改與本問題直接相關的頁面 WXML/WXSS、技能選擇元件 WXSS 和對應結構測試；不順手修復其他頁面或既有問題。
