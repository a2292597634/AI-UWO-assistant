# 大流行預測模組設計規格

## 1. 目標與使用情境

為《Uncharted Waters Origin》微信小程序新增「大流行預測」模組，讓玩家能查看多個海域未來的大流行發生時刻，並查看事件影響的交易品類別。主要使用情境是玩家在安排航線或貿易前，快速比較各海域接下來的事件；次要情境是指定海域與事件類型，查詢下一次發生時間。

本模組使用繁體中文，預測資料隨小程序離線提供。設計延續「海域為列、時間為欄」的時刻矩陣，並提供按時間排序的行程列表。生圖概念只供比較資訊布局；實際介面沿用本倉庫的首頁導航與 Design Foundation，不新增概念圖中的全域底部導覽列。

## 2. 現有專案與來源核對

- 目前沒有大流行頁面或 `data/master` 大流行資料。貿易品查詢位於 `subpkg-trade`，採用 `data/master`、資料生成器、分包內生成資料和 Data Store 的本地資料模式。
- 首頁主要入口使用三欄網格，目前只顯示前五個主要模組。新增獨立入口後，須將六個主要入口都顯示，形成兩列各三個入口。
- 2026-09-24 以唯讀方式檢查 voyage.tw 的 `map.js`、`json.js`、`lang_1.js`；HTTP 狀態均為 200，檔案大小和 SHA-256 與倉庫 2026-09-03 快照相符。快照版本為 `2026052501`，來源清單位於 `archive/voyage-tw-2026052501-trade-20260904/raw-data/source-manifest.json`。
- 大流行來源函式的規則為：`pHour = floor((now - 1670889600) / 3600)`，`Si = pHour + 401 × zoneHour + iHour`；任一事件類型在 `Si % periodHours === 0` 時發生。
- 快照含 18 個海域設定與 8 個事件週期。海域欄位 `z` 是計算相位用的時區值；`d` 是 0 至 600 秒的觸發延遲。來源以使用者裝置本地時間顯示事件時刻，並以 JavaScript `Math.round(d / 60)` 顯示分鐘。這個 `z` 用於預測相位，不可當作使用者選擇的 IANA 時區來格式化畫面時間。
- 事件週期如下：

## 3. 方案比較與決策

### A：時刻矩陣單一視圖

矩陣方便比較同一時段的海域，但長期預測會有許多時間段，逐段查看效率較低。

### B：依海域分組的事件時間線

這種方式適合追蹤單一海域，但 18 組海域會拉長頁面，也不利於比較同一時間不同海域的事件。海域篩選和全域行程列表已能覆蓋此需求，因此不納入首版。

### A + C：矩陣預設、全域行程切換

採用此方案。矩陣保留海域與時間的對照，行程列表提供長期事件瀏覽和篩選；兩者共用同一套本地預測結果與事件詳情。

## 4. 導航與頁面架構

- 在首頁主要模組網格增加「大流行預測」入口，放在貿易品入口旁；首頁顯示六個主要入口，維持三欄兩列。使用既有首頁模組卡片樣式，不新增全域底部導覽。
- 頁面加入既有 `subpkg-trade`，路由使用 `/subpkg-trade/pages/popularity/index`。大流行資料同屬貿易查詢範圍，使用獨立 Domain、Presenter、Runtime Store 和頁面檔案，避免把計算邏輯放進頁面控制器。
- 新增首頁入口圖示時，沿用既有航海資料館圖示系統：本地來源素材置於 `data/master/ui-assets`，透過 `tools/ui-assets/config.ts` 生成 96×96、單檔不超過 4 KB 的頁面圖示，非透明內容邊界目標為 84–88px；圖形概念為羅盤與時間刻度，使用既有黃銅及深色語義，不加入 Emoji 或文字。2026-09-24 檢查時 `miniprogram/assets/ui` 已有 249,776 bytes，接近 250 KiB 上限；此入口圖示是唯一新增到主包的本模組圖片，其餘裝飾與小圖示放入貿易分包。
- 頁面視圖切換為「時刻矩陣」與「行程列表」。選取的預測範圍和篩選條件在兩種視圖間保留。

## 5. 預測範圍與瀏覽方式

### 時刻矩陣

- 矩陣與行程共用「24 小時／3 天／7 天」範圍選擇，預設 3 天。範圍是從畫面更新時刻開始的精確滾動區間 `[now, now + horizon)`；更新或切換範圍後重新計算。矩陣以這個起點切成連續六小時區段，因此三種範圍固定為 4、12、28 段，每段六個一小時預測槽；首尾不按整點取整。
- 日期列顯示與預測範圍相交的所有裝置本地日期，日期數隨更新時刻變動：24 小時通常涵蓋 2 日、72 小時涵蓋 3–4 日、168 小時涵蓋 7–8 日。窄屏時只允許日期列在自身範圍內水平捲動，不得造成頁面級橫向溢出。選日後跳到與該日期相交的第一個六小時段；段控制顯示目前段序號／總段數、完整起訖日期時間，並支援上一段、下一段及快速跳日。
- 18 個海域為列，每列顯示六個一小時預測槽。矩陣首欄呈現完整名稱和 40rpx 徽記；窄屏時矩陣可在自身區域水平捲動，頁面本身不得橫向溢出。海域篩選可在「全部海域」和單一海域間切換。
- 欄頭顯示每個預測槽的裝置本地起始時間（`HH:mm`），段標題顯示完整日期時間範圍及「依裝置時間」。事件格和詳情顯示裝置本地 `HH:mm`；日期與小時取自實際 Unix 觸發時刻，分鐘依來源以 `Math.round(delaySeconds / 60)` 取整，因此 `390` 秒顯示 `07` 分，不可直接用 `Date` 的分鐘數代替。整點事件標示「整點」。同格兩種事件以兩個可點選的小籤分開顯示；空格以短橫線表示。跨日段依絕對時間排序；遇到夏令時間重複的本地時刻時，在詳情補上 UTC 偏移以消除歧義。
- 頁首摘要顯示所選範圍內的事件數，以及有預測事件的海域數，例如「未來 72 小時 · 36 筆預測 · 16／18 海域」。數字由預測結果計算，不寫入靜態資料。
- 概念圖中的 `17:04`、`36 筆預測` 和 `2026/09/24 17:07` 都是排版示例；實作時要依裝置時間、目前範圍及來源資料動態計算，不得硬編碼圖中日期或數字。

### 全域行程列表

- 預設按預測時間排序，依裝置本地日期分組，提供 24 小時、3 天、7 天範圍。
- 同一分鐘發生的事件可共用時間標題，事件列顯示海域、類型和受影響品類。支援按海域或事件類型篩選；篩選後無結果時明確顯示條件和空狀態。
- 在指定海域及事件類型後，可使用「查下一次」取得下一個週期事件。計算上限為最長週期 379 小時，介面以「約 16 天內」說明搜尋範圍，不生成 16 天的完整列表。
- 點選矩陣事件或列表事件，開啟共用底部詳情面板。面板列出事件類型、海域、日期與預測時刻，以及受影響的交易品類；首版不呈現未確認語義的區間數值。

#### 版面層級與尺寸

- 畫面由上而下固定為：深綠品牌抬頭、動態預測摘要、範圍選擇、矩陣／行程切換、與目前視圖相關的日期段或篩選控制、主要內容。詳情 Bottom Sheet 疊在頁面之上；不得把品牌抬頭重複放進內容卡。
- 沿用 Design Foundation 字級：頁面標題 `40rpx`、區塊標題 `32rpx`、強調正文 `28rpx`、正文 `26rpx`、輔助正文 `24rpx`；事件籤主名稱不低於 `22rpx`。間距只用 `4/8/12/16/24/32/48rpx`；一般控制圓角 `10rpx`、內容表面 `16rpx`、Bottom Sheet `28rpx`、標籤採膠囊圓角。
- 重要操作觸控區至少 `88rpx` 高；矩陣事件籤可點開詳情，籤的觸控高度也不得低於 `88rpx`，同格兩種事件分行顯示並讓列高自然增加。一般資訊卡不用陰影，詳情 Bottom Sheet 使用 Design Foundation 的 sheet 陰影及底部安全區。矩陣窄格內交易類別不另放圖示，事件類型與實際時間仍須可讀。
- 矩陣左側海域欄目標寬 `216rpx`（40rpx 徽記加完整名稱），每個時間欄至少 `88rpx`，整張表約 `744rpx`。320px 寬度時允許矩陣在自身容器內水平捲動，以維持六小時槽與事件籤的可讀／可點尺寸；不得縮小文字到 Design Foundation 下限以下或讓整頁溢出。
- 海域名稱和交易類別名稱旁的圖像只作裝飾，輔助技術不重複朗讀圖像；可點事件的無障礙名稱須包含海域、事件類型、日期與顯示時刻。選中、停用或錯誤狀態須同時有文字／形狀提示，不單靠色彩傳達。

#### 頁面底圖與裝飾

- 三種畫面共用淡色航海圖紙紋理：細紙纖維、少量海岸等高線與稀疏海圖刻度，不含文字、Logo 或數據。底色使用 `canvas` Token，紋理透明度控制在 5–8%，不得降低正文對比度。
- 矩陣頁在抬頭左側放置淡化帆船線描，右上放置羅盤玫瑰；海域表格之外保留淡化的航海線紋。裝飾只能落在留白和邊緣，不得落在事件文字後方。
- 行程列表沿用相同紙紋，日期軸使用黃銅細線與圓點；內容末端加入淡化的港口／海岸剪影，右下放置羅盤水印。
- 詳情 Bottom Sheet 使用完整淺色表面，右側放置低透明度羅盤水印，以細黃銅線分隔「預測時間」和「受影響交易類別」。手把、關閉操作和底部安全區必須清楚。
- 頁面抬頭使用深綠底、淺色標題和一條細黃銅分隔線；左側以現有首頁文案「航海資料館」作小型品牌字樣，配羅盤飾件，中央標題為「大流行預測」。保留微信原生狀態列和小程序導航列，不仿造新的手機狀態列、不新增全域底部導覽列、不複製生成圖中不準確的「大航海時代 ORIGIN」假 Logo。
- 普通內容區只使用一層容器，不做「頁卡包區塊卡、區塊卡再包條目卡」。一般卡片不用陰影；邊框、留白和底色負責建立層級。
- 範圍、視圖和篩選控制採同一套黃銅／深綠交互語義：選中項使用深綠底、淺色文字及細黃銅邊；未選中項使用淺色或次要表面、主要文字；按下和焦點狀態沿用 Design Foundation。日期列與矩陣控制不得改變頁面寬度。
- 行程列表以細黃銅垂直線和小圓點作時間軸，日期作區段標題；每筆事件只保留一層淺色列面，以細分隔線區分。空狀態和資料錯誤狀態使用相同紙紋底與清楚文字，不使用事件分類色營造錯誤語義。

## 6. 資料與計算架構

### 權威資料

- 新增 `data/master/major-events.json` 作為唯一手動維護的大流行資料源。內容使用穩定 ID，包含來源快照版本、`sourceManifestSha256`、計算錨點秒數、8 個事件週期、18 個海域的來源名稱／相位小時／延遲秒數／徽記 ID，以及每種事件所影響的交易品類 ID 清單（ID 取自完整 20 類清單）和逐列來源引用；事件及海域陣列保留來源順序。不複製交易品類圖示資產或圖示路徑。
- `archive/` 只保留來源快照，不修改；`miniprogram/subpkg-trade/` 中任何生成資料只能由 `npm run data:generate` 建立，不手動編輯。
- `tools/data-pipeline/generate.ts` 呼叫獨立的產生器，產生分包內大流行執行資料。校驗納入 `npm run data:check`；生成一致性納入 `npm run generate:check`。

### 執行資料流

```text
data/master/major-events.json
        ↓ data:generate
miniprogram/subpkg-trade/ 大流行生成資料
        ↓ Runtime Store
純 Domain 計算未來觸發時間
        ↓ Presenter
矩陣、行程列表與事件詳情
```

頁面不得呼叫遠程來源。Runtime Store 只讀生成資料；生成參考資料保留來源 snapshot、version 和 manifest hash，但不帶來源 URL/ref 到 Runtime。Domain 接收明確的現在時間和選取範圍，回傳排序穩定的事件結果；事件優先次序及海域列次序保留權威資料的來源順序。Presenter 負責日期、時間及繁體中文顯示字串。行程和詳情面板將來源 ID `tradetypeNN` 正規化成兩位數類別 ID `NN`，再呼叫共用交易類別圖示解析器取得路徑；不得在大流行頁重建或複製類別圖示表。

### 預測規則

1. 以來源錨點和目前 Unix 時間計算 `pHour`。
2. 對每個海域與未來整點，以 `Si = pHour + 401 × zoneHour + iHour` 判定八種週期。
3. 觸發時刻加入該海域 `delaySeconds`。對目前小時，只有延遲時刻尚未經過的事件才列入預測；已經過的事件不顯示為未來事件。
4. 以裝置本地時區呈現日期與小時；畫面分鐘依來源 JavaScript `Math.round(delaySeconds / 60)` 規則另行計算，不直接採用 `Date` 的分鐘欄位。跨日事件同時帶日期，避免只顯示小時造成誤認。
5. 預測區間採左閉右開 `[現在, 現在 + horizon)`，避免邊界事件重複出現在相鄰區間。
6. 同一海域、同一時段遵循來源的事件順序，最多回傳兩種事件。
7. 頁面首次載入、返回前景、每分鐘邊界及使用者下拉更新時重新捕捉 `now` 並刷新結果；頁面隱藏時停止分鐘計時器。刷新後保留目前視圖和仍有效的篩選；若目前日期已離開範圍，選取新的第一個本地日期，並將矩陣段索引限制在有效範圍內。

## 7. 狀態與錯誤處理

- 本地資料可載入時，顯示預測結果和來源核對日期；日期取自大流行資料的權威主檔，不使用整個資料集的通用更新時間。來源版本與雜湊保留在本地資料中供維護核對，不直接展示給玩家；沒有符合範圍或篩選條件的事件時，顯示清楚的空狀態，不視為錯誤。
- Runtime 資料缺失或結構無效時，不顯示看似有效的空矩陣；顯示「大流行資料暫時無法載入，請更新小程序後再試」。資料校驗應在建置前阻止缺漏或不相容的來源資料進入生成輸出。
- 不提供線上自動更新。若來源版本或公式改變，需更新 `data/master` 並重新通過資料校驗；不相容的來源版本應使生成失敗，不得在 Runtime 中靜默套用舊公式。
- 預測狀態只描述「預計觸發時間」，不得標記為「正在發生」或推算結束時間。

## 8. 驗證與驗收

### Domain 與資料測試

使用固定時間輸入，先寫測試再實作計算邏輯，涵蓋：

- 八個週期的整點命中、前一小時／下一小時未命中及模數邊界。
- 18 個海域相位和延遲秒數，以及延遲已過／尚未到的目前小時邊界。
- JavaScript 分鐘取整規則，特別驗證 `390` 秒顯示為 `7` 分鐘。
- 日期跨日、裝置本地時區格式、24／72／168 小時區間邊界及「查下一次」的 379 小時上限。
- 同一海域同一時段的兩種事件順序及最多兩種結果。
- 生成器排序穩定、來源引用保留、有效資料輸出可由 Runtime Store 讀取。
- 使用固定來源樣本比對前 24 小時結果；測試不在執行時下載 voyage.tw。

### 微信 DevTools 頁面驗收

依 `docs/superpowers/specs/2026-09-16-miniprogram-review-html-report-design.md` 為新頁面建立場景，HTML 報告內直接展示修改後截圖。至少驗收：

- 矩陣與列表視圖切換、範圍切換、上一／下一時間段、海域和事件類型篩選、事件詳情及空狀態。
- 篩選空狀態以本地有效資料的預測組合驗收；「查下一次」的無命中分支以合成超出 379 小時週期上限的 Runtime fixture 做頁面控制器測試，因有效來源的最長週期就是 379 小時，不會產生可重現的正常資料無命中畫面。
- 320px、375px、393px、430px 寬度下無新增頁面級橫向溢出；320px 時日期列和矩陣都只在各自容器內捲動，矩陣仍可辨識海域、一小時槽欄頭與觸發時間。
- 首頁第六個入口可見並導向大流行頁；圖示載入失敗時使用既有 fallback。
- 跨日時間使用裝置本地日期，詳情與矩陣／列表結果一致。
- Design Foundation 規格、`design-foundation.wxss` 和 Token 契約測試都包含本規格的 4 個事件分類 Token；色籤文字對比度至少 4.5:1，事件名稱仍可在不看顏色時辨認。
- 18 個來源海域都有正確對應的本地徽記；20 個來源交易品類都經 `getTradeCategoryIconPath` 使用篩選和詳情頁共用的圖示，例如來源 ID `tradetype01` 正規化為 `01` 並解析到 `/subpkg-trade/assets/category-icons/01.png`。矩陣、列表和詳情面板使用正確圖示及來源名稱，沒有概念圖中的示例假名稱，也沒有複製生成的類別圖示。
- 航海圖紙紋、矩陣帆船與羅盤、行程底部港口剪影、詳情羅盤水印都出現在指定位置；裝飾透明度不遮擋內容，也不造成文字對比度不足。
- 主包 UI 圖片總量不超過 250 KiB；首頁新圖示不超過 4 KB；大流行頁分包新增圖片不超過 96 KB；素材重建結果符合 `assets:ui:check` 和 `check:miniprogram-size`。

### 工程門禁

完成實作後，執行與本次變更相關的測試及 `npm run verify`。確認 `archive/`、手動生成資料以外的 `miniprogram/generated/` 和分包生成輸出沒有手動修改；確認沒有新增依賴、Runtime 網路請求或 Node.js Runtime API。

## 9. 範圍外

- 不提供通知、背景排程、使用者自訂時區、追蹤收藏海域或個人化提醒。
- 不提供按海域分組的第三種視圖、海圖標記或航線最佳化。
- 不推測事件開始後的持續時間、結束時間或即時生效狀態。
- 不顯示未確認的交易價格區間，也不查詢港口當下售價。
- 不製作或重新發布交易品類別圖示；重用「新增交易品类别小图标」任務完成後提供的 20 類本地素材及 ID 對應。
- 不新增 Runtime 遠程請求或自動抓取來源資料的服務。
