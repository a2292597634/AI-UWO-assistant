# 冒險預設技能追蹤可見設計規格

日期：2026-08-09

## 目標

讓冒險配隊新艦隊已預先配置的 `Lv.0` 技能追蹤在自動模式工作區直接可見，避免使用者誤以為沒有任何預設目標。

## 根因

冒險頁初始化時會建立非空的 `Lv.0` 技能目標。P6 將這些資料正確映射為 `trackingTargets`，但「技能追蹤」折疊區塊使用 `default-expanded="{{false}}"`，因此預設首屏只看得到沒有 `Lv.1+` 優化目標的空狀態。

## 設計決策

- 保留 `Lv.0` 的技能追蹤語義，不讓它們進入 Solver。
- 冒險頁的「技能追蹤」區塊改為 `default-expanded="{{true}}"`。
- 「全艦隊排除名單」與「全艦隊冒險技能累計」仍預設收起，維持低頻資訊的密度控制。
- 不修改 Presenter、Controller、Domain、Solver、資料、配置保存或既有事件 handler。

## 驗收條件

- 新建冒險頁進入自動模式時，預設技能追蹤區塊已展開並顯示技能列。
- 技能追蹤列仍標示 `Lv.0` 僅供查看、不參與計算。
- 優化目標仍只有使用者設定 `Lv.1+` 後才出現並啟用重新計算。
- 全艦隊排除名單與技能累計仍預設收起。
- 不新增依賴、網路請求、遠端 URL、Node.js Runtime API，也不修改受保護目錄。

## 測試策略

先在頁面結構測試加入「技能追蹤使用 `default-expanded="{{true}}"`」的失敗契約，確認目前基線會失敗；再把 WXML 屬性改為 `true`，執行 focused tests 與完整 `npm.cmd run verify`。
