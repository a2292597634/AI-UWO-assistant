# 使用者留言板設計

## 1. 目標、已確認決策與設計邊界

從首頁進入獨立留言板，讓玩家留下航海心得、問題與建議。公開留言顯示暱稱、頭像及所選伺服器，由管理員審核後公開。

使用者已確認三項產品決策：

- 首次留言由使用者主動選用微信暱稱、頭像，保存後供後續留言帶入。
- 留言前必須選擇伺服器，選項與兌換碼頁一致。
- 管理員審核後公開。

其餘數值、管理功能及技術細節是本文件的第一版設計建議。本階段只修訂設計、實施計畫與已授權的網路規範文字，不修改業務程式碼、依賴、實際掃描白名單或正式雲端配置，不提交或部署。

功能包含首頁入口、公開列表、寫留言、我的留言、留言資料設定、管理員審核與一則管理員回覆。為使公開內容有處置閉環，另包含輕量檢舉、解除投稿限制及清除本人留言資料。後三項是此次審查補充的建議，尚未視為使用者單獨批准。

第一版不加入玩家互相回覆、图片留言、點讚、私訊、搜尋、置頂、通知訂閱或遊戲帳號驗證。既有資料錯誤回報保持獨立。

## 2. 核心不變條件

1. 身分來自本次平台驗證的呼叫上下文，不採用客戶端提供的 OpenID、角色、時間或審核結果。
2. 自動內容檢查與管理員公開是兩個步驟。安全檢查通過也不能自動公開。
3. 正文、暱稱、頭像皆有與實際內容綁定的檢查結果；管理員回覆單獨檢查。
4. 投稿後正文、作者展示快照及伺服器不可編輯。個人資料更新不能改動已投稿內容。
5. 公開回應使用欄位白名單，不含作者私有識別、拒絕原因、內部風控資料或未公開檔案參照。
6. 所有寫入由服務端校驗。前端隱藏按鈕與資料庫記錄存在都不是權限證據。
7. 超時是結果未確認，不能當作失敗後再用新 request ID 重建留言。
8. 資料庫交易中不得呼叫圖片上傳或微信檢查等外部服務，避免交易重試重複執行副作用。
9. 撤回及下架後，新的公開查詢不再返回內容；不承諾抹除他人已讀畫面、截圖或已發出的查詢結果。
10. 遊戲靜態資料仍遵循 `archive/ → data/master/ → 工具生成`；線上留言資料保存於獨立 CloudBase 集合。

## 3. 使用者流程與頁面

### 3.1 首頁與公開列表

2026-10-06 使用者明確指定：留言板不作為單獨功能圖標，與「資料錯誤回報」在同一次級區並列。首頁保留既有六項主功能圖標及順序，下方「交流與回報」區提供兩個同級文字入口：資料錯誤回報、留言板；兩者整張卡片均可點擊。留言板提示「分享航海心得與建議」，不加入主功能圖標區、不新增留言板圖標素材。入口路由為 `/subpkg-message-board/pages/board/index`。

入口先行版本提供可打開／返回首頁的獨立頁面，清楚顯示「留言板尚未開放」，說明選伺服器與審核後公開；不顯示假的空列表、不收集暱稱／頭像、不呼叫未完成的雲端業務。此版本僅完成入口與頁面容器，正式列表／投稿／審核仍按後續任務及 G0 門檻執行。

留言板頂部提供伺服器篩選，預設「全部伺服器」，以及「我的留言」入口；底部固定「寫留言」。瀏覽不要求完善個人資料、選伺服器或同意可選的頭像收集；雲端身分不可用時顯示載入失敗，不阻斷其他離線模組。

每則顯示圓形頭像、暱稱、伺服器標籤、投稿時間及正文；超過六行提供「展開全文／收合」。管理員回覆置於下方，顯示固定身分「管理員回覆」及回覆時間，不暴露管理員微信資料。列表按首次公開時間排序，畫面上的時間明確標為「留言於」，避免與排序時間混淆。

提供載入、空列表、分頁中、載入失敗及分頁失敗狀態。分頁失敗保留已載入資料。留言末尾提供「檢舉」，只適用於目前公開留言。

第一版不開放單則留言分享，避免另增已撤回分享連結與詳情頁的存取規則。

### 3.2 寫留言、暱稱及頭像

同一表單完成「伺服器 → 暱稱／頭像 → 正文 → 提交」。伺服器首次不預選，帶入歷史選擇時明確顯示並可更改；查看列表的篩選值不自動變成投稿伺服器。只記住上次成功接收投稿的伺服器。

- 暱稱必填，1–32 個 Unicode code point；支援 `input type="nickname"` 快捷填入微信暱稱，也可手填。不能把暱稱當作實名或微信認證標識。
- 頭像透過 `button open-type="chooseAvatar"` 主動選用；取消或拒絕提供時可使用本地預設頭像，不強制收集真實微信頭像。
- 微信的頭像結果是臨時路徑。預览可用臨時路徑，持久化必須走第 6 節的受控處理。
- 正文必填，1–500 個 Unicode code point。空白留言不接收，不提供富文字、HTML、Markdown、外部連結跳轉或二維碼解析。
- 正規化統一為換行 LF、Unicode NFC 及首尾 trim；保留正文內的換行與正常空格，拒絕無效控制字元及用來偽裝文字方向的控制字元，保留正常 emoji 所需的 ZWJ／變體選擇符。
- 客戶端與服務端共用計數規則；原生 `maxlength` 不得成為唯一校驗或把 surrogate pair 截斷。暱稱只以 form 提交值校驗，不信任失焦前已保存的舊值。
- 提示「審核通過後，留言會公開顯示你的暱稱、頭像及伺服器」，並提供可開啟的隱私指引。
- 已保存的留言資料由雲端載入。選用新資料時保存一個新版本；個人資料包含當前版本指標及不可變內容的歷史版本，安全進度可單獨更新。當前提交以本人的仍有效選定版本建立不可變快照，不能在重試時自動換成最新版本；版本已被清除時返回 profile-version-expired 並要求重新確認。
- 第一版只顯示微信資料選用提示，不提供一鍵自動同步；更換微信資料後需在此重新選用。

暱稱／頭像能力及工具模擬限制依據：[微信官方說明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/userProfile.html)。

### 3.3 隱私與相容性

使用微信現有隱私授權機制，先核驗后台聲明及當前同意狀態，再啟用相應隱私元件。平台隱私同意與表單的公開用途提示分開，不用自訂勾選框假冒平台已授權。

拒絕提供頭像時保持預設圖；拒絕或未完成必需的隱私流程時，保留草稿、允許返回瀏覽，不上傳個人資料。不因進入首頁就彈出留言板授權。需要授權的元件在未同意前不渲染為可觸發的輸入元件。

以已配置的公開基礎庫與能力探測驗收。能力缺失時提供手填暱稱／預設頭像的降級方式；如果整體雲端或必需隱私機制不受支援，明確提示更新微信後投稿，不退回已回收的使用者資料介面。依據：[微信隱私協議開發指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

### 3.4 草稿、提交與結果未確認

草稿保存正文、伺服器 ID、選定資料版本及待确认的 request ID，不保存頭像 base64、微信临時路徑或完整 OpenID。草稿以服務端提供的本小程序作用域 `viewerKey` 分開保存，7 天過期；未確定目前身分時不讀取他人的草稿。不支援離線排隊自動投稿。

一次提交先冻结表單及 request ID，服務端原子接收後立即返回留言 ID、待審核狀態與當前安全檢查進度；圖片檢查不要求使用者在表單等待數十分鐘。顯示「已提交，審核通過後公開」，清除本次正文草稿，但不清除之後新寫的草稿。

提交前，已知 risky／revoked 的選定資料立即要求更換，不建立留言或扣投稿額度；checking／review 資料可進入待審核，不能提前公開。收到首次接收成功才記住伺服器，不能在 timeout 尚未釐清時改寫歷史選擇。

若傳輸超時，保留本次凍結內容與 request ID，顯示「提交結果尚未確認」，提供「確認提交結果」。未釐清前不得改用新 ID 自動再投；作者想寫另一則時保留未確認項目於「我的留言」本機待確認區。結果確認與重試均按第 9 節去重規則執行。

暱稱或頭像後續檢查未通過時，留言進入「未通過」，顯示可理解的原因。不能偷偷改成預設頭像後公开，也不因修改個人資料自動重新審核舊留言；使用者可複製正文另行投稿。

### 3.5 我的留言與資料清除

本人列表按建立時間與 ID 倒序分頁，展示五種留言狀態、安全檢查進度、回覆與給作者的處理原因。系統檢查逾時與管理員尚未審核使用不同文字。

待審核、已公開及已下架留言可撤回，操作前提示「撤回後不再公開，無法恢復」。未通過及已撤回留言仍可查看；不提供原文編輯或撤回復原。重複撤回返回當前已撤回狀態，不能因重試變成錯誤或重建留言。

「留言資料」可更換暱稱、頭像或移除個人頭像，僅影響新留言。旁邊提示「舊留言保留投稿時資料；如需移除，可撤回或清除留言資料」。

「清除我的留言資料」是另外的破壞性操作，明確列出會撤下所有本人公開留言、清除暱稱與頭像及留言正文。服務端先標記作者為清除中，所有公開查詢立即排除該作者，再背景刪除；清除中禁止新投稿及新資料上傳。完成後本人頁面只显示清除结果，不保留旧正文。風控最小資料依第 11 節保留，不對使用者宣稱已刪除全部技術紀錄。

## 4. 管理員與檢舉閉環

管理員工作台位於同一分包，預設「待審核」，可篩選伺服器、留言狀態、安全檢查進度和未處理檢舉。列表及詳情明確展示作者快照及目前檢查依據，不公開內部原因。

管理員可：

- 公開合格的待審核留言，或填写 1–200 字元的對作者可見原因後拒絕。
- 下架已公開留言，必填原因；可重新公開合格的已下架留言，保留首次 `publishedAt`，不藉重新公開把舊留言置頂。
- 新增／修改一則 1–500 字元回覆，或移除回覆。修改候選回覆檢查期間保留舊合格回覆；候選失敗不覆蓋舊回覆。
- 對平台標為 `review` 的內容作額外人工複核，记录結論與理由；平台 `risky`、尚未完成及系統錯誤不得人工強行放行。
- 限制及解除使用者新投稿。限制以留言 ID 找到內部作者，不能由前端任意提供 OpenID。限制不自動删除歷史留言；對仍待審核的受限作者，公開操作拒絕，先解除限制才可公開。
- 處理檢舉，選擇下架或保留并記錄理由。相同檢舉人對同一留言只保留一條，避免重複灌單；檢舉不自動下架。

檢舉使用固定理由「廣告／辱罵／個人資訊／其他」，第一版不收額外文字或圖片，避免另增一條待審核公開內容。作者不能檢舉自己。每人每天最多 20 次，每條公開留言每人最多一次，次數在服務端判定；所有新檢舉須進入可見待辦。

管理員身分採專用 `MESSAGE_BOARD_ADMIN_OPENIDS` 白名單，預設為空時關閉管理能力。可由部署人員確認後填入既有管理員，不自動沿用其他模組角色。新增、移除管理員須更新有效部署配置並核驗，不以本機 storage 或頁面入口維持權限。

每個管理動作附 `expectedRevision` 與 `operationId`，服務端重新驗證管理角色、目標作者、狀態、安全結果及版本。冲突提示重新載入；工作台不能修改玩家原文、伺服器或作者快照。審核原因與回覆是管理員輸入的文字，均以操作管理員的當次身分執行文字檢查。

## 5. 狀態機與安全結果

### 5.1 留言業務狀態

| 狀態                     | 公開                   | 允許轉移                                                                |
| ------------------------ | ---------------------- | ----------------------------------------------------------------------- |
| `pending-review`／待審核 | 否                     | 管理員公開 → published；拒絕或確定違規 → rejected；本人撤回 → withdrawn |
| `published`／已公開      | 是，另須符合公開判定式 | 管理員下架或已用素材撤銷 → hidden；本人撤回 → withdrawn                 |
| `rejected`／未通過       | 否                     | 不恢復；可另行投稿                                                      |
| `withdrawn`／已撤回      | 否                     | 不恢復                                                                  |
| `hidden`／已下架         | 否                     | 本人撤回 → withdrawn；管理員確認合格後重新公開 → published              |

內容快照创建後不可變；`revision` 隨安全結果、審核、撤回、回覆或下架等更新遞增。首次公開時間保持不變，回覆另有時間與版本。清除流程不作為可恢复的第六種業務狀態，以作者清除旗標與最終內容墓碑處理。

公開判定式為：留言狀態已公開，正文／暱稱／頭像均通過安全及必要人工複核，頭像未被撤銷，作者不在清除中。管理員批准必須與所見内容雜湊及版本一致；資料缺欄位、未知安全結果一律不公開。

### 5.2 內容安全狀態

正文、暱稱、頭像、回覆各自保存狀態、內容雜湊、檢查版本、provider trace ID 及結果，不以單一 `passed` 蓋過其他項目。

| 結果              | 意義與處理                                                   |
| ----------------- | ------------------------------------------------------------ |
| `checking`        | 尚未取得有效結果；不可公開                                   |
| `pass`            | 自動檢查通過；留言仍需管理員公開                             |
| `review`          | 平台建議人工複核；記錄額外複核結論，不能偽造成 provider pass |
| `risky`           | 確定風險；本次候選不可公開                                   |
| `retryable-error` | 服務、配額、下载或回調錯誤；依恢復規則重試，不判成使用者違規 |
| `needs-author`    | 原作者近期訪問條件失效，需本人重新開啟並觸發檢查             |

預設頭像視為內建可信素材。曾檢查合格的相同私有作者素材可重用結果，但不能把不同雜湊或不同來源素材當作已通過。素材 `review` 的人工結論可綁定相同 immutable asset；正文及新的暱稱複核仍按各留言快照處理。

任務結果只更新仍匹配的內容與代數。確定 risky 時，待審核留言才轉為未通過，已公開內容改為已下架；已撤回、已清除及其他終止內容不改回任何可公開狀態。回覆候選失敗只丟棄候選，不撤下已合格原留言或舊回覆。

不對已通過原文隨意重新檢查。若後台明確撤銷已用頭像，立即標記素材 revoked，新的公開查詢排除使用該素材的留言，背景將相關公開留言標為已下架；不得只更新個人資料而留下舊違規頭像。

## 6. 頭像處理、可見性與生命周期

採用專案既有的「小程序傳送有界 base64，雲函數上傳」模式，不讓小程序直接 `uploadFile` 或傳入任意 cloudPath／fileID／URL。這是對初稿直接上傳方案的修正。

1. 原生能力取得臨時檔案，按需縮放至最長邊 256px、压縮為 PNG／JPEG。最多三輪，輸出不超过 64 KiB；超出則提示重選或用預設頭像。不得先把大型原圖讀入 base64 再判定大小。
2. 透過專用 runtime 的 `callFunction` 傳送編碼與 operation ID。base64 最多 87,384 個字元，完整 JSON 請求／單次私有預覽回應上限 96 KiB；先驗證字串上限及編碼格式再解碼。此數值是本功能的預算，不是對平台上限的宣稱。
3. 雲端核驗當次身分與素材操作頻率、解碼後大小、圖片簽名及尺寸。實際格式由檔案判定，不信任副檔名與客戶端 metadata。現有簽名／尺寸驗證器不代表完整圖片解碼；損壞檔案還必須被解析／檢查鏈路拒絕，並以測試雲證據驗收。
4. 雲端產生隨機素材 ID、不可變私有檔案路徑與作者歸屬，保存內容 SHA-256、檢查任務及版本。相同操作重試返回同一素材；無法修改他人素材，也不能覆蓋曾公開的位元組。
5. 正文投稿可先引用本人的 checking 素材，仍保持待審核。私有頭像只由授權的本人／管理員取得限大小預覽，runtime 寫入有界本機臨時檔案後顯示，離開或切換身分時清理；不下發私有簽名連結給一般列表。
6. 管理員批准具體留言時，雲端將已檢查且必要人工複核完成的相同素材位元組準備到只讀公開區，再在交易中檢查版本並發布。失敗時留言保持不公開，孤立公開候選由清理任務刪除。只有收到管理員有效批准後才準備公開素材，不能在首次上傳時公開。
7. 公開列表只返回已批准的 cloud fileID，由 image 元件顯示；載入失敗回退本地圖。驗收必須確認 cloud fileID 與既有規則、基礎庫及真機相容，不擅自增加客戶端外部 URL／下載 API。
8. 公開區只允許客戶端讀，私有區拒絕客戶端直接讀寫；上傳、刪除及公開檔案更新只在服務端進行。不能把「沒傳 fileID」當作私有權限，也不能讓作者直接刪掉其他歷史留言引用的頭像。

公開素材準備與資料庫发布不是同一交易：公開候選使用獨立不可猜測路徑，不由客戶端已知 asset ID 推導，不在最終發布前下發；競態造成的無引用副本進入清理工作。這能限制曝光，但不把隨機路徑稱為存取權限，也不宣稱撤回能原子刪除已公開位元組。部署前必须驗證此發布與清理窗口符合產品公開提示。

素材引用包括個人資料版本、仍保留的留言快照及處理中的任務。更新個人資料不直接刪除舊素材；公開副本只在仍有公開留言引用時保留，移除後私有副本按保留規則處理。公開過的位元組不能保證從他人已下载的檔案中撤回。

CloudBase 的客戶端規則與服務端管理权限不同，部署時只為本模組路徑增加規則，保留既有素材及回報截圖權限。依據：[CloudBase 儲存安全規則](https://docs.cloudbase.net/storage/security-rules)。官方建議大資料欄位另作處理，本功能以小型頭像預算避免新增 CDN 呼叫；若實測鏈路不能滿足此預算，先調整設計，不能臨時全域放行。[callFunction 說明](https://developers.weixin.qq.com/miniprogram/dev/wxcloud/reference-sdk-api/functions/Cloud.callFunction.html)

## 7. 微信內容安全與非同步恢復

文字採微信內容安全 2.0：暱稱使用資料場景，留言與回覆使用評論場景；讀取有效的錯誤碼及 `result.suggest`，不能只憑 HTTP 200／函數成功判通過。依據：[文字內容安全官方介面](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck)。

圖片採 `mediaCheckAsync`，2.0、圖片類型及資料場景。由服務端為私有檔案取得只供檢查服務使用的有期限存取連結，不接受客戶端任意 URL；連結保留至少 60 分鐘有效期，配合其 30 分鐘內的非同步結果推送。連結與簽名不可寫入普通日誌。依據：[多媒體內容安全官方介面](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync)。

兩個介面均要求所用 OpenID 最近兩小時訪問過小程序。因此作者內容在作者近期訪問時啟動檢查；管理員稍後審核使用已保存結果。管理員可以重試仍滿足條件的任務，條件失效則標 `needs-author`，本人在我的留言中点击「重新檢查」後由當次服務端身分觸發。不能用管理員 OpenID 冒充原作者重檢，也不能假定相隔數天仍可重試。回覆與處理原因以當次管理員身分檢查。

持久化任務包含目標 ID、內容雜湊、類型、檢查代數、狀態、嘗試次數、下一次時間、租約、trace ID 與最後錯誤。投稿／資料保存交易同時建立任務；交易提交後才發起檢查。定時工作每分鐘領取到期任務，用有期限租約避免同時重複執行；程序崩潰後可接續。

API 接收失敗採有界自動重試，最多三次嘗試，重試延遲 1 分鐘、5 分鐘；檢查已受理而無回調時，在 45 分鐘後標為可恢復錯誤，不在等待期間重複發同一圖片任務。不得把業務函數逾時改成數十分鐘。重新發起檢查取得新代數與 trace ID，舊代數結果不能覆蓋新任務。

需要獨立的微信事件接收 HTTP 入口，支援 URL 校驗及安全模式簽名／解密，核驗 AppID、事件類型、trace ID、任務代數與內容雜湊。所有驗證均在写入前完成；有效事件持久化後即按平台要求應答，由後台完成處理。重複事件去重；结果早於 trace 映射保存时，受驗證事件短期暫存再匹配。未知 trace 不可凭猜测 author ID 匹配留言。

回調 Token、EncodingAESKey 等只保存在受控部署秘密配置，不寫入小程序、Git 或日誌。雲調用權限按所用 API 明確配置，不為方便取得前台 AppSecret。持久化事件失敗時不回 success 假裝已接收；后台處理失敗使用原事件重試。工作隊列另有全局 API 發送預算，低於實際可用平台配額，達到預算時延後排程並在工作台顯示，不把額度不足歸為玩家違規。

不能假定微信原生「雲函數接收消息推送」支援安全檢查事件：當前官方說明僅標示客服消息。方案採經驗證的 HTTP 接收端，且不得覆寫已存在的其他消息推送路由；若已有接收器，需按 Event 分流並驗證相容性。[微信消息推送官方說明](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push)

## 9. 去重、限流、交易與分頁

### 9.1 原子接收與操作去重

所有寫入使用作者作用域／動作／operation ID 定位回執，並綁定正規化 payload hash。相同 ID、相同內容返回既有結果或其最新狀態；相同 ID、不同內容返回 idempotency-conflict，不能修改原請求。跨作者不能讀到對方回執。

建立留言交易同時完成 owner 額度／限制檢查、不可變快照、留言、檢查任務與回執；重試已接收的原操作不再扣額度。交易後失敗的外部檢查由任務恢復，不用刪掉留言假裝未接收。

本人撤回、管理員公開／回覆／下架、解除限制與清除均採版本檢查及操作去重。審核／撤回競爭時只有一個版本更新成功；已撤回不得被舊公開操作復活。素材準備或回覆檢查完成後，仍要再次檢查角色、message revision、作者限制／清除狀態與候選版本才生效。

本機自動確認窗口為 24 小時，回執保留 30 天。operation ID 使用不可改動的時間前綴與至少 128-bit 隨機部分，時間依 getViewer 的服務端基準產生，允許最多兩分鐘的前向時鐘偏差；獨立 createdAt 不得覆蓋 ID 內的時間。服務端先查本人合法回執，命中後返回結果；未命中才檢查 ID 時效，超過 24 小時一律回覆 operation-expired。這使清理回執後相同的舊 ID 仍不能重新創建留言。超出本機窗口只做查詢與本人列表核對，不自動再次建立；不承諾無期限保留原結果。

### 9.2 限流與停用

第一版預設留言間隔 60 秒、每天最多 10 則，成功接收即計入，包括後續未通過／撤回的留言，不退額度；日界以服務端 Asia/Shanghai 計算。投稿入口嘗試、資料更新／頭像上傳及人工觸發檢查共用每人每分鐘 5 次的寫入嘗試預算，命中既有操作回執不再次扣除；資料設定只在明確保存／提交時寫入，不逐字自動保存。去重查詢不耗投稿額度，讀取仍有平台級節流。

檢舉按第 4 節独立計數。定時任務與共享相同素材檢查不重扣玩家額度；同一內容任務只能同時有一個有效租約，防止反覆點擊造成安全 API 風暴。

服務端配置 `readEnabled`、`writeEnabled` 與 `reviewEnabled` 開關；緊急情況可停止新投稿／審核或暫停公開列表，仍允許本人撤回及清除。前端讀取能力後顯示具體提示，API 不因舊前端仍有按鈕而繞過開關。

### 9.3 穩定分頁與撤回刷新

公開列表按 `(publishedAt, messageId)` 降序，每頁 20 則，最上界隨首批固定；游標包含版本、伺服器篩選及上下界，後端驗證其欄位與簽名，不接受任意資料庫查詢。本人與管理列表使用相同規則但按 createdAt；状态篩選改变也要更換游標。

客戶端依留言 ID 去重，以請求代數淘汰過期的載入結果。下架／撤回可令分頁少於 20 則，不能只按回傳數量推測沒有下一頁；服務端返回明确 nextCursor。每頁列表回應亦限制為 96 KiB，達到預算可少於 20 則，游標以最後實際交付的記錄推進，不丟棄未交付項目。後端每次查詢有最多五個候選批次的掃描預算；被清除作者或失效素材全部過濾時，可返回空 items 和已推進的 nextCursor，前端顯示載入更多而不陷入自動無界重試。不把會變動的列表當成固定資料快照，新增、下架或重新公開后的完整性由下拉更新恢復。

公開、本人與管理列表每個畫面窗口最多保留 100 條記錄，不無界累加 setData。窗口內每批最多 20 條；達到窗口上限且有下一游標時顯示「下一段」，切換後釋放舊內容，只保存輕量窗口起始游標，提供「上一段」重新查詢與「回到最新」重置。切換篩選清空窗口歷史。公開頁的每輪重驗因此最多 100 個 ID；長列表驗收須實際覆蓋至少三個窗口，不以首屏截圖代替。

公开正文不持久化到本機 storage。返回前台時重新驗證已載入 ID，前台活躍期間每 60 秒重驗一次，後台取消計時器；本人操作后立即移除本機公開項。已撤回／下架項在下一次成功重驗时移除；網路不可用不声称已同步，顯示「更新失敗，請重試」。同一次舊載入請求已讀到的內容或他人截圖不可收回。

## 10. UI 與易用性

沿用 [Design Foundation](2026-08-09-design-foundation-design.md) 全部 Token。米色頁面、淺色內容面、深綠主要按鈕、黃銅伺服器標籤；以分隔線呈現留言，不堆疊多層卡片。繁體中文文案，伺服器官方名稱作为必要專有名詞保留。

重要操作熱區至少 88rpx，小型操作文字至少 22rpx；所有圖形操作有可讀名稱。狀態同时有文字，禁用提交说明未满足的欄位，不只顯示灰色按鈕。只在真正不可逆的清除／撤回確認使用適當危險提示。

固定底部區處理 safe-area、鍵盤及正文遮擋；聚焦暱稱／正文不跳出可視區；不同寬度允許長伺服器名、emoji 與長連續文字換行。頭像失敗用本地預設圖；空頁引導第一則留言，但不強制授權。

## 11. 資料保留、清理、營運與部署

以下是產品保留策略建議，须與后台隐私指引一致，不宣称属于平台法定天数：

- 本機草稿 7 天過期。私有預覽臨時檔最多保留當前頁面所需，切換身分立即清除。
- 孤立／失敗／被替換且沒有有效引用的頭像，24 小時後清理；處理中素材不提前刪除。
- 未通過或已撤回留言正文保留 30 天供本人查看與故障处理，之后移除正文、作者展示快照及不再引用的素材，只保留到期受控的操作墓碑。
- 待審核留言 30 天仍未處理時轉為未通過，原因「留言超過審核保留期限」，避免无限积壓；不把逾時說成內容違規。
- 公開或已下架留言保存至作者清除或管理員內容清理；已下架內容不對公众返回。
- 清除本人資料先撤下公开内容，24 小時內完成正文、個人資料及可刪除檔案清理；失败重試并显式标示清除仍进行中。與其他公開留言共用的同一作者素材先撤下所有引用再清理。
- 操作回執、有效安全事件与普通風控紀錄有到期清理；回執 30 天，有效未匹配事件 60 分鐘。审计只留动作、操作者內部鍵与版本，預設 90 天，不複製原文。
- 最小限流鍵保留 30 天；仍有效的投稿限制保留至解除，避免清除資料即繞過限制。解除後依 30 天清理，不稱其為不可追溯匿名資料。

清理任务先取得租約并标記刪除中，新引用／新發布不得引用该素材；重新核對有效引用后删除，不依賴容易漂移的单一 refCount。所有工作可重复执行，不能只靠平台自动 TTL 删除数据库行而留下图片。

營運最少包含待審核數、最老待審核時間、逾時安全任務、未處理檢舉、清除失败与孤立素材。管理员进入工作台即可看到；告警不擅自对外发送通知。日誌只記操作碼、request ID、目標隨機 ID、耗時與脱敏錯誤，不記完整 OpenID、正文、暱稱、base64、Token、簽名連結或原始 provider 命中內容。一般 request ID 指排查用的呼叫 ID，不能把使用者或管理員識別拼接進去。

原設計優先使用獨立測試環境；2026-10-06 使用者拒絕新增環境費用，選擇現有付費環境的專用測試資源，執行 [同環境測試調整](../plans/2026-10-06-message-board-shared-environment.md)。第一批只測身分與合成文字，不修改既有消息推送或儲存規則；圖片／事件測試須補齊實際隔離條件。正式業務部署仍須建立集合／索引與私有／公開素材規則，核验微信内容安全权限、接收端校验与后台隐私聲明。不得用 `cloudbaserc.json` 中舊函數的配置推定新函數已经可部署。選擇平台當前支援且與既有 SDK 相容的雲端 runtime；本機 Node 22 門禁不表示雲端 runtime 已確認，也不直接照抄舊 Nodejs16.13 配置。

先让权限、檢查与回調闭环可用，再开启 read／write／review。上线回退先停写與審核，保留用户撤回／清除与持久化任務，不能用回滚删除真实投稿。尚未授权部署时只编写配置／说明与测试方案。

## 12. 倉庫規範及實作前置門檻

建議仅為 `miniprogram/runtime/message-board-service.ts` 放行 `wx.cloud.callFunction`，沿用既有 app 初始化。此版不需要客户端 `uploadFile`、`downloadFile`、`CDN`、資料庫直連或硬編碼遠端 URL。後端 HTTPS 回調、私有檢查連結及服務端檔案操作留在雲端。

`AGENTS.md` 第 2 節採預設禁止與按檔案／API 放行的受控網路邊界。留言板 service 尚未登記於現有白名單；正式實作前應明確授權上述單一服務的 callFunction 範圍，再同步掃描白名單及契約測試，已有明確授權覆蓋時不重複確認。此次規範文字對齊不放行留言板、不修改實際掃描器或雲端權限。

新雲函數建议复用现有 `wx-server-sdk@4.0.2`，不升级已有依賴；新函数清单、回调接收所需部署资源及任何新增包都需在实施计划列明，依 `AGENTS.md` 获得相应确认后才安装或部署。不以新增函数为由顺手更改根依賴。

正式业务编码前先做三项技术可行性门檻，以只读查证和用户授权的测试环境验证：

1. 微信安全檢查权限及近期访问要求可用，HTTP 接收端能接收、验签／解密并落库真实 `wxa_media_check`，不存在覆盖既有路由的问题。
2. 64 KiB 頭像、96 KiB 请求／响应预算能通过真实调用链；私有预览、只读公开 cloud fileID、存储规则及素材清理可闭环。
3. 当前 SDK／部署入口能可靠区分本次小程序、跨账号、HTTP、定时调用，拒绝伪造与实例残留身份；没有未经确认的 SDK 或基础设施升级要求。

三項未验证时标为 not-run／blocked，不把设计视作平台验收。如果任一无法满足，先修订相关方案再实施，不在代码中临时突破边界。

正式编码使用隔离 `codex/phase-N-描述` 分支，先保护既有配置、未追踪文档及必要输入；本次文档仍在原规划分支，不创建或移动用户工作区。静态数据调整遵循红→绿→重构，修改 master 后运行 data:check，再由工具生成。
