# 技能等级、解锁等级与角标显示规范

## 1. 目的与范围

本规范统一《Uncharted Waters Origin》航海士资料查询小程序中，技能等级、技能解锁等级、主动／被动分类和技能图标角标的含义。适用于 `data/master/`、数据生成器、名鉴列表、航海士详情、技能查询、投稿审核以及所有复用技能图标的界面。

`archive/` 仍是只读来源快照；任何来源字段都必须先归一化为本规范定义的 Canonical 语义，不能把来源字段名直接当作界面字段语义。

## 2. Canonical 字段语义

航海士技能关系中的字段必须严格区分：

| 字段 | 唯一含义 | 允许值与规则 |
| --- | --- | --- |
| `skills[].level` | 技能本身的等级 | 正整数的单数字等级；当前游戏资料以 `1`、`2`、`3` 为有效示例。不得写入 `10`、`30`、`50`、`70` 等解锁门槛。 |
| `skills[].unlockLevel` | 该航海士解锁此技能所需的航海士等级 | 必须是正整数，可为多位数；只用于解锁条件、资料说明或其他明确以解锁等级为语义的业务。 |
| `skills[].kind` | 该航海士与技能关系的主动／被动类型 | 只能是经审计确认的 `active` 或 `passive`；不得从名称、图标、槽位或数值臆测。 |

来源中的动态顶层 `skill*` 字段属于 archive-only 原始证据；嵌套 `skill.sk*` 的数值归一化到 `unlockLevel`，`slv.*` 的数值归一化到 `level`。导入、人工录入和审核时必须保持这两个语义分离，遇到 `10/30/50/70` 等解锁门槛值不能因为字段名相近就当作技能等级。

## 3. 技能图标角标

### 3.1 唯一数据来源

所有技能图标右下角角标只能读取同一笔技能关系的 canonical `level`。任何页面、Presenter、压缩索引或共用组件都不得使用 `unlockLevel` 作为角标来源，也不得在 `level` 缺失时回退到 `unlockLevel`。

### 3.2 显示规则

- `level === 1`：不显示角标。
- `level > 1`：显示 `Lv.N`，其中 `N` 必须是 canonical 技能等级。
- `level` 为 `0`、空值、非正值、非单数字或未完成归一化：不显示角标，并保留资料异常供校验或审核处理。
- 角标不显示解锁等级；解锁等级只能在明确标注“解锁”的字段中展示。

压缩运行字段 `skillLevels` 只代表技能等级映射 `skillId → level`。为节省空间可以省略 `Lv.1`，但绝不能把 `unlockLevel` 投影到 `skillLevels`。

## 4. 主动／被动分类

主动／被动的唯一依据是航海士与技能关系上的 `kind`：

- `kind: active` 进入主动技能集合；
- `kind: passive` 进入被动技能集合；
- 未知或冲突的 `kind` 必须进入数据校验／人工复核，不得按技能名称、图标样式、来源分组、槽位或解锁等级猜测。

名鉴列表保留现有布局：主动技能和被动技能之间只使用分隔线区分，不增加可见的“主动技能／被动技能”标题。航海士详情可以使用独立的主动／被动分区，但分区仍必须来自 `kind`。

## 5. 各界面规范

### 5.1 航海士名鉴列表

- 主动和被动图标分别由 `kind` 过滤后渲染，分组之间只显示分隔线。
- 技能图标右下角按第 3 节显示角标；`Lv.1` 不显示。
- 列表的 `+N` 只表示未展开的额外技能数量，不表示技能等级或解锁等级。
- 列表不显示解锁等级，也不得把解锁等级写入图标角标。

### 5.2 航海士详情

- 主动／被动区块由关系 `kind` 生成。
- 图标角标仍只读取 `level`，并遵循 `Lv.1` 隐藏规则。
- “目前 Lv.N”表示技能等级；“Lv.M 解锁”表示航海士解锁等级，两者必须是分开的字段和文案。

### 5.3 技能查询与配队相关界面

- 技能实体查询结果中的技能名称、分类和说明不能替代航海士关系上的 `level`、`unlockLevel` 或 `kind`。
- 若业务需要计算解锁贡献或目标值，必须在字段名、文案和测试中明确写出使用的是 `unlockLevel` 或其他专门的业务值；不得把该值回填到技能图标角标模型。

### 5.4 投稿、审核与资料维护

- 表单、审核页和 Canonical 预览必须分别显示并编辑“技能等级”和“解锁等级”。
- 技能等级录入只接受本规范的单数字技能等级；解锁等级单独校验，不得互相填充。
- 审核主动／被动时必须写入关系 `kind`，不能只保存技能名称或来源槽位。
- 审核页必须把 `kind` 与 `sourceGroup` 作为两个独立字段编辑；修改来源组别不得自动覆盖主动／被动类型。
- 发现来源资料只有解锁门槛、缺少技能等级，或两个字段含义不明确时，状态应标记为待复核，不得用解锁门槛冒充技能等级。

## 6. 本次已确认的新航海士资料

针对新加入的 `詹姆士蘭開斯特`，已根据用户补充的技能名称与同技能资料确认：

## 7. 校验与验收

数据与界面变更至少应验证：

1. 所有用于角标的值来自 `skills[].level` 或其明确的 canonical 投影，不来自 `unlockLevel`。
2. 关系 `level` 出现 `10`、`30`、`50`、`70` 等解锁门槛值时，`data:check` 或人工审核能阻止其发布。
3. `level === 1` 的图标没有角标，`level > 1` 的图标显示对应 `Lv.N`。
4. 主动／被动集合与关系 `kind` 一致，名鉴列表只保留分隔线。
5. 详情页能同时表达技能等级和解锁等级，且两者不会互换。
6. 修改 `data/master/` 后执行 `npm run data:check`，生成数据变更后执行 `npm run generate:check`，最终执行 `npm run verify`。

## 8. 非目标

- 本规范不修改 `archive/` 中的历史快照。
- 本规范不把所有以 `Lv.` 开头的配队目标或舰队累计值改成航海士技能等级；这些业务必须保留自己的字段语义并在界面上明确区分。
- 本规范不允许通过隐藏角标来掩盖未归一化或未经审核的资料异常。
