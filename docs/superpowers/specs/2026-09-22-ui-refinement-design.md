# 真實畫面驅動的 UI 精修

## 已確認方向與邊界

使用者選擇「精緻航海資料館」：延續米色、墨綠、黃銅與本地遊戲素材。首頁保留五個平行功能入口、現有順序和三加二排列，資料回報仍獨立。以微信開發者工具真實畫面作為修改依據，程式碼只用於定位與實作。

遵循既有 Design Foundation、技能角標規範與 HTML 頁面驗收規範。不修改資料、Controller、Solver 或配置保存語義，不新增依賴；不提交 Git，待使用者檢視變更與驗證結果後確認。

## 已取得的畫面證據

基線保存在 `artifacts/miniprogram-review/ui-design-review/report.html`，包含首頁、名冊、兩類配隊、交易品和兌換碼。後續已取得資料回報、人物詳情首尾，以及名冊篩選首尾。

- 冒險配隊統計換成四行；配置摘要與分享按鈕過度突出。
- 戰鬥空位網格與多組容器連續堆疊，技能列表在首屏底部。
- 名冊人物與技能資訊偏密；篩選確認操作隨長表單滾動，底部安全區不足。
- 人物詳情每項技能都有獨立邊框，長列表顯得零碎。
- 交易品分類占據五行；兌換碼禁用原因與底部操作相距過遠。

## 實作設計

1. 首頁：保留五入口，以一致圖標容器、字級、對齊、點按反饋和留白改善品質，不改導航語義。
2. 名冊：增加卡片內部呼吸空間、明確篩選入口；篩選浮層拆成固定標題、獨立滾動條件與固定操作區，保留草稿、清除、取消、套用事件。
3. 配隊：配置摘要回歸普通無陰影卡片，分享縮為次級入口；標題與統計改為穩定兩行。空船位減少高度，已配置船位保留內容高度。模式切換和面板統一內距、邊界與觸控反饋。
4. 人物詳情：同一技能集合使用連續列表，減少重複邊框；名稱、技能等級、解鎖條件仍分開顯示。
5. 交易品：分類保留全部可見，整理排列與列表內距；本輪不增加分類收合邏輯，避免未驗證的新操作。
6. 兌換碼：突出未設定玩家時的下一步，底部禁用原因就近顯示。只查看與輸入測試，不提交兌換。
7. 資料回報：沿用現有結構，必要時只調整欄位間距與邊界；不提交測試回報。

## 驗收基礎修正

已重現「詳情畫面存在但元素等待失敗」。wechatide 適配器改為期限內獨立查詢元素，避免工具內部等待持有轉場前页面。真正缺失繼續失敗，連線錯誤向外傳遞。此修正先執行紅綠回歸測試，再以真實搜尋、點擊、詳情和滾動流程驗證。

最終驗收進一步重現 `page is not on top of page stack`。檢查安裝版 IDE 實作確認：取得當前頁、取得元素及讀取尺寸之間可能發生轉場。等待流程針對這個過期頁錯誤重新查詢，並涵蓋 `Element not found:` 的明確缺失格式；底層命令有時間上限，不吞掉其他連線錯誤。9 項適配器測試通過，完整 9 場景最終驗收通過，補充名冊到詳情流程再次通過。最初連線卡住的全部原因未據此推定。

- 每批修改執行 `devtools:changed --mode iterate`，讀取真實截圖並修正。

- HTML 報告提供改版前後圖片，明確區分已覆蓋與待人工裝置／狀態；不得將模擬器單一寬度宣稱為多裝置通過。
- 未登入、實際資料寫入和多裝置／長文字狀態不能安全自動覆蓋時如實列明。
