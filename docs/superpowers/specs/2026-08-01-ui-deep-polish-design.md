# 小程序 UI 深度美化设计

## 1. 目标

在不改变现有航海士查询核心能力、不引入运行时网络请求、不新增依赖的前提下，对首页、航海士名册、航海士详情和技能快速信息层进行统一美化。

本次改造的视觉目标是“古典航海资料馆”：暖灰羊皮纸、炭黑、黄铜金和低饱和墨绿。界面继续只使用繁体中文。

## 2. 范围

### 2.1 本期包含

- 首页品牌横幅与可扩展功能入口布局。
- 已上线“航海士名鑑”入口的专属功能图标。
- 航海士名册的头像角标、筛选工具栏、列表层级和触控反馈。
- 航海士详情的人物卷宗布局。
- 名册与详情共用的技能底部快速信息层。
- 原站稀有度、头像边框、航海类型和性别图标的本地化。
- 首页原创横幅的生成、裁切、压缩和包体门禁。
- 必要的视觉等级字段、素材清单和确定性构建支持。

### 2.2 本期不包含

- 配队、技能图鉴、船舶图鉴、资讯或活动模块的功能实现。
- 在首页提前展示未上线模块。
- 筛选规则、排序规则、分页规则或技能反查语义的重做。
- 远程图片、网络 API、云开发或运行时素材下载。
- 新增、删除或升级依赖。

## 3. 视觉系统

### 3.1 色彩

- 页面底色：暖灰羊皮纸。
- 主导航与高权重区域：炭黑偏墨绿。
- 强调色：黄铜金。
- 辅助色：低饱和酒红、海军蓝、灰橄榄。
- 未选筛选项使用半透明显示；选中项恢复正常亮度并增加轻微投影，不增加圆点或可见外框。

### 3.2 形状与层级

- 大区块使用低对比边线和轻阴影，不使用高饱和现代卡片风。
- 功能入口使用统一黄铜徽章图标，名称位于图标下方。
- 小图标的透明点击热区大于可见图形，保证实机可点击性。
- 装饰只服务于层级，不使用持续动画、粒子或大面积模糊。

## 4. 首页

### 4.1 信息架构

首页是可扩展的“功能港口”，不是单功能落地页。

- 顶部使用较短的原创大航海场景横幅。
- 横幅下方使用四列功能图标网格。
- 每个入口由徽章图标和繁体中文名称组成。
- 只有已上线功能可见；新增功能随各自版本上线后加入。
- 功能数量增加后，网格自然向下扩展，不改变顶部品牌结构。

### 4.2 首页横幅

横幅使用图像生成能力创作原创画面，不模仿特定在世艺术家，也不复制游戏截图、角色或标志。

画面要求：

- 古典港口、近景帆船、码头灯火与远方城邦。
- 黄昏暖光，主色为墨绿、灰蓝、棕褐和黄铜金。
- 左侧或左上保留稳定的标题安全区。
- 不生成文字、角色面部、现代物件或复杂 UI。
- 构图适合横向裁切，主要船体不能贴近裁切边缘。

### 4.3 功能图标

- 使用统一的黄铜线稿徽章体系。
- 首期只制作并发布“航海士名鑑”图标。
- 后续模块沿用同一网格、描边、角半径和色彩规范。
- 图标优先保留 SVG 主源，运行包使用流水线输出的 PNG。

## 5. 航海士名册

### 5.1 列表

- 采用已确认的紧凑航海日志式列表。
- 单行目标高度约 58px。
- 头像视觉尺寸约 44–46px。
- 姓名、职业、性别和现有技能摘要保持当前信息语义。
- 保留现有分页、图片失败降级、技能点击和详情跳转行为。

### 5.2 头像叠图

- 头像背景使用原站 `uwo_bg_grade_*` 对应视觉等级边框。
- 左上叠加原站 `uwo_icon_grade_*` 稀有度图标。
- 左下叠加原站 `uwo_icon_class_1..3` 航海类型图标。
- 名册中的类型图标视觉尺寸为 12px，左、下各内缩约 2px。
- 稀有度和类型叠图失败时，不影响头像和文字资料显示。

规范稀有度 `rarityId` 与视觉等级不是同一概念。主资料需显式保存每位航海士的 `visualGradeId`，运行时不得根据 S/A/B/C 临时猜测特殊 Grade 6。一次性迁移从只读来源档案中的等级与特殊标记建立该字段，并由数据测试覆盖。

### 5.3 即时筛选工具栏

- 搜索、分类页签、当前分类筛选区和结果列表位于同一页面。
- 点击任一条件后立即更新数量与下方名册。
- 不使用筛选抽屉、草稿状态或“套用”按钮。
- 切换“航海士／技能／语言／职业”时保留已选组合条件。

“航海士”分类的首行筛选压缩为约 50px 高的无框图标工具栏：

- 稀有度：使用裁切后的 `uwo_icon_grade_2..5` 徽记。
- 航海类型：使用 `uwo_icon_class_1..3`，不显示文字。
- 性别：使用 `gender_f.png`、`gender_m.png`，不显示文字。
- 分组间只使用留白和细分隔线。
- 选中项正常亮度并带轻微投影；未选项约 35% 不透明度。
- 不显示选中圆点，不显示胶囊框，不另设已选摘要行。

原始稀有度图为 60×60 透明画布，有效徽记仅约 20×23。筛选工具栏必须按透明像素边界裁切有效区域，再缩放到约 29×29 的视觉尺寸；头像叠图仍使用未裁切原图。

## 6. 航海士详情

- 使用技能优先人物卷宗布局。
- 顶部左侧显示约 96px 的完整头像、稀有度边框、左上稀有度和左下类型叠图。
- 右侧显示姓名、职业、稀有度、类型、性别、国籍和语言摘要。
- 主动技能和被动技能紧跟人物摘要。
- 招募资料放在技能和语言之后。
- 不再把头像拉伸成整屏横幅，避免裁脸、模糊和无效占屏。

## 7. 技能底部快速信息层

名册和详情页共用同一展示组件与视觉规则。

- 点击技能后保留并压暗当前页面，信息层从底部出现。
- 显示技能图标、名称、主动／被动、分类和完整说明。
- 完整显示 Lv.1 至 Lv.10 的等级效果。
- 每个等级独占一行，并重复完整技能效果句子，不合并、不省略、不只显示数值缩写。
- 提供“查看擁有此技能的航海士”入口。
- 点击遮罩或向下关闭后恢复原列表筛选和滚动上下文。

若技能缺少某一级的来源说明，应明确显示“此等級暫無資料”，不得用相邻等级推断。

## 8. 素材与数据流

### 8.1 权威来源

- 新增的 UI 主源文件放在 `data/master/ui-assets/`。
- 原站小图标下载后记录来源 URL、下载日期、SHA-256、宽高和透明像素边界。
- 生成横幅保留一份主源和生成提示词记录。
- `data/master/assets.json` 扩展 UI 素材记录；不得把运行包文件当作权威源。
- `miniprogram/assets/ui/` 由素材流水线生成，禁止手工修改输出。

### 8.2 运行投影

- 运行数据为目录和详情补充本地 `visualGradeId` 或已解析的边框、稀有度与类型图标路径。
- 页面只读取本地路径，不拼接远程 URL。
- 全局小图标位于主包；航海士头像和技能图标继续沿用现有分包策略。
- 运行时禁止使用 `wx.request`、`wx.cloud`、远程 URL 或 Node.js API。

## 9. 性能与包体预算

以下预算为阻止发布的硬约束：

- 首页横幅运行文件：750×320px，JPEG，目标不超过 120KB，硬上限 150KB。
- 功能图标运行文件：96×96px PNG，单个硬上限 12KB。
- 原站稀有度、边框、类型和性别小图标合计硬上限 80KB。
- 本期新增主包视觉素材总量硬上限 250KB。
- 小程序包不保留 2×、3× 或未裁切的大尺寸横幅副本。
- 生成主源可保留高质量版本，但只能位于主资料层，不能进入小程序包。
- 页面不使用持续动画、大面积实时模糊、Canvas 粒子或自动轮播。
- 名册继续批量分页更新，避免一次向 `setData` 发送全部航海士。

素材构建报告必须输出每个文件的尺寸、编码体积、透明边界和总新增体积。任何预算超限均令检查失败。

## 10. 错误与降级

- 首页横幅失败时显示墨绿到羊皮纸的静态渐变，不影响功能入口。
- 功能图标失败时显示统一黄铜线稿占位，不显示 emoji。
- 头像失败继续显示姓名首字占位；稀有度或类型叠图失败不能遮挡头像。
- 无筛选结果时保留当前条件，显示清除筛选入口。
- 技能等级资料缺失时逐级标明暂无资料，不推断数据。
- 单条详情错误不能使整个名册不可用。

## 11. 验证

### 11.1 TDD 范围

- 来源视觉等级到 `visualGradeId` 的迁移。
- UI 素材清单、路径和哈希校验。
- 透明像素边界检测与稀有度徽记裁切。
- 横幅和图标尺寸、格式、体积预算。
- 确定性素材构建与运行路径投影。
- Lv.1–Lv.10 完整等级说明的展示模型。

### 11.2 UI 验证

- 首页四列图标网格在常见微信手机宽度下不溢出。
- 名册筛选工具栏的可见尺寸与点击热区分离验证。
- 名册即时筛选、分页、技能点击和详情跳转回归。
- 头像三层素材顺序：边框、人物、左上稀有度、左下类型。
- 详情头像不拉伸、不裁脸。
- 技能底部信息层可完整滚动查看十级说明。
- Android、iOS 和微信开发者工具至少各完成一次核心路径验证。

### 11.3 提交门禁

实现完成后运行：

```powershell
npm run verify
```

并额外记录新增主包素材总量和微信开发者工具中的主包／分包体积。

## 12. 实施边界

- 开发分支：`codex/phase-4-ui-deep-polish`。
- 不修改旧的只读 `archive/` 快照。
- 不直接修改 `miniprogram/generated/`。
- 不顺手修复无关问题或格式化无关文件。
- 实施阶段先写详细计划，再按 TDD 和页面级验证分批完成。
