# 航海士錯誤回報與線下新增流程設計

## 1. 目標

將現有面向使用者的航海士資料維護功能收斂為「既有資料錯誤回報」，停止讓普通使用者在線上編輯或新增完整航海士資料。每月少於十位的新增航海士改由固定文字模板收集，再由維護者與 Codex 在線下完成查重、欄位映射、主資料寫入及驗證。

## 2. 流程邊界

### 2.1 線上功能

- 使用者登入後才能提交錯誤報告。
- 只能針對名鑑中既有的航海士提交報告，不提供新增航海士入口。
- 使用者可從航海士詳情頁直接回報，也可在資料維護入口先搜尋航海士。
- 使用者可在「我的回報」查看自己的歷史報告、管理員回覆與處理狀態。
- 管理員繼續在小程序內審核，不另建管理後台。

### 2.2 線下功能

- 新增航海士使用本文固定模板，不透過小程序表單。
- 職業、國籍、語言、技能等引用項必須事先存在；若需要新增，先以獨立任務確認並加入主資料，再處理航海士。
- 人工只提供遊戲資料，不填寫 ID、`displayOrder`、`sourceRefs`、`sourceGroup`、`slot`、`visualGradeId` 或 `portraitId` 等內部欄位。
- 所有人手資料修改只寫入 `data/master/`；生成目錄不得手動修改。

## 3. 錯誤報告設計

### 3.1 使用者表單

| 欄位 | 要求 |
| --- | --- |
| 航海士 | 必填；從既有名鑑選擇 |
| 錯誤類型 | 必填；可複選 |
| 錯誤說明 | 必填 |
| 建議的正確內容 | 必填 |
| 來源網址 | 選填 |
| 證據截圖 | 選填；最多三張 |
| 補充說明 | 選填 |

錯誤類型包括：基本資料、技能、技能等級、招募資訊、圖片、文字錯誤及其他。來源網址和截圖均不得成為提交門檻；介面只提示提供來源可加快確認。

### 3.2 狀態流轉

```text
待確認 → 要求補充 → 待確認
待確認 → 已採納 → 已修正
待確認 → 不採納
```

- 「要求補充」允許使用者追加說明、網址或截圖，但不得覆寫原始報告。
- 「已採納」表示錯誤成立，等待正式資料更新。
- 「已修正」只能由管理員設定，並可記錄實際進入的資料版本。
- 「不採納」必須填寫原因。
- 「已修正」與「不採納」報告只讀。
- 管理員每次變更狀態均可留下回覆。

```text
【新增航海士】

名稱：
稀有度：S／A／B／C
航海類型：冒險／交易／戰鬥
職業：
性別：
國籍：

【語言】

1. 語言名稱：
   語言等級：

2. 語言名稱：
   語言等級：

沒有語言請填：無

【技能】

請按照遊戲畫面中的顯示順序填寫。

普通技能填写技能等级和解锁等级；天生效果的技能等级与解锁等级均固定为 Lv.1。

1. 技能名稱：
   技能等級：Lv.
   解鎖等級：

2. 技能名稱：
   技能等級：Lv.
   解鎖等級：

3. 技能名稱：
   技能等級：Lv.
   解鎖等級：

其餘技能按相同格式繼續填寫。

【招募資訊】（全部選填）

招募城市：
前置航海士：
招募條件：
取得方式或備註：

【頭像】（選填）

航海士頭像：
```

模板不收集其他名稱或譯名，也不要求填寫資料來源、來源網址、核對記錄或內部視覺品級。

## 5. 線下處理規則

### 5.1 基本引用

- 將 S／A／B／C 映射至 canonical 稀有度 ID。
- 普通航海士的 `visualGradeId` 由稀有度推導；特殊視覺資料另行確認，不加入日常模板。
- 航海類型、職業、性別、國籍、語言、城市及前置航海士均以名稱查找既有 ID。
- 名稱無法唯一匹配或引用不存在時停止入庫並向使用者確認；不得自行建立新字典項。

### 5.2 技能引用

- 以技能名稱查找既有技能，取得技能 ID、分類與主動／被動類型。
- 航海士技能關係的 `level` 僅取模板中的技能等級；`unlockLevel` 僅取解鎖等級，兩者不得互換。
- 天生效果固定記錄為 `level: 1`、`unlockLevel: 1`；模板、入庫與運行時資料統一表示為 Lv.1，不得填入其他等級。
- 技能圖標角標只使用 `level`；`level === 1` 不顯示，`level > 1` 顯示 `Lv.N`。
- 依模板順序生成槽位，但不得僅憑技能名稱推測有歧義的 `sourceGroup`。
- 現有資料中存在少量同名技能及同一技能跨 `sourceGroup` 的情況，按下列已確認規則處理；只有規則仍無法唯一判斷時才向使用者確認。
- 技能不存在時停止本次航海士入庫；先以獨立任務新增並核驗技能主資料。

#### 同名技能規則

| 技能名稱 | 處理規則 |
| --- | --- |
| 令人不安的資產管理 | 新航海士預設使用 `skill_skill50999925`；兩筆技能分類、效果和等級資訊相同 |
| 艱難的過去 | 新航海士預設使用 `skill_skill509999177`；兩筆技能分類、效果和等級資訊相同 |
| 實現利益 | 新航海士預設使用 `skill_skill50999862`；兩筆技能分類、效果和等級資訊相同 |
| 突擊 | 存在天生被動技能與海戰主動技能兩種不同效果；模板出現此名稱時必須再確認技能描述或參考航海士 |
| 運用 | 存在兩個提督技能 ID，其中一筆有明確的水與糧食消耗降低 30% 描述；只憑名稱和部分解鎖等級不能始終唯一判斷，模板出現此名稱時必須再確認技能描述或參考航海士 |

以上預設只適用於新增航海士引用，不代表自動合併或改寫既有技能主資料。既有重複技能的清理須另開資料稽核任務。

#### 跨來源組別規則

| 技能 | 固定判斷 |
| --- | --- |
| 應急處理 `skill_skill100010` | 按提督技能處理為 `sk4`；既有 G.S 的 `sk1` 關係視為待另案核對的孤立異常 |
| 海盜剿滅 `skill_skillT0097` | 新增引用使用 `sk5`；詹姆士蘭開斯特的 `sk0` 關係視為待另案核對的孤立異常 |
| 織物交易達人 `skill_skillT0032` | 新增引用使用 `sk5`；詹姆士蘭開斯特的 `sk0` 關係視為待另案核對的孤立異常 |
| 防禦力增加 `skill_skill400481` | 解鎖等級為 10 的既有型態使用 `sk0`；解鎖等級為 1 或 50 的海戰主動型態使用 `sk2`；出現其他門檻時再確認 |
| 被動突擊 `skill_skill509998255` | 按天生被動技能處理為 `sk1`；賽西爾·費特曼的 `sk2` 關係視為待另案核對的孤立異常 |

跨來源組別規則只決定新航海士關係的 `sourceGroup`，不在本任務中順手修改既有異常資料。

### 5.3 系統欄位與素材

- 生成穩定且不重複的航海士 ID 與合法 `sourceRefs`。
- 從正式與自訂航海士合併後的全域資料計算 `displayOrder`，並校驗重號；不得讓兩套來源各自分配相同排序值。
- 根據模板技能順序及已確認的來源分組生成 `slot`。
- 未提供頭像時使用既有後備顯示策略；文字不能替代官方頭像素材。
- 提供頭像時，仍須通過既有素材尺寸、格式、雜湊、依賴與發布流程。

### 5.4 入庫與驗證

1. 核對模板必填欄位。
2. 查找同名航海士及所有字典、技能引用。
3. 列出歧義和缺失項，取得確認後再繼續。
4. 修改 `data/master/` 中的唯一權威資料。
5. 執行 `npm run data:check`。
6. 執行資料生成並檢查生成差異。
7. 按變更風險執行相關測試；提交前執行 `npm run verify`。
8. 提交前向使用者展示變更文件、驗證結果及擬用 commit message，等待確認。

## 6. Skill 適用性決策

目前不建立全域個人 Skill。

本流程高度依賴此倉庫的 canonical schema、三層資料架構、UWO 技能語義和專案門禁，屬於專案規範而非跨專案通用技術。將它做成全域 Skill 會增加誤觸發和規則漂移風險。本文作為唯一詳細流程來源；後續可在 `AGENTS.md` 加入簡短路由規則，要求新增航海士時先讀取本文。

實際使用數次後，如反覆出現大量機械操作，再考慮：

- 把可確定性執行的名稱映射、全域排序分配和引用校驗實作為測試覆蓋的工具腳本；
- 把仍需判斷的模板解析與歧義處理建立為倉庫專用 Skill；
- Skill 只編排流程並引用本文，不複製 schema 與規則，避免形成兩套真相來源。

## 7. 不在本設計內

- 直接實作錯誤報告頁面或 CloudBase 資料模型。
- 刪除既有維護或審核程式碼。
- 新增、刪除或升級依賴。
- 建立新職業、國籍、語言、城市或技能資料。
- 修改任何 `archive/` 快照或手動修改 `miniprogram/generated/`。

## 8. 實作驗收記錄

- 普通使用者入口已收斂為「資料錯誤回報」，可從首頁選擇航海士或從航海士詳情帶入。
- 來源網址與最多三張證據截圖均為選填；必填欄位只包含航海士、錯誤類型、錯誤說明與建議的正確內容。
- 「我的回報」提供五種文字狀態、管理員回覆及 `needsInfo` 補充流程；原始回報保持唯讀。
- 管理員工作台只記錄要求補充、採納、不採納與已修正狀態，不直接修改 `data/master/`。
- 舊完整投稿、修改航海士及 canonical 工單頁面已從 `app.json` 正式路由移除，但相關檔案與線下工具暫時保留，未在本次任務刪除。
