# 航海士資料錯誤回報頁 UI 重設計

## 1. 目標

將目前偏向後台表單、區塊感不一致的「資料錯誤回報」頁，重設為克制、統一且接近正式上線品質的航海資料館表單。

本次只調整錯誤回報頁的展示、選擇航海士方式、表單回饋與成功狀態，不改變錯誤回報資料契約、CloudBase 儲存流程、「我的回報」或管理員審核頁。

## 2. 視覺方向

採用已確認的「緊湊單頁表單＋航海士身份卡」方向：

- 整體維持 Design Foundation 的低飽和羊皮紙、深墨綠與黃銅點綴，不增加花俏紋理、動畫或大型裝飾素材。
- 主表單只使用一個紙面容器；欄位之間以分隔線建立層級，避免卡片套卡片。
- 航海士身份卡與表單共用一致的 `surface`、邊界、圓角與間距規則。
- 標題、欄位標籤、輔助文字、輸入控件、Chip 和操作按鈕使用固定層級，不再由每個區域自行決定樣式。
- 頁面唯一主要強調操作為「提交回報」；黃銅色只用於焦點、稀有度細節與次級提示。
- 實機窄屏優先壓縮無效留白；短標籤不擴張為半屏寬按鈕，次級操作不得擠壓主要資料。

## 3. 頁面結構

頁面由上至下分為四部分：

1. 導航與引導區
2. 航海士身份卡
3. 單一回報表單容器
4. 底部提交操作

### 3.1 導航與引導區

- 導航標題使用「資料勘誤」。
- 內容區不再重複顯示「航海資料館勘誤」眉題，只保留一個「回報航海士資料錯誤」標題。
- 輔助文字說明必填項目少、可快速完成，不重複展示流程說明。
- 標題與輔助文字使用完整內容寬度，不與其他操作左右分欄。
- 輔助文字下方提供整行「查看我的回報與處理進度」入口；入口具備淺色背景、描邊和至少 `88rpx` 熱區，不使用懸空的純文字操作。

### 3.2 航海士身份卡

已選擇航海士時顯示：

- 真實航海士頭像；圖片載入失敗時提供姓名首字後備，不使用遠程臨時素材。
- 頭像複用 `buildOfficerVisuals()` 的分層素材：`framePath` 作為稀有度顏色背景／邊框，人物頭像位於其上，`rarityIconPath` 固定覆蓋在左上角。
- 稀有度不得另行使用右下角文字角標，避免與資料頁、詳情頁和配隊頁產生兩套視覺語義。
- 航海士姓名。
- 航海類型、職業、性別。
- 國籍與語言摘要；多語言時顯示主要可讀摘要，不讓身份卡無限制增高。
- 「更換」固定在身份卡右上角，使用輕量文字操作與至少 `88rpx` 熱區；不得作為固定寬度大按鈕占用資料欄寬度。
- 身份卡主體只使用「左側頭像＋右側資料」兩欄；資料欄 `min-width: 0` 並占滿剩餘空間，長姓名、職業和語言可合理換行。

從詳情頁進入時直接帶入身份卡。從首頁進入且尚未選擇時，同一区域顯示統一樣式的「選擇航海士」狀態；選擇完成後原位替換為身份卡，不新增另一層容器。

選擇狀態只顯示一個可直接輸入的搜尋框；輸入後立即列出候選人物，不顯示用途不明的下拉箭頭、重複「航海士」標籤或需要再次展開的結果區。

搜尋需支持姓名、ID 與既有 `searchAliases`，不能只依賴包含 630 名航海士的原生長列表。每個候選項均顯示：

- `80rpx × 80rpx` 航海士頭像，並使用與身份卡相同的稀有度背景、人物頭像、左上角稀有度圖標分層。
- 航海士姓名。
- 「稀有度 · 航海類型 · 職業」摘要。
- 完整整行點擊區；選中後原位替換為身份卡。

候選項不顯示國籍和語言，避免搜尋列表過高。長姓名允許換行，但不得壓縮頭像尺寸。

## 4. 表單設計

### 4.1 容器與欄位

所有表單字段置於單一 `surface` 容器中，字段間使用 `border-subtle` 分隔。字段順序固定：

1. 錯誤類型
2. 錯誤說明
3. 建議的正確內容
4. 來源與截圖

每個字段使用相同結構：左側字段標題，右側顯示「必填／選填／可多選／字符數」等輔助資訊，控件置於下一行。

### 4.2 錯誤類型

- 維持可多選。
- Chip 使用 `64rpx` 緊湊高度、一致水平內距、圓角和邊界。
- 未選狀態為 `surface-muted + border-subtle`；選中狀態為 `ink` 背景與 `surface` 文字。
- 選中狀態除顏色外，保留清楚的文字與實體填充差異。
- Chip 寬度由文字內容決定，左對齊自然換行；不得固定兩列、平均拉伸或讓短標籤占用半屏寬度。

### 4.3 文字輸入

- 「錯誤說明」與「建議的正確內容」使用同尺寸 textarea。
- 最大長度均維持 500 字。
- 右上角顯示即時字符數，例如 `36 / 500`。
- placeholder 使用具體問題提示，不放入技術字段名稱。
- textarea 高度可隨內容或既定最大高度處理，但兩個字段的初始高度一致。

### 4.4 來源與截圖

- 整組為選填，預設收合為整行可點擊入口，主標題使用「補充證據（選填）」、輔助文字使用「來源網址或最多 3 張截圖」，右側顯示「添加」及本地展開指示。
- 收合入口使用完整寬度、清楚邊界和至少 `88rpx` 熱區，不得把標題與「添加」縮成兩段懸空小字。
- 點擊後在原字段內展開，不使用新的卡片或獨立頁面。
- 展開內容包括來源網址輸入框和最多三張證據截圖。
- 已填內容後，收合摘要顯示例如「1 個網址 · 2 張截圖」。
- 移除截圖使用可見文字或具備無障礙名稱的操作，熱區符合規範。
- 收合只改變顯示，不清空已輸入的網址或已選擇的截圖。

## 5. 校驗與狀態回饋

### 5.1 字段校驗

- 初次進入不提前顯示錯誤。
- 點擊提交後，錯誤顯示在對應字段下方，而不是只使用 Toast。
- 頁面捲動到第一個錯誤字段，確保窄屏使用者能立即看到問題。
- 使用者修正字段後即時清除該字段錯誤。
- 必填規則不變：航海士、至少一種錯誤類型、錯誤說明、建議的正確內容。
- 來源網址和截圖為空時不得阻止提交。

### 5.2 提交状态

- 提交操作欄固定在屏幕底部，讓使用者進入頁面後即可知道存在提交操作。
- 操作欄使用頁面底色、上邊界、完整寬度主按鈕與 `env(safe-area-inset-bottom)`；不得縮成左下角小按鈕。
- 表單內容增加與固定操作欄等量的底部留白，最後一個字段不得被遮擋。
- 預設文字為「提交回報」。
- 提交期間禁用重複操作，並顯示「正在提交回報…」可見文字。
- 網路或登入錯誤保留所有已填寫內容，並在表單操作區顯示可理解的錯誤資訊；Toast 可作為補充，但不是唯一資訊來源。
- 成功狀態切換後隱藏固定提交操作欄。

### 5.3 成功状态

提交成功後在目前頁面切換為完成狀態，不立即強制跳轉。完成狀態包含：

- 明確的「回報已提交」文字。
- 服務端返回的回報編號。
- 「查看我的回報」主要後續操作。
- 若頁面從航海士詳情進入，提供「返回航海士詳情」；否則提供「返回名鑑」。

成功狀態不繼續顯示可編輯表單，防止重複提交同一內容。

## 6. 数据与组件边界

- 錯誤回報契約、校驗規則和 CloudBase action 不變。
- 頁面 ViewModel 增加航海士身份展示、字符計數、字段錯誤、證據區展開狀態、提交錯誤與成功結果。
- 航海士身份資訊從既有 runtime 資料取得，不修改 `data/master/` 或 `miniprogram/generated/`。
- Presenter 為搜尋候選與身份卡提供共用航海士資料及 `buildOfficerVisuals()` 視覺路徑。
- 不再複用後台維護用 `entity-search-picker`；本頁使用專用的輕量搜尋結果區，避免後台組件的標題、展開控制和選中列表洩漏到普通使用者流程。
- 不新增依賴、遠程請求或視覺素材。

## 7. 窄屏与可访问性

- 在 320、375、393、430px 宽度验证。
- 身份卡的长姓名、长职业和多语言摘要允许合理换行或省略，不能挤压“更换”热区。
- Chip 自然換行，頁面不得橫向捲動。
- 重要操作热区至少 `88rpx`，操作文字不小于 `22rpx`。
- 錯誤、選中、提交中和成功狀態均包含可見文字，不能只依賴顏色。
- 固定底部提交區包含 `env(safe-area-inset-bottom)`；鍵盤彈出、滾動到首錯及頁面底部時均不得遮擋當前輸入字段。

## 8. 測試與驗收

自動化測試覆蓋：

- 從詳情頁 query 正確帶入航海士身份資訊。
- 從首頁進入時能在單一搜尋框輸入姓名、ID 或別名，並立即顯示候選結果。
- 搜尋候選與身份卡均顯示人物頭像、稀有度背景及左上角稀有度圖標；圖片失敗時顯示文字後備。
- 身份卡「更換」位於右上角且不壓縮長姓名、長職業或語言摘要。
- 錯誤類型多選及字段錯誤即時清除。
- 錯誤類型 Chip 使用內容寬度、`64rpx` 高度並自然換行，不固定兩列。
- 字符计数与 500 字上限。
- 證據區以整行入口展開、收合及保留已填內容。
- 來源和截圖為空仍可提交。
- 提交期间禁止重复提交，失败后保留内容。
- 成功狀態顯示服務端回報編號及正確後續操作。
- 固定底部提交欄、內容避讓、Design Foundation Token、最小熱區、安全區與窄屏無橫向溢出。

微信 DevTools 人工验收覆盖：

- 320／375／393／430px 的整体层级、Chip 换行和文本溢出。
- 有頭像、頭像失敗、稀有度分層、長姓名、長職業、多語言摘要及右上角「更換」。
- 未選擇航海士、搜尋候選頭像、從詳情帶入及搜尋更換航海士。
- 緊湊 Chip、證據整行入口、收合、展開、添加與移除截圖。
- 固定底部提交欄、鍵盤彈出、內容避讓、必填錯誤、網路失敗、提交中與成功完成頁。

## 9. 不在本次范围

- 修改錯誤回報資料模型、狀態機或 Cloud Function 權限規則。
- 新增航海士、技能、语言、国籍、职业或其他主数据。
- 新增图片、字体、图标库或动画框架。
- 刪除舊維護頁面或舊離線工具。
