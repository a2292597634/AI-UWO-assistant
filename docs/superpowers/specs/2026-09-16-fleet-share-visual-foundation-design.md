# 戰鬥與冒險分享長圖視覺底板設計規格

## 目標

在不改變戰鬥配隊與冒險配隊分享圖既有內容布局的前提下，為生成出來的分享長圖建立一套完整、可辨識且可維護的視覺底板。底板需要讓用戶一眼感覺這是一張「航海隊伍分享圖」，而不是一張只有資料卡片的截圖。

本 Change 只處理生成圖片的視覺層：背景、頁首、裝飾線、模式徽記、標語、頁尾與小程序碼的視覺關係。航海士順序、船位語義、主動／被動技能篩選、冒險品質分組、技能累計、圖片高度計算與預覽／保存／分享流程均保持現有規格。

## 已確認的產品方向

- 交付物是 Canvas 生成的分享長圖，不是小程序內的預覽彈層改版。
- 戰鬥與冒險使用同一張海圖底板，不製作兩套大背景。
- 頁首完全透明，標題與模式資訊直接浮在背景圖上，不使用不透明色塊遮住海圖。
- 頁首區域收緊，只保留必要的標題、配置名稱、模式徽記與模式標語。
- 美觀度可在實作與微信 DevTools 驗收時微調，但不得因此改變既有內容布局規格。
- 小程序碼必須使用現有本地真實素材；AI 生成圖不得充當可掃描 QR 碼。
- 本次重新落地必須使用已確認的兩張原始 AI 圖像：`generated-map-bg.png` 作為海圖底板、`generated-nautical-motifs.png` 作為航海裝飾素材；不得以重新繪製的 Canvas 線稿或其他風格素材替換它們。

## 視覺語言

### 核心印象

分享圖的視覺定位是「古典航海資料館中的艦隊檔案」：紙張、海圖等高線、航線、黃銅儀器和低飽和墨色。裝飾集中在邊緣和節點，中心內容保持安靜，避免背景與航海士頭像、技能名稱爭奪注意力。

### Design Foundation 對應

Canvas Renderer 使用 Design Foundation 的同值色彩，不另造一套品牌色：

| 語義 | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#E7DECA` | 分享圖紙張底色 |
| `surface` | `#F5EFE0` | 船區、技能區的內容表面 |
| `ink` | `#26332F` | 頁首文字、頁尾文字陰影、主要分隔 |
| `text-primary` | `#292A26` | 航海士與技能正文 |
| `text-secondary` | `#625947` | 配置名稱、輔助說明 |
| `accent-brass` | `#B99552` | 羅盤、航線、分隔線與焦點 |
| `accent-text` | `#76501A` | 淺色背景上的標語和模式文字 |
| `danger` | `#8B3A3A` | 戰鬥模式的小面積強調，不表達錯誤 |

背景圖在內容區以低透明度繪製，文字與卡片仍遵守正文對比度；不使用黑色漸層遮罩取代真正的層級設計。

## 完整長圖結構

以下結構適用戰鬥與冒險兩種模式，僅資料區內容依既有 View Model 不同：

1. **海圖底層**：先填充 `canvas` 紙色，再以低透明度鋪設海圖紋理；顶部與底部保留較明顯的羅盤、航線或海浪細節，中段降低對比度。
2. **透明頁首**：不填充矩形色塊。標題、配置名稱、模式徽記直接浮在海圖上，使用墨色文字、細黃銅描邊與很輕的紙色文字陰影保證可讀性。
3. **模式標語**：位於頁首下方的短行，不新增內容卡片；用一條短黃銅線或小型航線節點與正文分隔。
4. **既有內容區**：戰鬥沿用船區、6＋5 航海士排列、四欄技能與主動／被動區；冒險沿用 S/A/B/C 分組、四欄航海士與全艦冒險技能累計。只在既有容器外側增加低對比裝飾，不在卡片中插入額外標題或空間。
5. **透明頁尾**：頁尾不再填充整塊深色 `ink` 表面，讓海圖底部海浪與邊框完整可見；左側以淺色文字、紙色陰影和黃銅細線繪製共用標語與入口說明，右側放置實際小程序碼。QR 優先錨定在原始海圖右下金色預留框內，按目前底板九切片映射座標並保留內邊距；頁尾高度不能覆蓋最後一行技能。

### 頁首幾何約束

- 頁首保留一個窄型布局邊界，目標邏輯高度為 `88`，比現有 `100` 的預留高度收緊；不改變正文網格欄數、卡片尺寸或分區高度公式。
- 頁首背景必須是透明；允許使用 Canvas 的文字陰影和 1–2px 黃銅線，但禁止整塊 `fillRect` 或不透明漸層作為標題底板。
- 标题、配置名和模式徽记的实际绘制坐标必须完全位于页首边界内，标语不得挤压第一艘船或第一个品质分组。
- 頁首文字使用繁體中文，不把 `BATTLE`、`ADVENTURE` 等英文作為正式模式標籤；模式標籤使用 `戰鬥` 或 `冒險`。

## 模式變體

兩種模式共用圖片資產、坐標與繪製單元，只由 View Model 的 `mode` 選擇下列差異：

| 項目 | 戰鬥 | 冒險 |
| --- | --- | --- |
| 頁首標題 | `戰鬥配隊記錄` | `冒險配隊記錄` |
| 配置副文案 | 實際配置名稱 | 實際配置名稱 |
| 模式徽記 | 羅盤／艦旗線稿 | 羅盤／海浪線稿 |
| 小面積強調 | `#8B3A3A` 鋼印紅 | `#315451` 海水青綠 |
| 模式標語 | `定航向・統全艦・赴遠洋` | `向未知海域・寫下下一段航跡` |
| 內容輔助線 | 斜向航線節點 | 波紋／星盤節點 |

模式色只用在徽記、短線、標語或小型角標，不改變既有主動／被動技能區的語義色，也不讓色彩成為唯一的模式辨識方式。

## 固定文字與頁尾

正式文字由 Canvas 以繁體中文繪製，避免把文字烘焙在背景圖中造成配置名稱、長文字或字體替換問題：

- 頁首眉題：`遠洋艦隊・航海檔案`
- 戰鬥標題：`戰鬥配隊記錄`
- 冒險標題：`冒險配隊記錄`
- 共用頁尾標語：`一圖收艦・掃碼回到航海日誌`
- QR 輔助說明：`掃描進入小程式首頁`

頁尾 QR 使用現有 `QR_PATH`（`/assets/ui/mini-program-home-code.png`），在原始海圖 `750 × 1125` 的右下預留框內按比例縮放（保留金色邊框可見的安全內距）；若背景素材不可用，才回退到現有布局提供的 QR 矩形。QR 自帶白底，不需要再用黑色頁尾襯底。QR 缺失仍是不可降級錯誤；背景或裝飾素材缺失可以退回紙色底板並記錄降級數量。

## 素材策略與包體積

### AI 生成素材的角色

已確認的兩張 AI 圖像都是本 Change 的正式藝術來源：海圖圖像提供整張背景，航海符號探索板提供羅盤、六分儀、船旗、錨、海浪與星盤。原始高解析檔案不直接放入小程序包；由既有 `sharp` 管線以等比例縮放、保留透明通道並重新編碼後作為運行時素材。不得重新生成同類圖標，也不得用 Canvas 線稿替代已確認的圖像。

### 受控資產流程

新增一個共享底板素材來源與輸出：

- 來源：`data/master/ui-assets/fleet-share-map-source.png`
- 輸出：`miniprogram/assets/ui/fleet-share-map.jpg`
- 生成方式：沿用既有 `sharp` UI 資產流程，裁取低細節的海圖紋理區，縮放到固定寬度後輸出 JPEG；Renderer 以低透明度平鋪或分段繪製，不把整張長圖拉伸變形。
- 輸出尺寸：固定為 `750 × 1125`，保留原始海圖的縱向構圖；分享圖超出此高度時只延展中段，不裁掉頂部羅盤與底部海浪。
- 單檔硬上限：`80 KiB`；加入後 `banner` 資產組與全體 UI 資產總量仍須通過現有預算檢查。
- 確定性：來源、處理參數、解碼像素雜湊與報告納入 `data/audit/ui-asset-build-report.json`，重複生成必須得到相同結果。

另新增一個共享航海裝飾素材輸出：

- 來源：`data/master/ui-assets/fleet-share-nautical-motifs-source.png`（內容必須是已確認的 `generated-nautical-motifs.png` 原圖）
- 輸出：`miniprogram/assets/ui/fleet-share-nautical-motifs.png`
- 生成方式：等比例縮放到固定 `768 × 512`，保留來源的透明通道與圖案像素；Renderer 使用 Canvas 的九參數 `drawImage` 從同一張素材中取用各個圖案，不把深色透明背景當成實體底板。
- 單檔硬上限：`80 KiB`；加入後現有 banner 資產組與全體 UI 資產總量仍須通過預算檢查。
- 確定性：與海圖底板相同，納入像素雜湊、輸出集合與 UI 資產報告。

不新增自訂字體、遠程圖片、網路請求或第三方依賴。Canvas 路徑只可保留作為細線、分隔線或素材缺失時的降級提示；正常渲染時，頁首／頁尾的模式徽記與航海裝飾必須由 `fleet-share-nautical-motifs.png` 提供。

## Renderer 與資料邊界

### Renderer 職責

`miniprogram/runtime/fleet-share-renderer.ts` 新增或整理以下視覺單元：

- `drawShareBackground`：填充紙色、繪製海圖紋理帶與低對比邊緣線；背景缺失時使用紙色降級。
- `drawHeader`：完全透明的窄型頁首，繪製眉題、模式標題、配置名稱、模式徽記和標語，不繪製不透明標題底板。
- `drawModeEmblem`：從 `fleet-share-nautical-motifs.png` 取用原始羅盤、船旗或海浪圖案，依模式調整取用區域、透明度與尺寸；不得在正常路徑重新繪製替代圖標。
- `drawSectionAccent`：在既有船區、品質分組和技能區外側繪製少量黃銅線、航線節點或波紋；不得修改區塊矩形、卡片順序或技能數量。
- `drawMotifDecorations`：使用同一張原始航海裝飾素材，在頁首、內容邊緣與頁尾放置少量羅盤、六分儀、錨、海浪或星盤；只增加視覺層，不新增布局空間。
- `drawFooter`：繪製共用標語、QR 說明和本地 QR；將 QR 映射到原始海圖右下預留框，並維持不覆蓋內容的布局保證。

背景素材與裝飾只接受本地受控路徑。航海士、技能、品質和類型素材仍由既有 View Model 與預載流程提供；Renderer 不讀取 FleetState、不計算技能、不判斷保存狀態。

### 不變的資料與業務邊界

- 不修改 `fleet-share-presenter.ts` 的戰鬥／冒險統計規則。
- 不修改 `fleet-share-layout.ts` 的 6＋5 航海士、四欄技能、品質分組和內容驅動高度邏輯；只調整頁首預留高度到 88，並證明頁尾仍不重疊。
- 不修改配置保存、未保存守衛、Canvas 導出、預覽、保存相冊或分享事件流程。
- 不修改 `archive/`、`data/master/` 的 canonical 航海士／技能資料或任何 `miniprogram/generated/` 輸出。

## 驗收與測試

### 自動化測試

1. **資產流程**：新增 recipe 的固定尺寸、JPEG MIME、單檔與分組預算、解碼像素雜湊、輸出集合和報告確定性測試。
2. **Renderer**：驗證背景在標題和正文前繪製、頁首沒有不透明填充、標題繪製在 88 高度邊界內、模式徽記和標語按 `mode` 切換、QR 仍使用 `QR_PATH` 且缺失時保持 fatal。
3. **布局**：驗證收緊後的頁首不會讓第一個內容區或頁尾與技能卡重疊；戰鬥七船、冒險多品質分組和長技能清單仍完整。
4. **架構契約**：驗證正式文字為繁體中文、沒有 Emoji 作為正式圖標、Renderer 同時引用 `/assets/ui/fleet-share-map.jpg` 與 `/assets/ui/fleet-share-nautical-motifs.png`、沒有遠程背景 URL、沒有 `wx.request`／`wx.cloud`／Node.js Runtime API。

### miniprogram-automator 迭代驗收

修改下列任一文件後，頁面相關變更觸發器必須選中戰鬥與冒險分享場景：

- `miniprogram/runtime/fleet-share-renderer.ts`
- `miniprogram/runtime/fleet-share-layout.ts`
- `miniprogram/assets/ui/fleet-share-map.jpg` 或其受控來源／recipe
- `miniprogram/assets/ui/fleet-share-nautical-motifs.png` 或其受控來源／recipe
- 戰鬥或冒險配隊頁的分享入口、預覽流程文件

迭代模式命令：

```bash
npm run devtools:changed -- --mode iterate
```

每一輪至少檢查：

- 頁首透明，海圖能看見，標題與配置名沒有被背景吞掉；
- 戰鬥和冒險只更換徽記、模式色和標語；
- 第一個船區／品質分組沒有被頁首或標語推擠；
- 頁尾標語和 QR 完整，沒有覆蓋最後一行技能；
- 320px、375px、393px、430px 寬度的預覽沒有新增頁面級橫向溢出。

最終模式命令：

```bash
npm run devtools:changed -- --mode final
```

最終 HTML 報告必須保留修改前／修改後截圖，並明確記錄背景素材降級、QR 缺失、Canvas 導出失敗和開發者工具阻塞等狀態。開發者工具阻塞只能標記為 `blocked`，不能當作視覺通過。

## 非目標

- 不重新設計戰鬥或冒險分享圖的資料布局，不改船位、技能欄數、分組順序或高度模型。
- 不把 AI 圖像中的文字、假 QR 或角色素材直接用於正式分享圖。
- 不把未壓縮的原始 AI 圖標探索板直接放進小程序包；只允許由受控 UI 素材管線生成的縮放透明輸出，不新增其他圖標集、自訂字體或遠程素材。
- 不改小程序內分享預覽彈層的交互與按鈕排版。
- 不改任何業務資料、Presenter、Solver、Controller、配置保存或資料生成流程。

## 完成條件

- 戰鬥和冒險分享長圖使用同一張受控海圖底板，頁首完全透明且高度收緊。
- 標題、配置名稱、模式徽記、標語和頁尾 QR 在微信圖片預覽中可辨識，透明頁尾不遮擋原始海圖底部海浪與核心內容。
- 既有戰鬥／冒險內容布局與技能統計契約全部保持通過。
- AI 海圖與航海裝飾輸出經現有資產流程壓縮並通過單檔、分組和總量預算；運行時實際使用兩個受控輸出，原始高解析圖只存在於來源或設計記錄。
- 定向 Vitest、`npm run verify`、`git diff --check` 和可用的 `miniprogram-automator` 迭代／最終驗收均通過。
- 報告 HTML 能顯示本 Change 的修改時間線、截圖證據、資產降級和最終狀態。
