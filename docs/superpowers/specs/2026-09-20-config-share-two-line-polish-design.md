# 配置／分享双行压缩版视觉重排设计

## 状态

用户已确认本方案：左侧改为两行、套数并入第一行、状态改为有背景的居中胶囊，右侧使用独立透明分享 PNG 与「分享」文字。

## 背景与视觉依据

上一轮 `config-bar--prominent-share` 已将冒险配队与战斗配队统一为纸张外卡，但当前截图仍有三个偏差：

- 左侧配置入口依然显示「我的配置／未命名配置／0 套」三层垂直信息，导致外卡高度偏高；
- 「尚未保存」虽然已有样式宣告，但仍使用 `text` 节点承担容器责任，背景与垂直居中在微信渲染中不稳定；
- 右侧分享票据的图形仍由 WXML/WXSS 节点与连线拼出，没有使用参考图要求的独立分享图片素材。

本次视觉依据为用户提供的完整双手机参考图，以及用户单独提供的「尚未保存」胶囊截图。所有尺寸、对齐和颜色调整都必须通过开发者工具截图复核，不凭空新增视觉元素。

## 目标结构

只调整共享 `config-bar` 的 `prominentShare` 顶部摘要，冒险配队与战斗配队继续使用同一组件、同一变体和同一事件接口。

### 左侧配置入口

突出变体的左侧按钮保留原有 `catchtap="onToggle"`，内部固定为两行：

```text
第一行：我的配置   0 套   [尚未保存]
第二行：未命名配置             >
```

- `我的配置` 与 `N 套` 作为同一组辅助信息，保持同一基线；
- `尚未保存`／`已保存` 使用独立的 `view` 胶囊控件：`surface` 背景、`border-subtle` 边界、pill 圆角、显式 `min-height`，由容器 flex 同时实现水平和垂直居中，内部文字只负责字形渲染；
- 第二行只保留配置名称和展开箭头，名称仍是左侧唯一主文字；
- 配置名称继续单行省略，长名称不得挤压状态胶囊、套数或箭头；
- 配置状态的可见文案、保存逻辑、展开事件和无障碍标签不变。

### 右侧分享按钮

- 分享按钮高度与左侧配置入口完全一致；
- 使用 `miniprogram/assets/ui/share-action-icon.png` 独立透明 PNG；素材由图像生成工具根据用户参考图生成，WXML 不再使用节点和连线拼图；
- 默认状态只显示「分享」；移除「生成分享图」辅助文字；
- 生成中和错误状态仍显示原有「生成中／重試」文案、loading、disabled 和 aria-label；
- 点击只触发既有 `share` 事件，不改变配置展开状态。

## 几何与样式约束

以当前开发者工具基线截图为测量起点，将突出外卡从现有 `248rpx` 压缩为 `144rpx`，内部左右控件从 `216rpx` 压缩为 `120rpx`；页面两处 `config-bar` host 同步使用 `144rpx`，避免 host 高度把下方内容推开。

- 左右控件仍为同一横向布局，分享票据宽度保持上一轮已确认的 `176rpx`；
- 新增或调整的样式只能使用 Design Foundation Token、既有 BEM 类名、`rpx` 几何、透明度和本地纸张素材；
- 不新增渐变、远程资源、滤镜、硬编码品牌色、字体或依赖；
- 保留纸张纹理、外卡圆角和既有按压／焦点反馈；
- 分享 PNG 只包含白色三节点连接图形，不包含按钮背景、文字或远程资源；
- 触控热区仍不低于 `88rpx`。

## 范围边界

允许修改：

- `miniprogram/components/config-bar/index.wxml`
- `miniprogram/components/config-bar/index.wxss`
- `miniprogram/assets/ui/share-action-icon.png`
- 两个页面顶部 `config-bar` host 的高度接线；
- 对应架构、页面和验收场景测试。

禁止修改：

- 船只页签、船位网格、技能、目标、总览和底部导航；
- 配置保存、载入、未保存拦截、分享图生成、Canvas 与预览流程；
- `archive/`、`data/master/`、`miniprogram/generated/`、Cloud Function、依赖和无关未跟踪文件。

## 验收标准

- 冒险和战斗顶部外卡均呈现两行左侧结构，卡片明显低于当前基线；
- 第一行同时显示「我的配置」「N 套」和状态胶囊；
- 状态胶囊的文字水平、垂直居中，背景和圆角接近用户截图；
- 分享按钮与左侧等高，图形在上、单独「分享」文字在下，不再出现「生成分享图」；
- 长配置名、已保存、尚未保存、生成中和错误状态均不溢出；
- 两个页面的下方区域截图像素位置不因本次顶部收缩发生额外移动；
- 相关测试、`git diff --check`、`npm run verify` 和两个 DevTools 分享场景全部通过。
