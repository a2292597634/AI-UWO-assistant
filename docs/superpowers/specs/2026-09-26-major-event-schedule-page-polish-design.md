# 大流行時刻表頁面精簡與首頁圖示一致性設計

## 背景與目標

大流行頁目前以「預測」描述按遊戲週期呈現的時間表，且首頁入口圖示缺少其他入口都有的深色徽章底和黃銅邊框。日期 chips、海域／事件類型篩選和「查下一次」控制也讓頁面內容被推到首屏下方。

本次把功能名稱和畫面說明改為「大流行時刻表」，移除不必要的頁面控制，讓矩陣和日程列表更早進入視野，並讓首頁新入口圖示使用現有功能圖示的徽章語言。遊戲週期、UTC+8 時間計算、矩陣分段、事件排序和目前時段的「可能進行」判定保持原有規則。

本規格只覆蓋先前規格中的使用者可見文案、日期／篩選／下一次控制及首頁入口圖示風格；先前確認的遊戲週期、UTC+8 換算、時段分段和事件顯示規則繼續有效。

## 已確認的設計決策

### 文字與時刻表語義

- 首頁入口、頁面標題和微信導航標題統一為「大流行時刻表」。
- 使用者可見的「預測」文案改為「時刻表」、「日程」、「時段」或「發生時刻」等中性表述；範圍選項改為查看日程範圍，摘要顯示時刻表項目數。
- 矩陣與行程標題、空狀態、詳情標題和無障礙名稱使用一致的日程用語。
- 保留「可能仍在進行」提示，以及城鎮活動、事件預算可能影響實際狀態的短說明；離線頁面不宣稱取得即時事件狀態。
- 不更動既有來源週期、錨點、事件延遲、UTC+8 換算或時間範圍計算。

### 頁面控制與首屏密度

- 保留 24 小時／3 天／7 天範圍切換、時刻矩陣／日程列表切換、六小時分段前後翻頁、事件詳情和上下拉更新。
- 移除矩陣上方的日期 chips；分段箭頭繼續瀏覽所選範圍內的時段。切換範圍時回到第一段，分鐘刷新時保留並限制目前段索引。
- 移除海域與事件類型篩選按鈕及選單；矩陣和列表直接顯示所有符合所選範圍的事件。底層週期查詢介面的通用篩選能力不改動。
- 移除「查下一次」按鈕、結果卡及頁面專用狀態和處理器；事件詳情仍由矩陣或日程列表開啟。
- 頁首最小高度由 `228rpx` 收斂為 `184rpx`，並移除被刪控制項的樣式及多餘區塊間距。範圍切換、視圖切換和分段箭頭維持不小於 `88rpx` 的觸控高度。

### 首頁入口圖示

- 僅重繪 `feature-major-events` 這一枚圖示；保留羅盤與時鐘主題，沿用其他首頁功能圖示的深色方形徽章底、黃銅外框、立體高光和同等實體占用範圍。
- 既有首頁圖示作為畫風參考，不重繪其餘圖示，不改首頁入口布局、順序或路由。
- 更新 `data/master/ui-assets/feature-major-events-source.png` 和素材生成記錄，使用既有 UI Asset Pipeline 產生 `96×96`、16 色、透明外角的運行圖示；輸出須符合現有 `4 KiB` 單檔限制。

## 實作邊界

- 修改首頁入口名稱、大流行頁面 WXML／WXSS／TypeScript、首頁入口素材主源、該素材的生成記錄、對應頁面驗收場景和相關測試。
- 不改 `data/master/major-events.json`、交易資料、排程週期、Domain 計算、交易類別圖示、其他首頁圖示、依賴或遠程資源。
- `miniprogram/assets/ui/feature-major-events.png` 和素材建置報告只由 `npm run assets:ui` 生成，不手動修改。
- 保留設計與行程日期採用的東八區語義，以及詳細事件資料和交易品類別圖示。

## 驗收

- 首頁、微信導航列、頁首、摘要、矩陣、日程列表、空狀態和詳情不再以「預測」稱呼此功能或其欄位。
- WXML 中不再包含日期 chips、海域／事件類型篩選選單或「查下一次」按鈕和結果卡。
- 範圍切換、分段翻頁、矩陣／日程切換、事件詳情和目前時段標示仍可操作；分段索引在分鐘刷新後保留有效位置。
- 首屏矩陣或日程內容提前；320、375、393、430px 視寬下沒有頁面水平溢出、標題裁切或矩陣控制重疊。
- 首頁新圖示與其他入口具有相同徽章結構和視覺占用，素材檢查通過且運行圖示不超過 `4 KiB`。
- 更新頁面驗收場景，不再執行已移除的日期／篩選／下一次操作；最終 HTML 報告含首頁與大流行頁實際截圖。
- 執行 `npm run assets:ui:check`、`npm run data:check`、`npm run check:miniprogram-size`、`npm run verify`、`git diff --check` 和 DevTools 最終驗收。
