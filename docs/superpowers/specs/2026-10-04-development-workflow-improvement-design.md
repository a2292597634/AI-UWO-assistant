# 後續開發流程改進設計

日期：2026-10-04。狀態：已完成規劃，尚未實施。

## 1. 要解決的問題

歷史修復表明，問題常出現在操作對象、處理範圍、非同步時間順序及驗證依據四個邊界。現有規範已具備資料分層、TDD、完整門禁及頁面報告要求；改進重點是讓工具準確執行這些約束，並讓交付結果與實際證據一致。

本設計不把正常需求迭代計為缺陷，不重新開啟已完成的 R01–R26，也不以新增文檔數量衡量改善。

## 3. 目標與完成條件

1. 在昂貴檢查前報出不支援的 Node、缺失輸入與準備方法；預檢不下載、不覆寫、不自動修復環境。
2. `generate:check` 不修改候選工作區；產物與當前輸入相符時，合法的未提交 diff 不導致失敗。
3. 檢查分辨「候選產物漂移」「生成非確定」「輸入在檢查期間改變」「構建失敗」。
4. 頁面圖片攜帶被測來源、實際執行環境、fixture 和場景身份。無法取得的欄位明示未知。
5. 有意的修改前／後版本可以不同；比較條件必須可核對，圖片不能跨場景或跨 fixture 冒用。
6. HTML、JSON、Markdown 與 CLI 對頁面、倉庫門禁及待外部驗收項的陳述一致。
7. 非同步場景以有界條件等待配合原有斷言；連線錯誤仍保留原始分類和整批恢復上限。
8. 一次小型試運行證明上述工具有效；真機、雲端、資料語義等剩餘工作繼續獨立追蹤。

## 4. 三批交付

### A：可靠驗證入口

A1 提供只讀預檢，重用既有素材配方及 CI 素材名單，避免第二套輸入名單。資料及生成任務只檢查其依賴；頁面任務額外列出 DevTools 配置及公共／私有基礎庫差異。服務可連線不代表頁面可測，實際探測仍由頁面工具完成。

A2 重用 `generate.ts` 的暫存構建函式及 `DATA_GENERATION_OUTPUT_PATHS`。連續生成至兩個工具自行建立的暫存目錄，先比較兩次輸出，再比較候選產物。檢查前後核對輸入指紋；發現變動就不給通過結論。第一版從倉庫根目錄執行，不改全套生成器的根路徑接口，不複製不完整的假工作區。

這是候選內容的一致性檢查。CI 問題仍須用包含必要輸入的乾淨 checkout 重現；素材準備只能在該副本依 manifest 校驗進行。

### B：可信頁面證據與結果

B1 每個場景保存來源身份與實際 runtime 探測。保留正式適配器及 SDK 元件作用域路徑；SDK 編譯副本要記錄原始根、執行根及映射。來源檔案 hash、啟動路徑、SDK 回覆是不同證據，不把其中一項當成完整編譯包證明。

基線比較使用頁面、場景 hash、fixture 實作 hash、狀態、實測尺寸、基礎庫及截圖步驟鍵。Git commit 和候選檔案 hash 分別顯示在 before／after，允許不同。舊報告維持可讀，但缺身份的圖片只作歷史參考，不自動稱為可信同條件基線。無基線要列缺口，不能因此跳過修改後驗收。

B2 增加 `page`、`repository`、`external` 三層结果。iterate 中未執行的倉庫門禁顯示 `not-run`；final 必需門禁未完成時不能顯示整體通過。真機、雲端與上傳包採清單逐項顯示，頁面工具不推斷它們通過。只更新本次 run 的報告，保留舊報告原樣。

B3 新增 `waitUntil`，用既有 `queryElement`、`readText`、`currentPagePath` 表達元素消失、文字到位及頁面路徑到位。頁面路徑到位不等於轉場動畫完成；需要動畫／可操作狀態時等待具體 UI 條件並保留操作斷言。

### C：規範、契約及試運行

C1 對齊 AGENTS、CLAUDE、README，建立精簡的現況入口和任務記錄模板。最高約束保留在 AGENTS；頁面驗收細節繼續只由既有頁面規範定義。歷史計畫保留日期與當時結果，現況入口連至最新證據。

C2 把四類歷史根因整理成操作契約與現有回歸測試索引。先核對既有測試，僅對可證明的缺口新增測試或另列修復任務。兩套 fleet 頁面的狀態機抽取、全量資料語義複核、求解器重構不混入本批。

C3 用三種隔離樣例試運行：文檔修改、主資料與工具生成產物一致性、離線 UI 非同步場景。記錄首次可信檢查時間、重複阻塞及補證操作數；不預先承諾改善比例。

## 5. 不包含的工作

- 更換測試框架、DevTools SDK，或新增／升級依賴。
- 改動 `.codex/config.toml`、archive、真實資料分類及使用者既有工作。
- 抽取兩個大型 fleet controller 的共同狀態機。
- 部署雲函數、修改 CloudBase 權限或限流政策、發布素材、上傳小程序。
- 自動提交、合併或推送；每批提交前仍展示範圍、驗證與 message 並等待授權。

## 6. 避免引入新的流程成本

預檢只回答環境及輸入是否就緒；不再發明一套與 `verify` 競爭的門禁。輸出路徑重用既有 registry，素材路徑重用既有配方。身份新增於報告 schema，不另外建立資料庫。條件等待是可選的新場景動作，既有場景保留相容性。

每批的提交材料集中在一份任務記錄：基線／保護範圍、實際修改、失敗證據、通過證據、未覆蓋項。文檔任務只檢查文檔；邏輯工具任務按風險執行相關測試與完整門禁；頁面變更按既有唯一規範補證。
