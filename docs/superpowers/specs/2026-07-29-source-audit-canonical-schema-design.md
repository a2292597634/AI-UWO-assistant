# 来源数据审计与规范数据 Schema 设计

日期：2026-07-29
状态：已完成设计确认，待用户复核书面规格

## 1. 目标

本阶段为 voyage.tw 的一次性导入建立可审计的数据边界和规范数据契约。工作重点是用有限且有代表性的来源样本确认字段、枚举、关系和素材结构，而不是提前执行全量抓取。

本阶段结束时，项目应具备：

- 完整的来源字段清单及每个字段的处置决定。
- 经样本验证的 `sk0` 至 `sk5` 映射规则。
- 航海士、技能、字典、素材和数据集的机器可执行 Schema。
- 能覆盖主要数据形态及错误情况的代表性 fixtures。
- 可重复的 Schema、引用关系和审计覆盖校验设计。
- 可供下一阶段实现一次性导入器的明确输入和输出边界。

## 2. 阶段边界

### 2.1 本阶段包含

- 只读检查少量来源页面、数据入口和素材入口。
- 审计约 8 至 12 名代表性航海士。
- 审计约 15 至 25 个代表性技能。
- 覆盖来源分组 `sk0` 至 `sk5`。
- 下载少量代表性头像和技能图标，用于确认格式、尺寸、哈希、重复和缺失处理。
- 设计字段清单、技能映射、Schema、fixtures 和审计报告格式。
- 设计数据契约校验及其正面、负面测试边界。

### 2.2 本阶段不包含

- 抓取全部航海士或技能。
- 下载全部头像和技能图标。
- 建立正式的全量来源快照。
- 生成或写入 `data/master` 正式主资料。
- 实现完整 voyage.tw 导入器。
- 压缩、转换、重命名或分包全部素材。
- 生成小程序运行时索引、详情分片或查询数据。

完整文字和原始素材快照属于第三阶段“一次性 voyage.tw 导入器”。素材压缩、去重、格式选择和分包属于第四阶段“本地素材流水线和包体实验”。

## 3. 核心原则

### 3.1 双层字段处置

来源样本中观察到的每个字段都必须登记，但不是所有字段都必须进入规范 Schema。每个来源字段必须具有且只能具有以下一种处置结果：

- `canonical`：直接进入规范数据。
- `derived`：通过明确、可测试的规则生成规范字段。
- `archive-only`：只保留在不可变来源档案中。
- `rejected`：明确拒绝，并记录原因。

不得静默丢弃来源字段。未确定处置结果的字段会阻止本阶段通过。

### 3.2 无别名字段

来源数据和航海士规范 Schema 均不设计 `alias` 或 `aliases` 字段。航海士只保存正式繁体中文名称。第一版名称搜索不依赖别名、简称、异体字或自动简繁转换。

如果未来确实需要别名搜索，必须作为独立的数据迁移和 Schema 版本变更处理，不能在本阶段预留未使用字段。

### 3.3 稳定标识

- 航海士、技能、字典项和素材使用项目内部稳定 ID。
- 显示名称、职业、稀有度和来源值变化不得改变内部 ID。
- voyage.tw 的 ID 只作为来源引用，不作为项目内部关系的唯一依据。
- 项目内部关系一律引用稳定 ID，不引用显示名称。

### 3.4 严格而可解释

- Schema 默认禁止未声明字段。
- 字段“缺失”和字段值为 `null` 必须分别定义，不得混用。
- 未知枚举不得按相似名称自动合并。
- 来源到规范数据的每次转换都必须能够说明规则和证据。
- 同一输入、同一映射和同一规则版本必须产生相同结果和相同顺序的报告。

## 4. 审计工作流

```text
有限来源样本
→ 来源字段清单
→ 字段处置决定
→ 枚举和值域清单
→ sk0–sk5 映射审计
→ 规范 Schema
→ 规范 fixtures
→ Schema 与关联校验
→ 审计覆盖报告
```

流程是单向的。来源样本不能直接成为正式主资料；样本必须先经过字段处置、映射和校验。

## 5. 产物与目录职责

建议采用以下目录：

```text
docs/
└─ data-audit/
   ├─ source-field-inventory.md
   ├─ source-enum-inventory.md
   ├─ skill-group-mapping.md
   └─ audit-report-format.md

data/
└─ schema/
   ├─ dataset.schema.json
   ├─ officers.schema.json
   ├─ skills.schema.json
   ├─ dictionaries.schema.json
   └─ assets.schema.json

tests/
├─ fixtures/
│  ├─ source-audit/
│  ├─ canonical/
│  └─ invalid/
└─ data-contract/
```

职责如下：

- `docs/data-audit`：供维护者阅读和审核的字段、枚举、映射及报告规范。
- `data/schema`：机器可执行的 JSON Schema，是数据结构的唯一标准。
- `tests/fixtures/source-audit`：固定的少量来源样本，不自动跟随网站变化。
- `tests/fixtures/canonical`：由来源样本人工确认得到的规范数据样本。
- `tests/fixtures/invalid`：用于证明校验器会拒绝错误数据的最小样本。
- `tests/data-contract`：Schema、引用、覆盖率及确定性测试。

本阶段不创建 `data/master`，以免代表性样本被误认为生产数据。

## 6. 来源字段清单

字段清单至少记录：

- 来源实体类型。
- 来源字段路径和原始名称。
- 字段说明。
- 一个或多个脱敏或固定样本值。
- 观察到的数据类型。
- 是否可能缺失。
- 是否可能为 `null`。
- 观察到的枚举值或值域。
- 目标规范字段。
- 转换规则。
- 处置结果。
- 决策依据。
- 审核状态。

字段按以下业务范围整理。

### 6.1 航海士身份与分类

- 来源 ID。
- 正式繁体中文名称。
- 稀有度。
- 航海类型。
- 性别。
- 职业。
- 国籍。
- 来源显示顺序或原始顺序。

不存在别名字段。

### 6.2 语言

- 语言来源 ID 或名称。
- 熟练度。
- 来源中的语言顺序。

语言被建模为航海士与语言字典项之间的有属性关系，不作为多个固定列保存。

### 6.3 招募

- 招募城市。
- 招募条件。
- 前置航海士。
- 来源备注。

字段审计必须确认来源是单值、多值、自由文本还是结构化引用，然后再决定规范结构；不得仅凭页面显示猜测。

### 6.4 航海士与技能关系

- 来源分组 `sk0` 至 `sk5`。
- 来源槽位或顺序。
- 技能来源 ID。
- 技能等级。
- 解锁等级。
- 主动或被动。
- 技能分类映射依据。

主动或被动属于航海士与技能的关系，不属于技能实体本身。

### 6.5 技能

- 来源 ID。
- 正式繁体中文名称。
- 正式繁体中文说明。
- 技能分类。
- 图标来源。
- 来源引用。

如果来源样本还包含效果数值、等级成长或其他具有业务意义的技能内容，先登记到字段清单，再决定进入规范 Schema、派生或仅留档。

### 6.6 素材

- 素材种类。
- 所属来源实体。
- 来源网址或来源路径。
- 原始文件名。
- MIME 类型或实际格式。
- 宽度和高度。
- 文件大小。
- SHA-256 哈希。
- 是否缺失。
- 是否与其他素材内容重复。

本阶段只对少量样本计算可取得的元数据。未下载样本可以登记网址和观察状态，但不能伪造尺寸或哈希。

### 6.7 公共字典

- 稀有度。
- 航海类型。
- 职业。
- 性别。
- 国籍。
- 语言。
- 城市。
- 技能分类。
- 招募条件类型。

每个来源枚举值必须对应一个稳定字典 ID，或明确标记为未决并阻止阶段通过。

### 6.8 来源与追溯

- 来源站点。
- 来源实体 ID。
- 来源页面或数据文件。
- 样本取得时间。
- 来源文件版本标记或响应版本。
- 样本文件哈希。
- 审计规则版本。

## 7. 代表性样本选择

审计样本为约 8 至 12 名航海士和约 15 至 25 个技能。样本不是随机选择，必须共同覆盖：

- `sk0` 至 `sk5` 的全部来源分组。
- 不同稀有度。
- 不同航海类型、职业和性别。
- 单语言、多语言及不同熟练度。
- 无条件招募、条件招募和前置航海士。
- 多名航海士共享同一技能。
- 相同技能在不同来源关系中的一致属性。
- 正常素材、内容重复素材和缺失素材。
- 可选字段存在和缺失两种情况。
- 名称或说明包含标点、数字或特殊字符的情况。

如果真实样本中没有重复或缺失素材，不为满足覆盖要求而伪造来源事实；对应行为改由 `tests/fixtures/invalid` 中的人工负面样本验证。

样本选择报告必须说明每条覆盖要求由哪些来源记录满足。

## 8. Schema 设计

Schema 使用 JSON Schema Draft 2020-12。所有顶层记录和嵌套对象默认设置 `additionalProperties: false`。

### 8.1 数据集

`dataset.schema.json` 至少定义：

- `schemaVersion`
- `contentVersion`
- `updatedAt`
- `sourceSnapshot`
- `counts.officers`
- `counts.skills`
- `counts.assets`
- `counts.dictionaryItems`

阶段二 fixtures 可以引用明确标记为审计样本的快照标识。正式来源快照标识在第三阶段生成。

### 8.2 航海士

`officers.schema.json` 中每条航海士记录至少定义：

- `id`
- `name`
- `rarityId`
- `typeId`
- `genderId`
- `jobId`
- `nationalityId`
- `languages`
- `skills`
- `recruitment`
- `portraitId`
- `displayOrder`
- `sourceRefs`
- 可选维护备注

不定义 `alias` 或 `aliases`。

`languages` 中每项至少包含：

- `languageId`
- `level`

同一航海士不得重复引用同一语言。

`skills` 中每项至少包含：

- `skillId`
- `kind`
- `sourceGroup`
- `slot`
- `unlockLevel`
- `level`

`kind` 只能是经审计确认的 `active` 或 `passive`。同一航海士的来源分组和槽位组合必须唯一。

`recruitment` 至少表达：

- `cityIds`
- `requirementId`
- `requiredOfficerIds`
- `note`

字段审计若证明来源允许多个独立条件，Schema 必须在本阶段调整为明确的条件列表，不能把多个条件压进自由文本。

### 8.3 技能

`skills.schema.json` 中每条技能记录至少定义：

- `id`
- `name`
- `categoryId`
- `description`
- `iconId`
- `sourceRefs`

技能实体不定义主动或被动字段。相同技能由稳定 ID 去重；名称相同但来源 ID、说明或效果不同的情况必须进入人工复核，不能仅按名称自动合并。

### 8.4 字典

`dictionaries.schema.json` 至少定义以下集合：

- `rarities`
- `officerTypes`
- `jobs`
- `genders`
- `nationalities`
- `languages`
- `cities`
- `skillCategories`
- `recruitmentRequirements`

所有字典项至少包含：

- `id`
- `name`
- `displayOrder`
- `sourceRefs`

稀有度另外包含 `sortWeight`。

### 8.5 素材

`assets.schema.json` 中每条素材记录至少定义：

- `id`
- `kind`
- `ownerType`
- `ownerId`
- `source`
- `output`

`source` 至少能够表达：

- 来源网址或路径。
- 原始文件名。
- 格式。
- 宽高。
- 文件大小。
- SHA-256。

`output` 用于第四阶段生成的本地素材，至少能够表达：

- 小程序路径。
- 输出格式。
- 宽高。
- 文件大小。
- SHA-256。
- 处理规则版本。
- 分片 ID。

阶段二的规范素材 fixture 只使用实际下载并完成元数据确认的少量样本。未下载素材只存在于来源审计记录，不伪装成完整规范素材。

## 9. `sk0` 至 `sk5` 映射审计

技能映射表至少包含：

- `sourceGroup`
- 来源技能分类。
- 观察到的来源槽位。
- 规范 `kind`。
- 规范 `categoryId`。
- 代表性来源记录。
- 判断证据。
- 审核状态。

映射必须来自来源结构、游戏内显示和代表性记录的共同证据，不能只根据技能名称猜测。

以下情况阻止本阶段通过：

- 某个观察到的 `sk0` 至 `sk5` 分组没有映射。
- 同一来源分组和分类组合被映射到不同 `kind`。
- 同一技能在不同航海士关系中出现无法解释的主动或被动冲突。
- 来源分组与技能分类之间存在未决歧义。

## 10. 错误与报告

所有发现使用稳定错误码，并至少记录：

- 严重程度。
- 错误码。
- 来源实体和来源 ID。
- 字段路径。
- 观察值。
- 说明。
- 建议处理。
- 当前处置状态。

### 10.1 阻断错误

- 来源字段没有处置结果。
- `sk0` 至 `sk5` 存在未确认或矛盾映射。
- 未知枚举值。
- 重复稳定 ID。
- 缺失内部引用。
- 必填字段缺失。
- 非法的主动或被动值。
- 同一技能被错误拆分或错误合并。
- 素材无法对应所属实体。
- Schema 不通过。

### 10.2 警告

- 可选说明或备注缺失。
- 样本图片尚未取得尺寸或哈希。
- 来源格式不一致但业务含义已确认。
- 当前样本没有覆盖某个非阻断边界情况。

警告不得被静默忽略，必须出现在审计报告中。

## 11. 测试设计

### 11.1 正面 fixtures

正面 fixtures 必须证明：

- 所有规范记录通过对应 Schema。
- 航海士引用的字典、技能、航海士和素材均存在。
- `sk0` 至 `sk5` 覆盖要求得到满足。
- 共享技能不会被重复建立。
- 语言、技能和招募关系可以无损表达样本事实。

### 11.2 负面 fixtures

每种阻断错误至少有一个最小负面 fixture：

- 未声明字段。
- 未知枚举。
- 重复 ID。
- 断裂引用。
- 重复语言关系。
- 重复技能槽位。
- 非法 `sourceGroup`。
- 未映射技能关系。
- 主动或被动冲突。
- 缺失必填字段。
- 素材所属实体不存在。

### 11.3 审计覆盖测试

测试必须证明：

- 每个观察到的来源字段都有处置结果。
- 每个 `canonical` 或 `derived` 字段都有目标规范字段和转换规则。
- 每个观察到的来源枚举值都有稳定字典 ID。
- 每个观察到的 `sk0` 至 `sk5` 组合都有审核完成的映射。
- 每项样本覆盖要求都有对应来源记录。

### 11.4 确定性

相同 fixtures、映射表和规则版本重复运行必须产生：

- 相同校验结果。
- 相同错误码。
- 相同报告顺序。
- 相同规范数据序列化结果。

## 12. 完成标准

本阶段只有在以下条件全部满足时才完成：

- 字段清单包含所有样本中观察到的字段。
- 每个来源字段均标记为 `canonical`、`derived`、`archive-only` 或 `rejected`。
- 所有观察到的来源枚举均已映射或明确阻断。
- `sk0` 至 `sk5` 没有未决映射。
- 五类 Schema 已建立并通过代表性 fixtures。
- 正面和负面数据契约测试通过。
- 代表性素材样本具有真实、可核对的元数据。
- 审计报告能够稳定重现。
- 没有抓取全量数据或全量素材。
- `data/master` 尚未被样本污染。

## 13. 后续阶段接口

第三阶段的一次性导入器只允许消费：

- 本阶段确认的来源字段清单。
- 已审核的枚举映射。
- 已审核的 `sk0` 至 `sk5` 映射。
- 已发布的规范 Schema。
- 已通过测试的错误码和报告格式。

第三阶段遇到本阶段未观察到的新字段、新枚举或新技能组合时必须停止导入并重新审计，不能自动猜测或静默丢弃。
