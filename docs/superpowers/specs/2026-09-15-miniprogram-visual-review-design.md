# 小程序 AI 自主页面验收设计

## 1. 目标

建立一套以 `miniprogram-automator` 为底层执行引擎的本地验收系统，使 AI 能根据文字需求和仓库 Design Foundation 自主完成页面实现、运行、交互、截图、检查和修正。用户原则上只进行最终核验；仅在微信登录失效、授权弹窗或真机扫码等安全边界出现时介入。

## 2. 范围

第一阶段交付可靠、可重复的基础闭环：

- 自动发现或显式配置 Windows 微信开发者工具 CLI。
- 检查开发者工具登录、服务端口、自动化端口和项目路径。
- 通过 `miniprogram-automator` 启动或连接小程序自动化会话。
- 用声明式场景执行页面跳转、点击、输入、清空、滚动、等待、断言和截图。
- 输出机器可读的 JSON 报告及便于人工核验的 Markdown 报告。
- 为一个现有页面提供真实示范场景。
- 使用 Vitest 覆盖配置解析、场景校验、步骤调度、错误报告和确定性输出。
- 提供 AI 可直接遵循的本地使用说明。

第一阶段不实现通用视觉评分模型、不接入第三方 MCP Server、不自动绕过微信登录或授权，也不要求一次覆盖仓库全部页面。更深入的布局检测和全页面场景库在基础闭环稳定后分阶段建设。

## 3. 总体流程

```text
文字需求 + Design Foundation
            ↓
       AI 实现页面
            ↓
微信开发者工具编译并运行项目
            ↓
miniprogram-automator 进入页面并执行交互
            ↓
结构断言 + 控制台信息 + 页面截图
            ↓
确定性规则检查 + AI 视觉审查
            ↓
     AI 修改并重复验收
            ↓
   最终报告与关键截图交给用户
```

`miniprogram-automator` 只承担连接和操作运行中小程序的职责。场景管理、状态覆盖、规则判断、报告生成以及 AI 视觉判断均由仓库内验收系统提供。

## 4. 架构与边界

### 4.1 开发者工具连接层

连接层负责：

- 从环境变量、常见 Windows 安装位置和显式命令行参数解析 CLI 路径。
- 校验 `project.config.json` 所在的项目目录。
- 检查端口格式和占用情况。
- 启动自动化会话，或连接已经开放的 WebSocket 自动化端点。
- 将未登录、服务端口未开启、CLI 不存在、端口冲突和连接超时转换为可操作的繁体中文错误。

敏感或机器相关配置不得提交 Git。支持以下环境变量：

- `WECHAT_DEVTOOLS_CLI`：开发者工具 CLI 绝对路径。
- `WECHAT_DEVTOOLS_SERVICE_PORT`：开发者工具服务端口。
- `WECHAT_AUTOMATION_PORT`：自动化 WebSocket 端口，默认 `9420`。
- `WECHAT_AUTOMATION_WS_ENDPOINT`：连接已有会话时的完整端点。

### 4.2 场景执行层

场景由版本化 JSON 文件描述，并在运行前做严格校验。每个场景包含名称、入口页面、数据状态、设备配置及有序步骤。

第一阶段动作集合：

- `navigate`：使用路由打开非 Tab 页面。
- `switchTab`：切换 Tab 页面。
- `tap`：点击指定元素。
- `input`：向输入元素写入文本。
- `clearInput`：清空输入元素。
- `scrollPage`：滚动页面。
- `scrollElement`：滚动指定容器。
- `waitFor`：等待元素出现或等待明确的短时长。
- `assertExists`：断言元素存在或不存在。
- `assertVisible`：断言元素可见。
- `assertText`：断言元素文本满足精确值或包含关系。
- `screenshot`：保存命名截图。

选择器找不到、元素不可操作、等待超时或断言失败时，执行器立即保存失败现场截图，记录当前页面与失败步骤，并以非零退出码结束。场景不得包含任意 JavaScript 执行，以避免测试文件成为绕过运行时约束的入口。

### 4.3 页面状态层

新页面默认考虑五类状态：

- 正常数据。
- 空状态。
- 加载中。
- 错误状态。
- 极端长文本。

状态应通过确定性的测试夹具或页面现有的可控输入产生，不依赖实时远程数据，也不得为了自动化在生产包中加入可被普通用户触发的调试后门。页面确实不存在某一状态时，场景元数据必须记录豁免原因；报告不得把豁免记为已覆盖。

### 4.4 视觉检查层

视觉检查分为两部分：

1. 确定性检查：页面或关键元素越界、意外横向滚动、必需元素缺失、不可见、文字不符和交互失败。
2. AI 视觉审查：对照 `docs/superpowers/specs/2026-08-09-design-foundation-design.md` 检查信息层级、留白、颜色语义、按钮可发现性、信息密度、长文本表现和整体一致性。

截图不能单独证明交互正确，结构断言也不能单独证明视觉质量。完整验收必须同时保留交互结果、确定性断言和截图证据。

### 4.5 多设备覆盖

默认设备矩阵为：

- 小屏 iPhone。
- 标准 iPhone。
- 安卓大屏。

实现阶段先探测当前开发者工具及自动化接口能够可靠控制的设备参数。只有真实执行成功的设备才能标记为已覆盖；无法自动切换时，系统提供明确的半自动切换提示，并在报告中将其列为待人工核验，禁止虚报覆盖。

### 4.6 报告与产物

每次运行建立独立目录：

```text
artifacts/miniprogram-review/<run-id>/
├── report.json
├── report.md
├── console.log
├── iphone-small/
├── iphone-standard/
└── android-large/
```

报告至少包含：

- 运行编号、时间、Git commit 和工作区是否有未提交修改。
- 场景、页面、数据状态和实际设备覆盖。
- 每个步骤的开始时间、结果、耗时和错误。
- 截图的绝对路径。
- 自动检查发现的问题。
- AI 修正轮次及最终状态。
- 豁免项、未覆盖项和必须人工核验项。

`artifacts/miniprogram-review/` 默认加入 `.gitignore`，不得提交登录二维码、用户数据或包含秘密的截图。

## 5. 命令接口

第一阶段提供以下入口：

```powershell
npm run devtools:doctor
npm run devtools:start
npm run devtools:inspect -- --page /pages/catalog/index
npm run devtools:run -- --scenario catalog-search
npm run devtools:review -- --page /pages/catalog/index
```

- `devtools:doctor`：只读诊断本机环境和配置。
- `devtools:start`：启动或连接自动化会话。
- `devtools:inspect`：打开单一页面，输出页面信息并截图。
- `devtools:run`：执行一个已保存场景。
- `devtools:review`：运行页面对应的全部状态和设备场景，生成汇总报告。

所有命令成功时退出码为 `0`，配置错误、连接失败、步骤失败或断言失败时退出码非零，便于 AI 和 CI 判断结果。

## 6. 测试策略

必须遵循红—绿—重构循环，优先测试不依赖微信开发者工具的确定性逻辑：

- CLI 路径和端口配置优先级。
- 场景 Schema 与非法动作拒绝。
- 每种动作到自动化适配器接口的调度。
- 超时、缺失元素和断言失败的错误结构。
- 报告字段、目录命名和排序的确定性。
- 敏感配置及截图目录不进入 Git。

真实微信开发者工具连接测试作为本机验收，由 `devtools:doctor` 和一个示范场景完成。普通 `npm test` 不应因开发者工具未安装、未登录或未启动而失败。

最终提交前运行完整门禁：

```powershell
npm run verify
```

## 7. 安全与仓库约束

- 自动化依赖只能存在于开发工具链，不得进入 `miniprogram/` 运行时代码。
- 不修改 `archive/`；数据修改仍只能发生在 `data/master/`。
- 不在运行时代码中加入 `wx.request`、`wx.cloud`、远程 URL 或 Node.js API。
- 不绕过微信登录、授权或扫码确认。
- 自动化端口只监听本机，不暴露公网。
- 除已确认的 `miniprogram-automator` 外，不新增、删除或升级其他依赖。
- 不顺手修复与自动验收系统无关的问题。

## 8. 完成标准

第一阶段完成时必须满足：

1. AI 能用单条命令诊断并连接本机微信开发者工具。
2. AI 能打开示范页面，完成至少一次输入、点击、滚动、断言和截图。
3. 任一步骤失败时能自动保存现场并给出明确原因。
4. 运行结束后生成 JSON 与 Markdown 报告，且截图路径可由 AI 直接读取。
5. 无开发者工具时，单元测试和仓库普通质量检查仍可运行。
6. 报告准确区分已覆盖、豁免和待人工核验项目。
7. 完整 `npm run verify` 通过。
