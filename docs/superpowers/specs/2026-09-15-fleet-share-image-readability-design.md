# 配隊分享圖可讀性優化設計規格

## 目標

優化戰鬥配隊與冒險配隊分享長圖在微信聊天預覽中的可讀性。現有分享圖把戰鬥頁 11 個航海士壓在同一列，技能固定五欄，導致頭像、圖標、技能名稱和累計等級過小；空船也佔用大量長圖高度。

本次變更只調整分享圖的 View Model 篩選、Canvas 布局與繪製尺寸，不改變配隊資料、技能統計規則、保存流程、預覽流程或資料三層架構。

## 已確認的用戶需求

- 戰鬥分享圖中的 11 個位置改為「6＋5」兩列，放大單格內的航海士素材與文字。
- 技能卡改為四欄，放大技能圖標、技能名稱和 `Lv.N` 累計膠囊。
- 完全沒有有效航海士的船不在分享圖中顯示。
- 有部分空位的船仍保留空位，維持 11 個位置的語義和船內位置順序。
- 如果整支戰鬥艦隊都沒有有效航海士，分享圖顯示「尚未配置航海士」空狀態，仍保留頁首、頁尾和小程序碼。

## 設計範圍

### 1. 分享資料篩選

`buildBattleFleetShareViewModel` 在建立每艘船的 11 個位置後，移除所有位置均為空的船。有效航海士指能從目前頁面資料中解析出完整航海士資料的項目；未知 ID 不會產生佔位船。

篩選只作用於分享 View Model：

- 保留剩餘船隻的原始 `shipId`、船號文字和順序。
- 船內仍輸出固定 11 個位置，已配置航海士與空位的位置不重新壓縮。
- 技能累計仍以原有 canonical `level` 和 `kind` 規則計算。
- 冒險分享圖沿用現有按品質分組規則，不新增空船區塊。

### 2. 分享圖布局

維持 750px 邏輯寬度和現有 Canvas 安全尺寸策略，將可讀性主要交給信息密度和繪製尺寸改善。

戰鬥頁：

- 航海士欄位使用六欄；11 個位置按索引排列為第一列 0–5、第二列 6–10。
- 航海士單格高度、頭像框、品質徽章、類型圖標和姓名字級同步增加。
- 第二列未使用的第 12 格不繪製額外卡片，避免產生誤導性空位。
- 船標題、航海士區和技能區之間維持固定間距，並依航海士兩列高度重新計算船區高度。
- 完全沒有分享船隻時，在頁首下方繪製一個明確的空狀態區塊。

冒險頁：

- S、A、B、C 分組順序和內容不變。
- 分組航海士使用四欄布局，讓品質分組中的頭像、品質徽章、類型圖標和姓名比原五欄更易辨識。

技能區：

- 所有技能區使用四欄布局，卡片寬度由內容寬度計算，不再被原五欄固定寬度壓縮。
- 卡片保留「上排圖標與累計等級、下排技能名稱」結構，避免名稱和等級重疊。
- 技能名稱仍維持單行省略，保護每張卡片高度一致；增加寬度後減少不必要的省略。
- 頁首、分區標題、輔助文字與頁尾文字同步增加到適合分享圖閱讀的尺寸。
- 小程序碼保留獨立留白區，尺寸同步增加；若高度達到平台限制，沿用現有統一倍率縮放，不裁切內容。

### 3. 繪製與素材

Renderer 仍先預載素材，再設置 Canvas bitmap 尺寸並依邏輯坐標繪製。新增布局信息只由 `fleet-share-layout.ts` 提供，Renderer 不讀取業務狀態。

- 航海士品質背景先於頭像繪製，品質徽章和類型圖標仍錨定在實際頭像框內。
- 放大素材時保持 `contain`／裁切行為不變，避免圖標變形。
- 素材失敗、QR 缺失、Canvas 初始化、導出和預覽錯誤沿用現有錯誤語義。
- 不新增遠程資產、網路請求、字體、依賴或新的正式圖標素材。

### 4. 空狀態與高度安全

布局結果增加可選的 `emptyState` 矩形。戰鬥分享圖沒有可繪製船隻時，內容區仍有固定高度的空狀態，頁尾從空狀態之後開始；有船隻時不保留空狀態空間。所有內容底部位置由布局測量結果推導，頁尾和 QR 不得覆蓋任何船區、技能卡或空狀態。

## 數據流

```text
FleetState + canonical 航海士／技能
        ↓
fleet-share-presenter（過濾空船，保留 11 槽和統計規則）
        ↓
fleet-share-layout（6＋5 航海士、4 欄技能、內容驅動高度）
        ↓
fleet-share-renderer（放大素材與文字、繪製空狀態、頁尾 QR）
        ↓
Canvas 2D → wx.canvasToTempFilePath → 預覽／保存／分享
```

## 測試與驗收

### 自動化測試

- Presenter：全空船被移除；部分空位仍保持固定 11 槽；船隻順序和技能統計不變。
- Layout：戰鬥 11 槽座標分成 6＋5 兩列；冒險分組使用四欄；技能行數按四欄計算；空狀態與頁尾不重疊。
- Renderer：航海士與技能視覺矩形符合放大後尺寸；技能卡的圖標、等級和名稱仍不重疊；既有素材降級和 QR 缺失測試保持通過。
- 架構：分享圖仍使用本地 QR、離線素材邊界和繁體中文文字，不新增 Runtime 網路 API。

### 微信 DevTools／真機

- 一艘有航海士、其餘船全空：只顯示有航海士的船，且航海士圖標和技能文字在預覽中可辨識。
- 多艘有航海士：每艘船按 6＋5 排列，部分空位不會錯位，船號順序正確。
- 冒險 S／A／B／C 多行分組：四欄分組和四欄技能不裁切，QR 與頁尾完整。
- 全空戰鬥艦隊：顯示空狀態，不生成只有頁首／頁尾的空白內容。
- 在 320px、375px、393px、430px 寬設備查看分享預覽，確認無新增頁面級橫向溢出。

## 非目標

- 不改變戰鬥主動技能 TOP 5、被動技能篩選或冒險技能累計規則。
- 不修改配置保存、未保存守衛、Canvas 導出 API、預覽操作或相冊權限流程。
- 不修改 `archive/`、`data/master/`、`miniprogram/generated/`、Cloud Function 或素材 canonical 資料。
- 不新增依賴、自訂字體、遠程圖片生成或分享圖匯入能力。

## 完成條件

- 分享圖在正常微信圖片預覽尺寸下，航海士圖標、技能圖標、技能名稱和累計等級比目前版本清楚可辨。
- 完全空船不再佔用分享圖高度，部分空位仍保持位置語義。
- 相關 Vitest、`npm run verify`、`git diff --check` 和可用的 DevTools 驗收通過。
