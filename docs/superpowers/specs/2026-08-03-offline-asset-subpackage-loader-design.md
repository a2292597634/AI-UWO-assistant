# 離線素材分包載入設計

## 背景與問題

名冊頁位於主包 `pages/catalog/index`，人物頭像和技能圖示位於 `subpkg-a0` 至 `subpkg-a9` 十個普通分包。生成資料使用 `/subpkg-aN/imgs/*.png` 路徑引用這些素材。

微信開發者工具的工作區預覽可以直接讀取本地檔案，但真機進入測試版時，主包頁面不會因為 `<image>` 的 `src` 路徑而可靠地下載所有素材分包，因此圖片載入失敗。現有頭像錯誤處理會顯示人物首字，技能圖示沒有錯誤占位，所以會顯示空白。

依賴分析已確認十個素材分包均已進入發布包，總素材約 7.4 MB；主包目前約 1.66 MB。問題是運行時分包可用性，不是素材缺檔或資料生成錯誤。

## 約束與非目標

- 必須保持完全離線；運行時不得使用 CDN、雲端圖片、遠程 URL 或網絡請求。
- 不新增、刪除或升級依賴。
- 不修改 `data/master/`、`miniprogram/generated/` 或素材生成規則。
- 不把全部圖片移回主包；目前主包已接近 2 MB，無法容納全部素材。
- 不使用 `preloadRule` 一次預載十個素材分包；十個分包總量超過預下載限制。
- 本次只處理素材分包可用性、載入狀態與錯誤重試，不順手處理主包體積品質警告。

## 方案決策

採用「路由觸發分包下載」方案。現有每個素材分包都已配置空的 `pages/placeholder/index` 頁面；名冊頁進入時，依序導航到每個 placeholder，再立即返回主頁。導航成功代表對應普通分包已經被客戶端下載並可用，返回後主頁再渲染人物與技能圖片。

載入順序如下：

```text
名冊頁 onLoad
  → 顯示本地素材載入狀態
  → 導航 subpkg-a0 placeholder，成功後返回
  → 導航 subpkg-a1 placeholder，成功後返回
  → …
  → 導航 subpkg-a9 placeholder，成功後返回
  → 顯示名冊資料
```

採用順序載入而非並行載入，避免多個導航同時操作頁面棧，也便於定位是哪一個素材分包失敗。已成功載入的分包會以模組級集合記錄，後續重新進入名冊頁不重複導航。

## 模組與資料流

### `miniprogram/runtime/asset-package-loader.ts`

新增只依賴微信導航 API 的運行時載入器：

- 固定管理 `subpkg-a0` 至 `subpkg-a9` 的 placeholder 路徑。
- `loadAssetPackages()` 依序載入尚未完成的素材分包。
- 單一分包導航成功後立即 `navigateBack`，成功返回後才標記為已載入。
- 任一導航失敗時以包含分包 root 的錯誤拒絕，後續分包不再繼續。
- 將導航與返回操作抽象成可注入依賴，讓單元測試能驗證順序、去重和失敗停止，不依賴真實 `wx`。

### 名冊頁初始化

`pages/catalog/index.ts` 將現有同步初始化拆成可等待的初始化流程：

1. 讀取已生成的名冊、技能和字典資料。
2. 設置 `assetLoading` 狀態，暫不把含圖片的名冊行交給 WXML。
3. 等待素材載入器完成十個分包。
4. 按現有邏輯建立篩選狀態與名冊行，完成一次 `setData`。
5. 若載入失敗，設置錯誤訊息與重試狀態，不顯示看似完整但圖片全部失敗的名冊。

新增 `retryAssetLoading` 事件，重試時沿用已成功載入的分包，只重新嘗試失敗分包。

### 名冊 WXML

新增最小的載入與錯誤狀態：

- 素材載入中：顯示「正在載入本地圖片素材」。
- 素材載入失敗：顯示繁體中文錯誤提示與「重新載入」操作。
- 素材完成後才顯示既有篩選器和名冊列表。

既有頭像首字回退和技能圖示路徑不改動；它們只作為真正圖片檔案錯誤時的最後防線。

## 錯誤處理

- 導航到 placeholder 失敗：記錄 root、保留失敗 root 未標記為已載入，並讓使用者可重試。
- 返回 placeholder 失敗：視同該分包載入失敗，避免在頁面棧狀態不明時繼續渲染。
- 重複初始化：已完成的 root 直接跳過；同一頁面同時只允許一個初始化流程。
- 不新增遠程回退。離線要求下，素材無法載入時必須明確顯示錯誤，而不是嘗試網絡 URL。

## 測試與驗證

### 自動化測試

- 載入器會按 `subpkg-a0` 至 `subpkg-a9` 順序導航並返回。
- 已載入分包不會再次導航。
- 某個分包失敗時，流程拒絕且不會繼續觸發後續分包。
- 名冊頁會在素材載入完成前保持載入狀態，成功後才設置可見名冊行。
- 名冊頁載入失敗時會暴露重試狀態。

### 真機驗證

1. 重新編譯並上傳測試版。
2. 首次進入名冊頁，確認先看到繁體中文本地素材載入狀態。
3. 載入完成後確認人物頭像、技能圖示和詳情頁素材均正常。
4. 返回名冊頁再進入，確認不會重複出現長時間載入。
5. 在無網絡條件下重複上述流程，確認不依賴遠程 URL。
6. 確認代碼依賴分析中十個素材分包仍存在，且主包沒有被塞入全部圖片。

## 風險與後續優化

此方案會把首次進入名冊頁的下載量從主包延後到載入階段，首次等待可能較長；這是保持完全離線且不超出主包限制的直接代價。本次先載入十個分包以保證篩選、分頁和反查都不再遇到跨分包圖片失敗。後續若需縮短首屏等待，可另開任務按可見行的素材 root 做按需載入，但不與本次修復混合。
