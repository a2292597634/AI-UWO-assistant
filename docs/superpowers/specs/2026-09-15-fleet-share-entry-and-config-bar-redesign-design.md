# 配隊分享入口與配置欄重整設計

## 目標

取消戰鬥與冒險配隊頁底部固定的分享操作欄，避免其與「重新計算」後的方案預覽、應用方案、撤銷及其他底部操作發生遮擋。分享入口改為配置欄摘要列中的常駐操作，並同步整理配置名稱、保存狀態、配置數量及展開內容的對齊與分組。

本文替代 `2026-09-14-fleet-share-image-design.md` 中「分享入口按鈕」一節；分享圖內容、生成流程、未保存守衛、素材降級及錯誤處理等其餘規格保持不變。

## 已確認布局

### 收起狀態

配置欄摘要列從左到右分為四個區域：

1. 名稱區：同一基線顯示「我的配置」與目前配置名稱；名稱過長時只截斷配置名稱。
2. 狀態區：將保存狀態與配置數量合併為一組，例如「已保存 · 1 套」或「尚未保存 · 0 套」，不得再分散成兩塊高低不一的文字。
3. 分享操作：顯示緊湊的「分享」按鈕，位於展開箭頭左側，是戰鬥與冒險配隊頁唯一的分享入口。
4. 展開操作：維持獨立箭頭按鈕，只負責展開或收起配置內容。

摘要列使用垂直居中與統一文字基線。配置名稱可壓縮，狀態、分享及箭頭不可被擠壓或換行。分享與展開按鈕保留至少 `88rpx` 的可點擊熱區；視覺內容可以更緊湊，但不得縮小實際熱區。

### 展開狀態

摘要列布局保持不變，內容區按以下順序排列：

1. 登入、載入中、空列表或錯誤狀態提示；
2. 配置列表；
3. 配置管理操作；
4. 待分類舊配置（存在時）。

配置列表每一行左側顯示配置名稱及「目前使用」狀態，右側顯示「載入」。若該行是目前使用的配置，則在「載入」右側追加「離開配置」；非目前配置不顯示離開操作。這使離開行為與其作用對象保持在同一行，不再占用全寬獨立行。

配置管理操作固定為同一行四欄，順序為：

1. 另存為；
2. 重新命名；
3. 刪除配置；
4. 新建配置。

四欄等寬、間距一致，按鈕文字不換行。刪除配置沿用危險操作樣式，其餘使用次要操作樣式。當某操作不適用時，維持既有業務條件：沒有目前配置時不顯示重新命名與刪除配置；其餘可用操作仍保持原順序，不以空白按鈕占位。

若目前配置存在未保存修改，「覆蓋保存」仍作為獨立主要操作，放在四欄管理操作之前，不與四個管理按鈕擠在同一行。訪客狀態仍顯示全寬「登入後保存」，不顯示僅登入後可用的管理操作。

## 分享交互

`config-bar` 新增分享事件，不承擔圖片生成或未保存判斷。戰鬥與冒險頁接收事件後，繼續調用既有 `onShareFleet` 流程：

- 配置乾淨時直接生成分享圖；
- 配置未保存時顯示「保存後生成／直接生成／取消」守衛；
- 生成中按鈕顯示明確狀態並禁用重複點擊；
- 生成或素材失敗後恢復可點擊並允許重試。

分享入口在配置欄收起、展開、未命名、未保存及訪客狀態下均保持可見。分享不依賴雲端配置，因此訪客仍可生成目前本地隊伍的分享圖。

## 页面结构调整

戰鬥與冒險頁移除位於主滾動區外的 `.fleet-share-bar`。隱藏 Canvas 與分享預覽元件仍保留在頁面級，配置欄只觸發事件，不接收 Canvas 或分享 View Model。

移除固定分享欄後，同步刪除僅為固定欄預留的頁面底部間距與分享欄層級規則。方案預覽 Sheet、撤銷提示及分享圖片預覽各自維持既有層級，不再需要和分享入口競爭底部空间。

## 響應式與可用性

- 以 `320px` 寬視口為最低驗收寬度；摘要列不得橫向溢出。
- 配置名稱優先省略，保存狀態與配置數量保持完整；若極長本地化文字造成空間不足，狀態組可隱藏分隔點前後的額外空格，但不可拆成兩行。
- 四個管理按鈕在同一行內等寬排列；使用 Design Foundation 的最小操作字級和控制圓角，不使用小於規範的文字换取空间。
- 「分享」、展開箭頭、「載入」及「離開配置」均具備清晰的 `aria-label`，圖標不單獨承擔語義。
- 摘要列僅箭頭控制展開，分享按鈕不觸發展開，避免事件冒泡造成雙重操作。

## 元件邊界

### `config-bar`

新增輸入：

- `shareStatus`：用於顯示默認、生成中及可重試狀態。

新增輸出：

- `share`：使用者點擊摘要列分享按鈕時觸發。

既有 `toggle`、`load`、`exit`、`save`、`save-as`、`rename`、`delete`、`new`、`login`、`classify` 與 `retry` 事件語義不變。配置行上的離開按鈕仍觸發既有 `exit`，不新增第二套離開流程。

### 戰鬥與冒險頁

兩頁向 `config-bar` 傳入 `shareStatus` 並綁定 `share="onShareFleet"`。不再維護只為控制底部分享欄可見性的派生狀態；方案預覽的顯示只由既有 `proposalPreview` 管理。

## 測試與驗收

### 自動化測試

- `config-bar` 結構契約：摘要列包含名稱組、合併狀態組、分享按鈕及獨立展開按鈕。
- 分享事件：點擊分享只觸發一次 `share`，不觸發 `toggle`。
- 配置列表：目前配置行以「載入 → 離開配置」順序顯示，非目前配置不顯示離開。
- 管理操作：另存為、重新命名、刪除配置、新建配置在同一容器中按固定順序排列。
- 頁面契約：戰鬥與冒險頁均綁定配置欄分享事件，且不存在 `.fleet-share-bar`。
- 分享流程既有測試保持通過，包括未保存三分支、生成中攔截、預覽、保存及失敗重試。
- 執行 `git diff --check`、相關定向測試及 `npm run verify`。

### 微信 DevTools 與真機

- 在 `320／375／393／430px` 寬度检查摘要列對齊、配置名稱省略及無橫向溢出。
- 檢查訪客、未命名、已保存、未保存、空列表、錯誤及多配置狀態。
- 展開配置後確認四個管理按鈕保持同一行，且「載入／離開配置」位於目前配置行右側。
- 點擊分享不得展開或收起配置欄；點擊箭頭不得觸發分享。
- 打開方案預覽後，底部「取消／應用方案」完整可見、可點擊，頁面不存在固定分享區遮擋。

## 非目標

- 不修改配置保存、載入、衝突處理、數量上限或雲端資料格式。
- 不修改分享圖內容、Canvas Renderer、分享碼或分享圖片預覽布局。
- 不新增第二個分享入口，不在页面底部保留悬浮或固定分享按钮。
- 不修改航海士、技能及生成資料。

## 完成條件

- 戰鬥與冒險配隊頁的分享入口均位於配置欄摘要列、展開箭頭左側。
- 配置摘要文字對齊穩定，不再出現保存狀態與配置數量參差錯位。
- 四個配置管理按鈕按要求同列顯示；離開配置位於目前配置行的載入按鈕右側。
- 方案預覽和所有底部操作不再被分享入口遮擋。
- 自動化測試、完整工程門禁及指定視口的 DevTools／真機驗收通過。
