# 戰鬥模擬艦隊功能設計

## 1. 目標

在首頁新增「戰鬥模擬艦隊」功能，讓玩家在單一頁面管理 7 艘船的航海士配置，並以手動配隊或逐船自動配隊的方式，觀察當前船的主動技能與戰鬥類被動技能累計結果。

## 2. 已確認的產品規則

- 一支艦隊固定包含 7 艘船。
- 每艘船最多容納 11 位航海士，全艦隊最多 77 個位置。
- 同一航海士在同一支艦隊中只能出現一次。
- 每艘船可以獨立選擇手動或自動配隊模式。
- 配隊介面是單一頁面，不採用流程向導，不因完成一艘船而自動跳頁。
- 頁面以 7 個船位標籤切換目前編輯的船；同一時間只展開目前船的編輯區。
- 玩家可以自行點選下一艘船；完成狀態不阻止返回修改。
- 排除名單對全艦隊生效。
- 自動模式只計算目前選中的船，不因目前船變更而靜默重算其他船。
- 修改已完成的船時，其他 6 艘船的航海士仍視為已占用。
- 若玩家要把其他船已使用的航海士移到目前船，必須明確確認；原船移除該航海士並標記為「需要重新檢查」，不靜默重配。

## 3. 技能計算規則

### 3.1 計算範圍

只納入以下技能：

- 主動技能。
- 戰鬥類被動技能，包括砲擊、肉搏、衝破、防禦、其他戰鬥被動分類。

交易、冒險、航海、醫療、修復、天生增益、天生減益及其他非戰鬥分類不納入本功能的技能搜尋、目標設定或累計顯示。

### 3.2 單個航海士貢獻值

單個航海士對技能的貢獻值使用技能關係資料中的 `unlockLevel`。例如某航海士對某技能的關係為 `unlockLevel: 2`，則該航海士對該技能貢獻 Lv.2。

`level` 不作為艦隊技能累計值；它保留原有資料語義，用於航海士技能資料展示及其他既有功能。

### 3.3 船上累計與效果上限

目前船對每個技能的實際累計值為該船所有航海士貢獻值之和，不封頂。例如 3 位航海士貢獻 Lv.2、Lv.2、Lv.1，顯示為 Lv.5；超過 10 時仍顯示真實值，例如 Lv.12 或 Lv.18。

遊戲效果在 Lv.10 以上與 Lv.10 相同，因此自動目標輸入只允許 Lv.1 至 Lv.10。目標判斷使用真實累計值與目標值比較，累計值達到目標即視為達標。

### 3.4 當前船技能摘要

頁面底部即時顯示目前船的技能累計情況：

- 顯示目前船所有已出現的戰鬥技能。
- 已設定目標但目前累計為 0 的技能也要顯示。
- 每行顯示技能圖示、名稱、真實累計等級及目標達成狀態。
- 每行右側顯示貢獻該技能的航海士小型頭像。
- 同一技能最多可能有 11 位貢獻者；頭像區允許橫向滾動，不隱藏貢獻者。
- 目標技能沒有貢獻者時顯示空狀態，不偽造頭像。
- 技能行按真實累計等級由高到低排列；同級以穩定的技能 ID 或名稱排序。

## 4. 單頁介面結構

頁面由上至下包含：

1. 頁面標題與全艦隊占用摘要，例如「已配置 42 / 77 個位置」。
2. 7 個船位切換標籤，例如「1號船」至「7號船」。
3. 目前船標題、完成狀態、已配置人數及 11 個船艙位置。
4. 目前船的模式切換：手動配隊或自動配隊。
5. 目前模式的配隊工作區。
6. 自動模式的全艦隊排除名單區域；手動模式可隱藏此工作區，但排除狀態仍保留。
7. 目前船底部即時技能累計區。
8. 全艦隊 7 船摘要，顯示每艘船的人數、完成狀態及是否需要重新檢查。

不把 7 艘船的 77 個船艙同時展開，避免手機頁面過長且難以辨識目前正在編輯的船。

## 5. 手動配隊

手動模式使用共用技能選擇器搜尋技能，再列出擁有該技能的可用航海士。

- 顯示技能名稱、圖示、主動／被動及戰鬥分類。
- 選擇技能後列出航海士姓名、頭像、職業、稀有度和該技能貢獻值。
- 目前船已加入的航海士可以移除。
- 已在其他船的航海士顯示所屬船位並禁止選擇。
- 排除名單中的航海士禁止選擇，並顯示「已排除」。
- 船艙達到 11 位後，新增操作停用。
- 手動配隊不因沒有設定技能目標而自動補人。

## 6. 自動配隊

### 6.1 目標列表

進入目前船的自動模式時，預設建立一條空白目標編輯行：

- 預設目標等級為 Lv.1。
- 技能尚未選擇前，該行只是占位，不計入目標。
- 玩家可透過「新增目標」持續增加目標行，數量不設固定上限。
- 每一行只能選一個技能及一個 Lv.1 至 Lv.10 的目標值。
- 同一技能不可重複添加。
- 移除目標後，已入隊的航海士不自動移除；重新計算才會依新目標產生結果。

### 6.2 技能逐層篩選

手動搜尋及自動目標設定共用同一個技能選擇器，依三層篩選：

1. 技能類型：主動技能、戰鬥被動。
2. 戰鬥分類：砲擊、肉搏、衝破、強化、防禦、其他。
3. 具體技能：顯示技能圖示與名稱，並支援在目前分類內輸入文字搜尋。

選擇技能後返回原本的手動搜尋條件或自動目標編輯行，不重置其他目前船狀態。

### 6.3 鎖定、排除與重新計算

- 鎖定：目前船重新計算時必須保留該航海士。
- 移除：只移出目前推薦或目前船，不加入排除名單。
- 排除：加入全艦隊 `bannedOfficerIds`，從目前推薦移除，並禁止後續所有船推薦。
- 解除排除：從全艦隊排除名單移除，不自動入隊，只有下一次重新計算才可能出現。
- 已入隊或已鎖定航海士不能直接排除；要排除必須先解除目前占用狀態。
- 排除推薦結果後，保留目標和鎖定航海士並重新計算目前船。

### 6.4 求解優先級

目前船的候選集合排除：其他 6 船已占用航海士、全艦隊排除名單及目前船已移除的候選人；目前船已鎖定航海士作為固定輸入保留。

求解結果按以下詞典序評分：

1. 達成的目標技能數量越多越好。
2. 所有目標均可達成時，使用的航海士數量越少越好。
3. 使用人數相同時，所有目標技能超出目標值的總量越少越好。
4. 仍相同時，按航海士 ID 穩定排序。

沒有設定有效目標時，自動模式回傳空推薦，不為了填滿 11 個位置而加入無關航海士。

無法完全達成目標時，顯示每個技能的目前值、目標值和差額；允許玩家保留不完整結果並完成目前船，但船位摘要標記「未完全達成目標」。

## 7. 排除名單

排除名單是全艦隊共用狀態，在自動模式工作區中提供專門區域：

- 顯示被排除航海士的頭像、姓名及解除排除操作。
- 顯示排除人數。
- 排除名單過長時使用獨立橫向或縱向滾動區域，不佔滿整個頁面。
- 排除與鎖定、已入隊互斥。
- 解除排除不自動改變任何既有船配置。

## 8. 編輯與衝突狀態

每艘船具有以下展示狀態：

- 未配置。
- 編輯中。
- 已完成。
- 未完全達成目標。
- 需要重新檢查。

修改某船時：

- 只釋放該船原本的航海士。
- 其他船仍然占用自己的航海士。
- 嘗試選擇其他船航海士時，先顯示所屬船位，再要求明確確認移動。
- 確認移動後，原船移除該航海士並變成「需要重新檢查」。
- 不自動重算原船或其他船。

## 9. 運行資料與程式邊界

`archive/` 保持唯讀；所有新增資料加工在 `data/master/` 和生成工具完成。由 `npm run data:generate` 產生主包所需的輕量艦隊技能索引，例如 `miniprogram/generated/fleet-officers.js`，內容至少包含航海士 ID、戰鬥技能 ID、技能類型及 `unlockLevel` 貢獻值。

主包頁面經由 `miniprogram/runtime/main-data-store.ts` 讀取該索引，不直接引用生成檔案，也不依賴詳情子包的懶加載模組。運行時不使用 `wx.request`、`wx.cloud`、遠端 URL 或 Node.js API。

純 TypeScript 領域模組負責：

- 艦隊去重與船位容量驗證。
- 船上技能累計與排序。
- 目標達成判斷。
- 可用、已占用、鎖定、排除狀態轉換。
- 自動配隊候選篩選與確定性求解。

頁面與 presenter 只負責狀態同步、WXML 所需視圖資料、互動事件與本地路由。

## 10. 測試與驗證範圍

依 TDD 先為純邏輯建立失敗測試，再實作最小通過版本。至少覆蓋：

- 7 船與每船 11 人容量限制。
- 全艦隊航海士 ID 去重。
- 使用 `unlockLevel` 累計，不使用 `level`。
- 技能累計不封頂、目標輸入只接受 Lv.1 至 Lv.10。
- 累計技能按數值降序並穩定排序。
- 累計技能行包含正確貢獻者 ID，缺少目標技能時顯示 Lv.0。
- 手動搜尋只回傳主動及戰鬥類被動技能。
- 三層技能分類篩選和分類內文字搜尋。
- 鎖定航海士在重新計算後仍保留。
- 排除航海士對後續所有船生效。
- 已占用、已鎖定、排除三種狀態互斥。
- 修改某船時不靜默重算其他船，並正確產生「需要重新檢查」狀態。
- 無目標、目標不可達、船位已滿和目標重複等邊界情況。
- 生成資料與 `data/master/` 的確定性及完整性檢查。

完成實作前執行 `npm run verify`，並使用微信開發者工具驗證單頁船位切換、手動搜尋、自動目標新增、鎖定、排除、重新計算、技能頭像列表及修改衝突提示。

## 11. 明確不包含

- 船舶資料、船舶技能或戰鬥傷害數值模擬。
- 保存多套艦隊方案、分享連結或雲端同步。
- 自動填滿沒有技能目標的船。
- 其他非戰鬥技能的配置與統計。
- 修改既有 `archive/` 或手動修改生成目錄。
