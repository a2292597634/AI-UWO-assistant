# 航海士卡片内联操作设计规格

## 背景

战斗配队与探险配队页面目前共用 `officer-action-sheet`。每张航海士卡片头像下方只有一个“更多操作”触发按钮，按钮占用空间过大且继续打开弹出式操作面板，不符合紧凑配队页面的操作需求。

## 目标

- 在战斗配队和探险配队两页的每张航海士卡片下方直接显示三个紧凑操作按钮：锁定、移除、排除。
- 点击按钮直接执行操作，不再打开航海士操作弹出框。
- 锁定或解锁后，锁定航海士在当前展示列表中前置，并使用明显但克制的高亮状态。
- 保留现有领域层的锁定、移除和排除规则，包括锁定后不可移除/排除。
- 不新增依赖、不新增图片素材，不修改配队求解算法和配置持久化协议。

## 非目标

- 不修改航海士头像、稀有度图标、职业图标等资料素材。
- 不改变“锁定”“移除”“排除”在领域层的业务语义。
- 不把排除名单、技能目标或配置管理按钮改造成图标按钮。
- 不修改配置预览底部的“取消”“应用方案”等全局操作按钮。

## 现状与根因

- 两页的航海士卡片都使用 `<officer-action-sheet presentation="trigger">`。
- 触发模式目前只渲染一个“更多操作”按钮，并通过 `open` 事件打开页面底部的 sheet 模式。
- sheet 模式已经具备 `lock`、`remove`、`ban` 三个事件，但页面卡片没有直接绑定这些事件。
- 探险页 presenter 已经按锁定状态把航海士分成“锁定在前、其他在后”；战斗页当前船位仍按 `officerIds` 原始顺序生成，需要增加仅用于展示的锁定优先顺序，不能改写船位数据。
- 探险页已有 `.officer-card--locked` 高亮样式；战斗页需要补充对应的锁定卡片状态样式。

## 方案

### 组件边界

继续使用 `officer-action-sheet` 作为航海士操作组件，但将 `presentation="trigger"` 改为直接渲染内联操作条：

- 锁定按钮：未锁定时显示锁定图标语义，已锁定时显示解锁图标语义；事件仍统一发出 `lock`。
- 移除按钮：发出 `remove`。
- 排除按钮：发出 `ban`。
- 每个按钮都保留可读的 `aria-label`，禁止只依赖颜色或不可读图形表达状态。
- 图标采用现有字体/CSS 可表达的紧凑非 Emoji 符号，不新增外部图标库或图片素材。
- `presentation="sheet"` 的实现可保留为组件兼容分支，但战斗配队和探险配队页面不再挂载或触发该弹出模式。

### 页面事件流

两页的每个卡片实例直接绑定 `lock`、`remove`、`ban` 到现有页面处理函数。页面处理函数继续调用现有领域操作：

```text
图标按钮
  → officer-action-sheet 事件
  → 页面 onOfficerLock / onOfficerRemove / onBanOfficer
  → 现有领域 transition
  → presenter 重新生成页面数据
  → 锁定项前置 + 锁定高亮
```

删除卡片底部未使用的 sheet 实例和对应的打开/关闭状态流，避免点击卡片操作后仍可能出现弹出框。现有领域状态和撤销/保存流程不变。

### 锁定前置与高亮

- 探险页继续沿用 presenter 的锁定优先分组，并以 `officer-card--locked` 显示锁定高亮。
- 战斗页在 presenter 生成 `currentShip.slots` 时使用“锁定 ID + 其余 ID”的展示顺序，位置编号仍由展示数组生成；不修改 `currentShip.officerIds`，因此不改变领域层船位顺序和求解输入。
- 战斗页新增 `.officer-slot--locked` 状态样式，与探险页保持相同的高亮语义：边框使用 `accent-brass`，辅以内框强调，不使用大面积阴影。
- 解锁后重新回到未锁定项区域，并移除高亮。

### 禁用规则

- 已锁定航海士：锁定按钮变为解锁；移除和排除按钮保留但禁用，并提供对应原因的辅助文本/无障碍标签。
- 未锁定航海士：三个按钮均可用。
- 页面已有领域层错误处理继续作为最终保护，UI 禁用状态不替代领域校验。

## 响应式与触控

- 三个按钮只保留紧凑的视觉尺寸，按钮容器使用固定紧凑间距，不能再撑满航海士卡片。
- 卡片宽度不足时，操作条仍保持单行，不挤压头像、姓名和船名；按钮文字不参与布局宽度计算。
- 操作按钮提供明确的 `aria-label`，焦点和按下状态沿用现有 token。
- 不降低主要页面操作按钮的 88rpx 触控规范；本次缩小仅针对卡片内的次级图标操作热区，并以窄屏截图/布局契约验证不溢出。

## 测试策略

遵循红-绿-重构：

1. 先为组件契约增加失败测试，要求 trigger 模式包含三个直接操作按钮、锁定状态切换语义和 `aria-label`，且页面不再挂载 trigger-to-sheet 的打开事件。
2. 为战斗与探险页面增加失败测试，要求卡片直接绑定三个操作事件，并覆盖 locked 状态 class/展示顺序。
3. 为 presenter 增加行为测试：战斗展示数据把锁定航海士放在前面但不改变原始 state；探险锁定项继续前置。
4. 实现后运行组件、页面和 presenter 定向测试，再运行全量测试、Lint、TypeScript 类型检查、格式检查和 `git diff --check`。

## 验收标准

- 两页每个已配置航海士头像下方都能看到锁定、移除、排除三个紧凑图标按钮。
- 点击任一按钮直接执行操作，不出现原来的航海士操作弹出框。
- 锁定后航海士前置并高亮；解锁后恢复普通排序和样式。
- 锁定航海士的移除/排除按钮不可用，未锁定航海士的对应按钮可用。
- 头像、姓名、船名、卡片网格以及现有配置保存/撤销行为不回归。
