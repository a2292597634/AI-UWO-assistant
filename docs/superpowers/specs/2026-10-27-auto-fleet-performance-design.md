結論：只分批執行不會減少運算量，還會增加排程成本；只做簡單同類截取也不足以處理冒險五目標。因此必須同時減少重複搜索、降低每次轉移成本，並復用完全相同輸入的已完成結果。

## 方案比較

1. **推薦：搜索核心優化＋精確結果快取＋可中斷排程。** 第一優先縮短冷計算，快取處理未變更條件下的重新計算，排程與進度負責等待體驗。保留既有評分、約束及結果排序語義。
2. **Worker 隔離運算。** 可以隔離邏輯層長任務，但單個 Worker 執行相同搜索仍要做相同工作；建立、資料序列化、主包／分包與平台相容性需實測。作為核心優化後的備選，不把 Worker 本身當作計算加速證據。
3. **快速方案先出、再繼續優化。** 最快得到可用結果，但需要區分暫定方案與最終方案，且可能讓使用者提前使用品質較低的結果。這是另一種產品行為，本輪不預設採用，也不直接降低 DP 門檻換成貪心。

## 效能實作順序與品質界線

### 先減少不必要的工作

- 對空目標、無可用容量、鎖定成員已滿足全部目標等有明確證明的情況直接返回；不能把「找到一個達標方案」當作通用提前結束條件，因為人數、溢出與 ID 排序仍可能改善。
- 已完成結果以頁面內最近一次精確輸入作有界記憶體快取；輸入未變更時直接重新建立預覽，不重跑搜索。命中應在 100 ms 內回應，這是待驗證的工程目標。
- 快取鍵包含 Solver／資料版本、戰鬥或冒險模式、目標及其順序、容量、候選 ID 與實際有效貢獻、鎖定／排除／佔用、目前成員、目標船和編隊基線；不能只比較目標，也不能只相信可能未隨自訂航海士更新的資料版本。取消或失敗結果不進快取，頁面卸載時釋放。
- 相同技能貢獻可分組，但不能每組只留一人；先過濾鎖定、排除、其他船佔用，再按剩餘容量與目標需求計算足夠的保留數。保留 ID 排序最優的足額代表，不能丟失必要多重數量。此優化需測試確認，不能憑目前單例直接上線。

### 再降低搜索核心成本

- 共用戰鬥與冒險的純計算核心，保留兩個入口的資料準備、容量及約束差異，避免維護兩份性能修復。
- 把目標貢獻轉為預先建立索引的數值向量；DP 有界分支的狀態鍵使用混合進位整數，避免每次建立字串與字典。
- 轉移若完全不增加任何未達標目標，其相同狀態鍵下的人數更大，不可能勝出，先略過；新狀態確定勝出後才建立成員路徑，減少失敗轉移的配置。
- 保留真實技能總量、溢出與同分排序資訊；不能只保存截斷到目標的總量，否則會改變溢出評分與預覽。
- 同一輪候選的讀取必須來自該輪開始的狀態。數值陣列原地更新時必須用正確的世代隔離／遍歷證明，防止同一航海士被重複使用。
- 不因增量評分改變浮點加總順序或同分判定；如需改成整數比例評分，應單獨審查其語義，不混入純效能宣稱。
- 只有具備上界證明的剪枝才可採用，不以隱性超時、縮小 beam 或降低 DP 門檻換取表面速度。現有 DP 不能直接宣稱對所有輸入保證全局最優，本次也不擴張該承諾。

### 排程成本要可控

- 每個時間片暫定 8 ms，批內每一小批轉移檢查時鐘和取消訊號，避免每一步都讀時鐘；在單一候選內也可中斷。
- 讓出事件迴圈採用宏任務，不能只用連續 Promise 微任務；微任務串接可能仍不讓介面處理操作。
- 進度資料最多每 100–150 ms 更新一次，只發送少量進度欄位；不在每批重建全頁 Presenter 或大量 `setData`。
- 不固定每一個候選 sleep 一幀；這會把大量小候選轉成可觀等待時間。排程只在時間預算用完後執行。

### 工程目標與停止條件

- 點擊後 100 ms 內出現處理狀態；取消操作目標在 100 ms 內生效。
- 計算批次目標約 8 ms、記錄最長批次；若預處理、收尾或單一狀態仍有長任務，也需拆分。不要只看平均數。
- 正式 Node 22 重測的戰鬥五目標中位耗時以低於原版 20% 為第一門檻，爭取 1 秒內；冒險五目標以 2 秒內作優化目標。這些是實作驗收目標，尚未達成，也不是所有手機的時間保證。
- 採取交錯多次基準與記憶體峰值觀測；冒險原版的 30 秒超時只能作下界，不能算出精確加速倍數。
- 若核心優化仍無法達標，先交付測量與剩餘熱點，評估 Worker 或新的搜索策略；不得把只有進度條的版本標作效能修復完成。所有正式結果仍須保持既有約束與品質回歸。

## 計算與互動設計

- 把求解過程改為可增量推進的共用計算核心，原同步入口保留作既有呼叫；頁面使用非同步排程入口。同步與非同步入口不能各維護一份算法。
- 時間片暫定約 8 ms，必須在狀態轉移內部檢查，避免單一候選本身形成長阻塞；每批讓出事件迴圈，微信驗收時按實測調整。
- 優化方向為預先計算目標索引與貢獻、減少內迴圈的字串／物件建立及重複遍歷；只採用有等價性測試支持的變更。
- 不以降低 DP 精度取得效能數字；既有超大狀態空間的貪心分支維持其邊界與語義。
- 點擊後先更新可見狀態，再開始計算，等待進度視圖完成首次更新後啟動重任務；快取命中直接開預覽，不為了展示進度而人為等待。
- 計算時禁止重複啟動，同區提供「取消計算」。不以全頁遮罩阻擋閱讀和返回。
- 取消後停止後續批次，不修改目前艦隊，也不產生可套用的半成品。
- 每個任務保存輸入快照、頁面實例與任務識別；目標、船隻、成員、鎖定、排除或配置改變時取消／作廢舊任務。頁面隱藏或卸載時停止計算；舊回呼不能更新已卸載頁面或覆蓋新結果。
- 失敗時恢復按鈕狀態，顯示繁體中文錯誤與重試入口。
- 完成後沿用既有「方案預覽 → 應用 → 一次撤銷」，保留指紋校驗、容量、鎖定和排除護欄。

### 對照稿：目標區內嵌

放在目標列表與計算按鈕之間，沿用原區塊的紙色背景、墨綠進度、字體與間距，不增加全頁遮罩或額外卡片。取消為次要按鈕、熱區至少 88rpx，計算按鈕原生禁用並顯示「計算中…」。

正常搜索呈現：標題「正在計算配隊」、已用時間、「候選比較 64%」、進度條、「已比較 127 / 198 名候選」、說明「可繼續瀏覽；取消不會變更目前編隊。」與取消入口。

進度必須有明確分母語義：百分比只指候選／貢獻組比較的處理量，不能稱作總剩餘時間或結果品質。分組後若處理的是貢獻組，文案改為「組合比較」「已比較 X / N 組」，不能繼續冒稱航海士人數。長批次可按該候選的快照處理量顯示批內小數進度，但可見計數只計完整完成的候選。

### 已確認：底部常駐

同一進度元件固定於頁面底部，滾動瀏覽時也可立即取消；內容需預留等高底部空間與安全區，避免遮住最後一列。代價是佔用更多窄屏高度，並與其他底部操作區協調。互動稿只展示佈局，不冒充已完成真機滾動驗收。

### 所有狀態的行為

| 階段 | 進度展示 | 操作與說明 |
| --- | --- | --- |
| 準備 | 「正在準備配隊」，無百分比的不定進度 | 可取消；篩選候選、快取比對也須可響應 |
| 比較 | 實際處理量百分比＋X / N＋已用時 | 可取消、不可重複啟動；百分比允許暫停，不按時間自動前進 |
| 整理 | 「正在整理配隊方案」，不定進度 | 比較階段已結束；不把比較 100% 當成預覽已就緒 |
| 完成 | 清除計算狀態，開啟既有預覽 | 不為湊滿一段動畫而延遲結果；預覽成功渲染後才視為完成 |
| 取消 | 「已取消計算，目前編隊未變更」 | 恢復重新計算入口，丟棄未完成結果 |
| 失敗 | 「配隊計算未完成，目前編隊未變更，請重試」 | 恢復重試入口，不讓進度永久停留 |
| 長等待 | 原真實進度＋已用時 | 約 8 秒後補充「目標組合較多，仍在計算中；可隨時取消」，不虛構剩餘秒數 |

正常情況不顯示預估剩餘秒數，不用計時器假裝真實搜索進度，不把進度鎖在 99% 等待未知工作完成。等待期間可閱讀、滾動、返回；任何影響輸入的操作先取消原任務，再執行操作並提示需重新計算。

進度文字避免每 100 ms 觸發讀屏，無障礙通知只報告主要階段、完成、取消及失敗。動畫尊重減少動態偏好；長文字與 320／375／393／430 px 寬度需檢查。
