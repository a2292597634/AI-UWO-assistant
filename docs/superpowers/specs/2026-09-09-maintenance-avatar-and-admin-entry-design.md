# 航海士維護頭像與管理員入口修正設計

## 目標

補齊資料維護流程的兩個可用性缺口：新增航海士工單可在手機選取並裁切正式版頭像，且白名單管理員能從維護工單列表進入待審核工作台。

## 已確認規則

- 新增航海士必須提供一張頭像；修改既有航海士沿用正式資料的原頭像，不提供一般使用者改動正式 `portraitId` 的輸入。
- 手機端先使用微信 `wx.chooseImage` 選圖，再使用 `wx.cropImage` 以 `1:1` 比例裁切，最後沿用既有壓縮與檢查規則：PNG/JPG/JPEG、檔案不超過 512 KB、最長邊不超過 512 px。
- 裁切後的暫存圖只在小程序端預覽；維護雲函數在保存草稿或送審時接收檔案內容，服務端校驗後上傳 CloudBase Storage，工單只保存檔案參照與尺寸資訊，不把 base64 寫進資料庫。
- `portraitId` 仍是系統欄位：同步工具和資產流程依正式航海士 ID 產生本地資產，不接受使用者填寫或覆寫。
- 維護工單列表在載入時以服務端 `listAdmin('pendingReview')` 探測權限；成功（即使清單為空）才顯示「管理員審核工作台」入口，普通使用者的 `forbidden` 只會隱藏入口，不改變自己的工單錯誤狀態。審核頁與雲函數權限檢查保持不變。

## 資料流

```text
手機選圖 → 1:1 裁切 → 壓縮／尺寸檢查 → 保存草稿或送審
                                  ↓
             officer-maintenance 雲函數驗證並上傳 Storage
                                  ↓
              work order portraitFileId／portraitMeta（非正式 ID）
                                  ↓
             管理員審核預覽 → 核准 → 同步／資產流程產生 portraitId
```

`portraitFileId` 與 `portraitMeta` 僅屬工單附件資料，不進入 `MaintenanceOfficerData` 的正式欄位；管理員可預覽但不能由畫面直接指定正式頭像 ID。新增工單若送審時沒有已上傳檔案，服務端返回可理解的必填錯誤；草稿仍可先保存其他欄位。

## 元件與錯誤處理

- 編輯器新增頭像卡片：顯示裁切後預覽、重新選擇、移除與尺寸提示；管理員審核模式只讀顯示附件預覽。
- 裁切取消、選圖失敗、檔案格式／尺寸不符均保留表單內容並顯示下一步提示，不清空其他欄位。
- 上傳失敗不把工單標記為待審核；使用者可重試保存或送審。替換頭像時保留舊工單版本，服務端以最新附件參照為準。
- 管理員入口不可作為權限判斷；所有 `listAdmin`、保存、核准與駁回仍由雲函數白名單決定。

## 驗證範圍

- Presenter／服務測試覆蓋裁切後檔案 payload、附件保存與新增送審缺少頭像的拒絕。
- 頁面測試覆蓋 `wx.cropImage` 呼叫、預覽狀態、頭像必填提示，以及管理員入口僅在 `listAdmin` 成功時顯示。
- 雲函數測試覆蓋圖片格式／尺寸驗證、檔案上傳與工單附件參照；不改動正式 ID 或 `archive/`、`data/master/`、`miniprogram/generated/`。
- 完成後執行 `npm run verify`，並以微信 WXML 編譯器檢查維護三個頁面。
