# 大流行遊戲時刻表顯示修正設計

> 2026-09-26 更新：本文件關於大流行「預測」文案、日期 chips、海域／類型篩選和「查下一次」的決策，已由 [大流行時刻表頁面精簡與首頁圖示一致性設計](2026-09-26-major-event-schedule-page-polish-design.md) 取代。本文件中的 UTC+8 換算、週期、時段分段及矩陣事件顯示規則仍有效。

## 背景與對照結果

使用者提供的遊戲截圖以遊戲時刻顯示大流行：海域在左、整點在上，同一海域／時段以綠色事件條標示；目前時段以黃色欄底提示。遊戲當下的說明指出時刻表呈現發生時間、城鎮活動具有優先權、符合條件的同時事件最多兩種，且事件可能因預算耗盡而提前結束，最長持續兩小時。

依截圖提供的 2026-09-25 10:47（UTC+8）時間，以 UTC+8 呈現既有來源週期後，可重現遊戲畫面中可見的後續事件：東亞奢侈 11:04、東北亞戰爭 11:05、東印度和印度支那戰爭 13:04、南非戰爭 15:01。北極海戰爭的 09:06:30 雖已觸發，但距當時少於兩小時；後續設計允許它只以「可能進行」候選顯示在目前時段，不列作一般過去事件。截圖中的奢侈、繁榮、開發、贊助品類映射也與 `data/master/major-events.json` 一致。

主要問題在時間表呈現方式：頁面以裝置時區和非整點起始的六小時段顯示欄頭，事件籤還重複顯示分鐘；這與遊戲的整點欄頭、目前時段高亮及綠色事件條不同。週期、海域相位、延遲和交易品映射不改寫。

## 決策

保留「時刻矩陣」和「行程列表」雙視圖、24 小時／3 天／7 天範圍、日期選擇、海域與類型篩選、詳情及查下一次功能。僅重設矩陣的時鐘格式、可視時段與事件籤，讓矩陣按遊戲時刻表呈現；其他視圖仍使用 UTC+8 日期與時間。

採用明確的 UTC+8 換算，不依賴執行裝置的系統時區。Domain 仍以 Unix 秒數計算來源週期，Presenter 將欄頭、日期和詳情時間轉成 UTC+8。一般未來預測窗仍從實際目前時間開始；為呈現仍可能持續的大流行，依後續設計只為目前時段額外檢查過去兩小時內已觸發事件，並明確標示為候選。

## 矩陣與互動

- 每次顯示七個連續整點欄：從目前 UTC+8 整點開始，含目前時段及接續六個時段。例如目前時間為 10:47，欄頭為 10:00 至 16:00，10:00 欄以黃色底高亮。
- 選定範圍的未來預測仍是精確滾動區間 `[now, now + horizon)`；矩陣按 UTC+8 整點切分此區間。每個槽代表起始時間為整點的一小時區間；將相交槽序列每七槽切成不重疊頁段，首尾頁段可少於七槽。頁段數依相交槽數計算，日期按鈕導向該日期相交的第一個頁段，不漏事件、不重複事件。另見 [大流行可能進行事件與精簡海域矩陣設計](2026-09-25-major-event-ongoing-sparse-matrix-design.md)：只有目前時段可額外顯示尚未超過兩小時上限的事件候選。
- 海域維持列、時間維持欄；矩陣在自己的水平捲動容器內保留七欄的可讀尺寸，不造成頁面級橫向溢出。
- 同一海域／小時的事件類型使用綠色、深色文字的遊戲式事件條；事件條只顯示類型名稱，分鐘不在格內重複呈現。精確預測時間仍在行程與詳情顯示。
- 事件條維持緊湊的遊戲式外觀，但其獨立點擊熱區至少高 `88rpx`，不同事件的熱區不可重疊。
- 沒有預測事件的矩陣格維持留白，不加破折號或占位文字，對齊遊戲內的空格呈現。
- 使用集中式樣式 Token 表示遊戲綠色事件條與黃色目前時段；沿用 Design Foundation 色彩系統並檢查文字對比度，不在 WXML 寫入任意色值。原有四種事件色仍供行程和詳情使用。
- 海域徽記、紙紋底圖、羅盤與品牌抬頭沿用既有本地素材；行程及詳情中的交易品圖示繼續使用 `getTradeCategoryIconPath`。
- 範圍與段落控制仍可瀏覽長期預測；每一矩陣頁段以整點起始、最多顯示七個時段。日期、篩選和視圖切換的保留行為維持原設計。頁面以「東八區時間」標示固定時區，不再顯示「依裝置時間」。
- 矩陣底部以簡短輔助文字說明：時刻為週期預計發生時間；城鎮活動可能優先或令事件無法發生，事件預算耗盡可提早結束，最長兩小時。過去兩小時內觸發的事件只標示為「可能進行」，因離線頁面沒有城鎮活動與預算的即時資料，不宣稱已確認正在發生，也不顯示實際結束時間或預算狀態。

## 預測規則與資料邊界

- 沿用現有來源錨點 `1670889600`、8 個週期、18 個海域相位／延遲、類型順序和每小時最多兩種事件的規則。相位計算仍為 `pHour = floor((now - anchor) / 3600)`、`Si = pHour + 401 × zoneHour + iHour`；頁面只將結果呈現轉為 UTC+8。類型順序按來源週期由長至短排列，符合同時命中時優先保留等待週期較長事件的規則。
- 未來預測範圍採 `[now, now + horizon)`。只為目前時段另計算 `(now - 2 小時, now)` 內觸發、且兩小時上限尚未到期的事件候選；不把候選放進一般過去時段、其他矩陣頁段或行程列表，也不從截圖補造預算和城鎮活動狀態。
- 城鎮活動與非活動交易事件對實際大流行的抑制條件沒有可離線取得的目前狀態。本頁顯示的是週期預計時間，輔助文字須清楚說明遊戲規則可能使實際事件不發生。
- 不修改 `archive/`、既有週期或交易品類別映射；若回歸樣本與規則相符，不增修 `data/master/major-events.json`。

## 驗收

### 資料與 Presenter

- 以固定時間 `2026-09-25T10:47:00+08:00` 驗證 UTC+8 格式、整點欄頭及事件起始時間：東亞奢侈 `11:04`、東北亞戰爭 `11:05`、東印度和印度支那戰爭 `13:04`、南非戰爭 `15:01`。
- 同一固定時間下，北極海 `09:06:30` 只作為目前時段「可能進行」候選；不出現在一般過去槽或行程列表。改變 Node 測試執行環境時區，不得改變上述 UTC+8 展示結果。
- 驗證最多七個整點槽、目前小時高亮索引、相鄰頁段不漏事件、槽位不重複、範圍右邊界排除規則，以及同小時最多兩種事件的順序。
- 驗證截圖中的四種事件品類名稱仍由現有共用交易品資料和圖示解析器解析，不複製品類映射表。

### 微信 DevTools

- 驗收矩陣與遊戲佈局相符：UTC+8 整點欄頭、目前時段黃色高亮、綠色類型條、海域徽記、事件點選詳情、七槽頁段及段切換。
- 驗收行程、篩選、詳情、首頁入口及輔助規則說明；截圖報告中包含矩陣和詳情畫面。
- 窄屏仍只允許矩陣自身水平捲動；保留 320px、375px、393px、430px 的手動視口檢查要求。現有自動化工具不能設定這些寬度時，報告如實註明未覆蓋，不能宣稱已完成。
