# 工作區與證據管理

本規範適用於本項目開發、驗證和歸檔；不處理 E 盤上其他個人資料。入口與帳號以 [新端維護與舊端封存手冊](dual-app-maintenance.md) 為準。工作樹、分支、獨立 clone、預覽工程和證據目錄是不同對象，不能僅憑目錄名判斷可刪。

## 位置與建立

- 日常工程入口為 `E:\AI-UWO-new`，指向 `E:\AI UWO assistant`；固定舊端回溯入口 `E:\AI-UWO-old` 繼續保留。新任務從最新 `main` 建符合 AGENTS 命名規則的分支；按需要選擇原工程、隔離工作樹或乾淨驗證副本，不為每項任務無條件建立副本。
- 需要手動新建的項目工作樹優先集中於 `E:\UWO-worktrees`，使用 `git worktree add`，命名遵循 AGENTS。Codex 或宿主托管的工作樹使用平台返回的實際路徑和生命週期工具，不強行更改平台位置；先檢查已有可用工作樹及用戶指定路徑。
- 驗收證據按專項規範放在既有 `artifacts/` 或 `E:\AI-UWO-verification` 的任務子目錄；臨時 clone、編譯結果、預覽工程與臨時腳本放在明確標記的隔離子目錄。不得把新的項目臨時目錄直接散放在 E 盤根目錄。現有資料不因本規範自動移動或刪除。
- 保存腳本和輸出前檢查實際 format、lint 等掃描範圍；Git ignored 不代表其他工具忽略。不得為通過檢查而全域關閉掃描、擴大網路例外或覆寫合法證據；必要時在乾淨隔離副本驗證，並分開記錄本地與隔離結果。

## 建立記錄與任務收尾

建立工作樹、獨立 clone 或預覽／驗證副本時，記錄類型、絕對路徑、來源提交及分支、用途、所屬任務、建立時間與需要保留的證據；托管工作樹另記錄平台附件。位置與忽略文件可能含私有資料，私有清單僅本機保存，不提交密鑰或個人資料。

任務結束時逐項標記「繼續使用」「待核對」或「可清理」，並記錄對應報告、測試結果和後續動作。可重建不等於可任意刪除：只清理確認屬於本任務、已完成且不再使用的臨時輸出；其他受保護資料的刪除或移動先列出具體對象並取得相應授權。不要因工作樹乾淨或分支已合併而推定 ignored 證據可刪。

## 遷移、歸檔與恢復

1. 先核對真實路徑及 junction／符號連結、工作樹與嵌套倉庫、Git HEAD 和 tracked／untracked／必要 ignored 文件、獨有提交、依賴關係及 Codex 對話附件；保護固定入口、共享資源、私有資料及正在使用的工作。Git 工作樹的移動與移除使用 Git 或對應宿主管理工具，不能直接當普通目錄移動。
2. 遷移前檢查項目文檔、腳本、固定入口和已知任務中的引用；明確新舊路徑、備份與回退方案。大範圍外部引用無法完全窮舉時如實標記，不能聲稱全部無影響。檢查目標不存在或已明確核對，避免覆蓋。
3. 按對象類型保留可恢復原件及清單，核對檔案集合和 SHA-256、聯結目標、Git 狀態與提交；切換後再驗證入口及必要引用。保留未提交內容、ignored 證據和恢復所需資料；不把當前工作區、使用者文件或共享雲資源當臨時副本。
4. 更新仍需使用的引用，或提供本機新舊路徑對照及可用性說明；不要把本機絕對路徑假稱其他機器均可訪問。記錄未修復的外部引用。處理 Codex 對話歸檔時，另遵循維護手冊對附件、排程和 ignored 資料的檢查。
