## 5. P1 详细任务

## P1-1 航海士操作区改为真正的上下文操作

### 现状

`officer-action-sheet` 当前实际表现为航海士卡片内常驻的三个按钮：

- 锁定 / 解锁；
- 移除；
- 排除。

战斗配队使用 5 列槽位，每个槽位内部再次放置三个操作按钮。slot 模式还隐藏了文字标签。

相关文件：

- [组件 WXML](</E:/AI UWO assistant/miniprogram/components/officer-action-sheet/index.wxml:1>)
- [组件 WXSS](</E:/AI UWO assistant/miniprogram/components/officer-action-sheet/index.wxss:1>)
- [战斗使用位置](</E:/AI UWO assistant/miniprogram/pages/fleet/index.wxml:143>)
- [冒险使用位置](</E:/AI UWO assistant/miniprogram/pages/adventure-fleet/index.wxml:221>)

### 问题原因

- 组件名称和交互语义是 Action Sheet，但实际不是面板，而是永久显示的按钮组；
- 5 列槽位导致按钮横向宽度严重不足；
- 文字隐藏后，普通用户只能依赖图标识别动作；
- 用户容易误触“锁定 / 移除 / 排除”；
- 状态和危险操作没有足够的上下文确认。

### 实施建议

推荐方案：

1. 点击整个航海士卡片或槽位；
2. 打开页面级 Bottom Sheet；
3. 在面板中显示完整文字操作；
4. 显示当前状态、操作说明和禁用原因；
5. 点击遮罩或“取消”关闭；
6. “排除”使用危险色，并在必要时增加二次确认。

如果暂时不做 Bottom Sheet，最低要求是：

- 卡片内部只保留一个“更多操作”入口；
- 删除常驻三按钮；
- 所有操作热区至少为 `88rpx × 88rpx`；
- 不隐藏操作文字；
- 重要动作使用标准按钮组件。

### 验收标准

- 375px 宽度下，战斗 5 列槽位不会出现窄到无法准确点击的操作按钮；
- 锁定、移除、排除均可通过文字理解；
- 点击航海士主体不会误触危险动作；
- 锁定成员、已满容量、不可移除状态均有明确禁用反馈；
- Bottom Sheet 不被主页面滚动区域裁切。

## P1-2 战斗结果预览移出主 `scroll-view`

### 现状

战斗页面当前结构为：

```text
scroll-view.fleet-scroll
  └── result-preview-sheet
```

相关位置：

[战斗页面滚动区域](</E:/AI UWO assistant/miniprogram/pages/fleet/index.wxml:112>)

冒险页面的结果预览已经放在主滚动区域外，可作为调整参考。

### 问题原因

小程序原生 `scroll-view` 与 `position: fixed` 组件嵌套时，真机可能出现：

- 面板被裁切；
- 遮罩层级异常；
- 滚动手势被主页面接管；
- 底部按钮无法稳定固定在安全区上方。

当前结果面板还使用普通 `view + overflow-y: auto`，稳定性不如原生 `<scroll-view scroll-y>`。

### 实施建议

- 将战斗页 `result-preview-sheet` 移到主 `scroll-view` 外；
- 组件内部使用 `<scroll-view scroll-y>`；
- 面板最大高度保留约 80～82vh；
- 底部操作区使用安全区 padding；
- 预览内容过长时只滚动面板内容，不滚动背景页面。

### 验收标准

- 方案目标较多时，面板内容可独立滚动；
- 背景页面不会跟随面板一起滚动；
- iPhone 底部安全区不会遮挡“取消 / 应用”；
- 面板不会被 `fleet-scroll` 裁切；
- 取消、应用、撤销事件仍保持原有测试通过。
